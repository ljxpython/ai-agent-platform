# 企业级 Agent 平台全自动化漫游演示视频工业级制作与避坑指南

> **文档定位：** 本文档系统性复盘与固化了平台演示视频从“人工录制易翻车、低分辨率、音画脱节”向“1080P 无人驾驶自动化采集、神经网络知性女声混流、系统级字模内嵌与毫秒级音画同步”演进的完整工业级生产管线。供后续产品发版、特性上线与宣传演示制作直接参考复用，杜绝重复踩坑。

## 一、 为什么要做全自动化演示视频？

在企业级 AI Agent 领域，演示视频（Product Tour / Walkthrough）面临三大核心难题：

1. **长程任务时间跨度大**：真实深度代码调研、文献分析往往包含 30~50 步工具链，真实耗时 3~10 分钟。直接录制不仅冗长枯燥，人工操作还极易出现鼠标漂移、误点击、切换卡顿等问题；
2. **分辨率与视口不统一**：笔记本、外接大屏分辨率各异，视口比例不对容易导致前端响应式布局折叠、字体缩放失真；
3. **音画脱节与字幕灾难**：传统后期剪辑手工对齐耗时耗力，而在自动化压制中，macOS 字体映射、字幕溢出、异步组件（如 iframe 图谱、沙箱 Markdown）尚未加载即切走，极易造成严重翻车事故。

本指南所沉淀的**全自动化生产管线**，通过纯代码驱动的无头浏览器自动化、分段神经网络语音合成与 FFmpeg 复杂滤镜链，实现了“一键触发、全自动录制、毫秒级对齐、无乱码内嵌、直接出片”的生产级工程闭环。

## 三、 血泪经验与六大翻车事故彻底根治手册

> **核心法则：任何上屏给用户看的大片，必须经过逐帧 OCR 级技术验核，不容忍任何瑕疵！**

### 1. 事故一：开头上方出现巨大方块乱码（`□□□□ AI Agent`）
- **致命根因**：
  1. **输入源污染**：混流时直接使用了上一轮已经被旧脚本烧录过脏字幕的临时视频片断（二次压制叠加）；
  2. **macOS 字体映射黑洞**：在 macOS 上使用 FFmpeg 的 `subtitles=...ass` 滤镜时，若 ASS 样式指定 `PingFang SC`，底层的 libass 往往无法通过字体名称正确查找 macOS 系统字库，导致所有中文字符因缺少字形直接降级回退为方块 `□`，只有英文字母（如 `AI Agent`、`DeepEval`）能显示！
- **彻底根治方案**：
  - 录制必须输出绝对纯净、无任何字幕的全新母带 `raw_tour_pristine.mp4`，禁止二次叠加；
  - 彻底抛弃 ASS 滤镜，改用 FFmpeg 原生 `drawtext` 滤镜，**必须绝对指定系统自带字体文件真实路径**：
    `/System/Library/Fonts/STHeiti Light.ttc`（华文黑体，macOS 原生必带，100% 包含完整简体中文字模，零依赖、零乱码）。

### 2. 事故二：字幕文本边缘溢出屏幕
- **致命根因**：
  在文本分片中直接传入 30~45 字的长句子。在 1920 宽度的视口下，即使设置居中，文字总宽度也会突破 1800px，在播放器边缘发生文字被吞、左右顶格现象。
- **彻底根治方案**：
  - **严格分行限制**：每行汉字严格控制在 **18~22 个中文字以内**（遇逗号、分号强制断行）；
  - **字号与边距基线**：1080P 视口下字号严格统一为 `24px`，`line_spacing=8`，`boxborderw=14`；
  - **安全留白**：通过 `x=(w-text_w)/2` 水平居中，确保屏幕左右两端各有超过 **260px ~ 300px 的巨大安全留白**，在任何 16:9 或带圆角的播放器中绝无溢出。

### 3. 事故三：沙箱工作区未打开报告预览，没有上下滑动
- **致命根因**：
  1. **粗糙关键词误击**：在遍历 DOM 匹配产物条目时，因聊天消息流中也打印了 `产物引用: 75d9f7ff...`，普通的 `75d9f7 in line` 优先匹配到了消息流里的“复制”小图标，导致产物条目并未真正被点击；
  2. **未执行视图交互**：仅停留在文件列表，未触发滚轮或滚动指令。
- **彻底根治方案**：
  - 精确判定点击目标为 `button` 且包含 `33.1 KB`（或属于 `交付物列表` context），确保点击的是右侧产物卡片；
  - 等待 5 秒完成 Markdown 解析渲染后，必须调用无头浏览器的平滑滚轮交互 `wheel_scroll(sess, 900)`，向下浏览核心指标与评价，再滚回顶部，让观众看清全文细节。

### 4. 事故四：任务成果库显示“该会话暂无正式交付成果”（空态尴尬）
- **致命根因**：
  切入「任务成果」路由后，左侧历史成果会话列表默认高亮第一项（而第一项通常是刚刚第一幕新建、仍在后台执行的空会话），右侧自然展示空态占位符。
- **彻底根治方案**：
  - 切入「任务成果」后，**必须根据时间戳（如 `16:58:07`）或哈希显式点击已归档的会话条目**；
  - 触发前端响应式高亮，右侧立即渲染出正式交付物卡片（包含文档类型图标、文件名、33.1 KB 大小、SHA256 哈希、在线预览与安全下载按钮），彻底消灭空态。

### 5. 事故五：异步组件与图谱“半成品上屏”（尚未加载完成即切走）
- **致命根因**：
  现代 Web 应用（如知识图谱、LightRAG 中枢看板）多采用异步数据拉取或 iframe 嵌套。脚本切入该页面后未留足网络加载时间（仅等 2~3 秒），在画面刚显示“正在挂载...”的一瞬间解说词就已经讲完并切走了下一个分镜。
- **彻底根治方案**：
  - **前置深度预热/测量**：通过探针脚本测量异步组件的实际 Ready 耗时（如知识库 iframe 稳定就绪需 4 秒）；
  - **分镜时间充裕化**：在解说任务成果库时停留 6 秒，切入知识库后预留 5 秒加载 + 13 秒稳定展示（总停留 18 秒），确保 2,450 知识实体与 3,890 关系拓扑完全就绪后由滚轮轻微下探，与解说词分秒契合。

### 6. 事故六：片尾突兀掐断、解说词未说完
- **致命根因**：
  录制视频的实际长度短于配音总长度，压制时直接 `-t` 掐断，或者未留片尾淡出余量。
- **彻底根治方案**：
  - 利用 FFmpeg 的 `tpad=stop_mode=clone:stop_duration=...` 滤镜，自动将视频最后一帧画面冻结克隆延伸；
  - 保证在最后一句配音完全念完后，画面定格留白 **8 ~ 10 秒**，配合 BGM 的 `afade=t=out` 平滑衰减，呈现出专业电影级的从容收尾。

### 7. 事故七：说到成果库画面却已跳至知识库（分镜耦合音画脱节）
- **致命根因**：
  将“任务成果库”与“知识中台”揉在一整段配音解说词中，而在自动化录屏时，成果库展示停留仅 6 秒，导致解说词刚念到“所有关键交付物统一归档”，画面就已经按代码逻辑提前点击切入了知识库！
- **彻底根治方案**：
  - **分镜严格原子化解耦**：将成果库与知识库拆分为两个独立的物理幕次，各自配备独立音频与字幕文件；
  - **硬性时间门禁保护**：任务成果库独享 **23 秒** 独立画面，只有在成果库专属配音完全念完、外挂字幕消失后，无头浏览器才执行点击切换至知识库，实现 100% 的音画物理锁定！

### 8. 事故八：YouTube Web 自动化上传踩坑（Polymer 隐藏 Input 与幽灵 Disabled）
- **致命根因**：
  1. **CDP 无法操作隐藏元素**：YouTube Studio 的文件上传组件 `<input type="file" name="Filedata">` 采用 Polymer 封装，CSS 设为 `display: none`，常规自动化驱动（如 CDP 或原生 CLI）直接报 `element not visible`；
  2. **Polymer 响应式状态漏触**：直接通过 JS 脚本对单选框执行 `.click()` 时，未能派发完整的真实指针交互序列，导致 Polymer 的 `iron-selected` 数据绑定失效，底部的 Save/Publish 按钮被锁死为 `disabled` 状态；
  3. **发布后背景全禁遮罩**：当视频发布成功后，YouTube 会弹出 `ytcp-video-share-dialog`，并为底层的上传对话框叠加 `show-save-scrim` 遮罩，导致底层按钮全盘禁用。
- **彻底根治方案**：
  - **CORS 本地桥接 + 原生 DataTransfer**：本地启动轻量 127.0.0.1 静态 HTTP 服务，浏览器内执行 `fetch -> Blob -> File -> DataTransfer -> input.files = dt.files -> dispatchEvent('change')`，以 100% 原生方式触发上传流水线；
  - **完整鼠标事件序列模拟**：针对 Visibility 的单选框（如 `PUBLIC`），依次派发 `mousedown -> mouseup -> click` 原生事件到内部的 `#radioContainer`，精准解开 `#done-button` 的禁用属性；
  - **自适应弹窗层级抓取**：轮询顶层的 `ytcp-video-share-dialog`，提取最终生成的短链（`https://youtu.be/...`）后再触发关闭，确保链路自闭环。

## 四、 核心自动化生产脚本资产 (v4 工业级标准)

本项目沉淀在 `scratch/` 及资产库中的标准执行脚本与模块化组件：

### 1. 中英双语配音生成与时长测算 (`scratch/generate_bilingual_voiceover.py`)
使用 Edge-TTS 驱动微软官方高拟真神经网络声音：
- 中文语音：`zh-CN-XiaoxiaoNeural`（微软晓晓知性女声）
- 英文语音：`en-US-JennyNeural`（微软 Jenny 专业纯正美音）
通过 `ffprobe` 精准提取 8 幕分段音频时长，产出毫秒级物理门禁基准。

### 2. 8 幕无人驾驶无头录屏母带机 (`scratch/record_pristine_tour_v4.py`)
核心能力：
- 严格锁定 1920x1080 视口比例；
- **沙箱终端实测入镜**：自动点击进入【💻 终端】Tab，展现 `● 终端 1` 运行态与命令行控制台；
- **分镜物理门禁**：第 6 幕【任务成果库】独立停留 23 秒，解说完全念完后才准许进入【知识库】；
- 产出纯净无字幕、高码率 1080P 原始母带：`docs/assets/raw_tour_pristine_v4.mp4`。

### 3. 双语双轨音画混流与字幕烧录引擎 (`scratch/mix_bilingual_v4.py`)
FFmpeg 核心滤镜链模版：
```python
# 1. 华文黑体系统级字模单层压制（无 ASS 依赖、零乱码、居中安全留白）
drawtext_filter = (
    "drawtext=fontfile='/System/Library/Fonts/STHeiti Light.ttc':"
    "textfile='sub_texts/part_1.txt':"
    "fontsize=24:fontcolor=white:line_spacing=8:"
    "box=1:boxcolor=black@0.72:boxborderw=14:"
    "x=(w-text_w)/2:y=h-text_h-45:"
    "enable='between(t,0.80,25.00)'"
)

# 2. 视频末帧克隆冻结留白（8~10秒从容收尾）
video_filter = f"[0:v]tpad=stop_mode=clone:stop_duration={pad_dur:.2f},{drawtext_filter},fps=30[vout]"

# 3. 语音精确定位延迟与 BGM 渐弱
audio_filter = (
    "[1:a]adelay=800|800[v1];"
    "[2:a]adelay=26500|26500[v2];..."
    "[v1][v2]...amix=inputs=8:dropout_transition=0:normalize=0[voiceout];"
    f"[9:a]afade=t=in:ss=0:d=1,afade=t=out:st={fade_start:.2f}:d=4.0,volume=0.20[bgmout];"
    "[voiceout][bgmout]amix=inputs=2:duration=first:dropout_transition=2[aout]"
)
```
一键产出：
- 中文成片：`docs/assets/demo-walkthrough.mp4` + 字幕 `docs/assets/demo-walkthrough.srt`
- 英文成片：`docs/assets/demo-walkthrough-en.mp4` + 字幕 `docs/assets/demo-walkthrough-en.srt`

### 4. YouTube Web 端到端自动化发布脚本 (`scratch/upload_and_publish_en.py`)
- 全自动驱动本地已登录浏览器会话；
- 自动完成文件注入、SEO 元数据填充、受众设定、Visibility 选定与短链解析。

## 五、 验收与质检标准化清单 (Checklist)

在任何演示视频发布或提交前，必须执行以下 8 项硬性检查：

- [ ] **1. 乱码检查**：抽检第 12 秒与第 60 秒，确认画面绝无方块 `□`，无上下两层字幕重叠；
- [ ] **2. 溢出检查**：抽检最长字幕分镜，确认左右两侧距离屏幕边缘各有 $\ge 250\text{px}$ 留白；
- [ ] **3. 沙箱报告**：抽检第 65 秒，确认右侧 Markdown 预览区已打开并渲染出富文本报告，伴随平滑滚动；
- [ ] **4. 沙箱终端**：抽检第 98 秒，确认右侧工作区切换至终端控制台，状态圆点显示绿色运行中，交互终端就绪；
- [ ] **5. 交付物卡片**：抽检任务成果库，确认右侧明确展现成果卡片（含文件名、KB 大小、下载按钮），非空态；
- [ ] **6. 图谱与中台**：抽检知识库页面，确认 iframe 已完全就绪（Entities / Relationships 数字上屏），非空白或正在加载中；
- [ ] **7. 尾部留白**：抽检视频最后 8 秒，确认解说词已从容说完，画面定格留白，BGM 自然平滑淡出；
- [ ] **8. 线上可播性**：抽检 YouTube 公开链接，确认 1080P 分辨率转码完毕，双语声道与字幕显示清晰无瑕疵。
