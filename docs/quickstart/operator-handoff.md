# 运维部署交接与验收回执

用途：接手原生进程开发环境部署。先读本页，再按[部署手册](deployment-guide.md)顺序执行。
本页没有真实 IP、密码或模型 Key；具体机器和目录由私有交接 README 指定。

## 1. 开工前确认收到什么

| 材料 | 内容 | 如何处理 |
|---|---|---|
| 私有交接 README | 目标机、用户、账号映射、版本、已做/未做事项 | 决定本次实际参数，不能照抄通用示例覆盖 |
| source/ | 已核对的源码和本次部署文档 | 可能包含未提交改动；以交接说明的版本边界为准 |
| private/config/apps/ | 服务器使用的 app-local env | 只安装对应服务文件；不要公开回传 |
| private/pg-init.env | 建库用业务角色名、库名、原始密码 | 不是 PG 管理员或 SSH 凭据；不整体注入应用 |
| private/original/（若附） | 最初交接时的原始备份 | 不作为当前推荐配置；运维专用包不包含此目录 |
| private/current-local/（若有） | 更新后的开发机配置备查 | 不复制其中的开发机路径到服务器 |
| MANIFEST.sha256 | 解包后的逐文件校验 | 在交接根目录校验后再部署 |

交接目录应只有受托运维可读；私有目录 700、文件 600。接收压缩包时先比对交付方给出的 SHA-256，
确认后解到独立目录，再执行：

```bash
sha256sum -c "MANIFEST.sha256" --quiet
```

接收完整文件与授权范围后即可部署，不必每一步都再问提供者。
遇到已有业务数据、角色权限冲突、需开放公网或扩大服务范围时，先说明实际冲突再确认。

## 2. 源码版本与配置不要混淆

- Git 分支/HEAD 标识已提交基线；交接源码快照还可能有未提交改动。仅切分支不等于已经取得本轮文档或源码。
- 先确认原仓库分支、HEAD 和工作区状态；已有未提交改动先保全，不能 reset --hard、clean 或强制覆盖。
- 在新的普通用户项目目录中准备代码。需要保留 Git 时按私有 README 复制已核对基线，再应用指定快照。
- 不把 .venv、node_modules、数据库、聊天、Redis 队列或工作区当源码复制。
- 配置选择 private/config；source 的示例只是参考。模型 Key 不放命令行、VITE_*、回执或 Git。

## 3. 本次部署顺序

1. 核对系统、依赖版本、端口和已有服务。面板管理的 PostgreSQL/Redis 原地复用，不安装第二套。
2. 创建或使用普通应用用户，准备项目和持久工作区，核对该用户的 PATH。
3. 安装 Python/前端锁定依赖，安装服务器配置文件，核对实际库名、角色、地址和工作区权限。
4. 按手册第 6 节确认 PG 管理入口，创建缺失的非超级用户角色和空库；不重置已有角色、不重建库。
5. 备份 HBA，保留管理通道，为实际业务角色配置 SCRAM；新连接完成正确/缺失/错误密码验收。
6. 依次执行 local-stack.sh doctor、migrate、start、status；三条迁移链成功后继续。
7. 通过 SSH 隧道访问前端，用私有 bootstrap 账号登录。
8. 创建新项目、模型连接和 Agent 模型选择，执行一条真实新聊天，验证流式回复和刷新后的持久化。
9. 返回下节回执。结果域、图片/MCP/观测等未验收的可选能力明确写“未配置”或“未验证”。

默认是开发环境，APP_ENV=local，四个应用进程。不开生产切流，不额外配置 Docker 或开机守护。
如果需要长期无人值守、外网域名或 HTTPS，作为追加范围单独安排。

## 4. 失败如何处理

| 阶段 | 处理 |
|---|---|
| SSH 超时 | 云控制台确认机器状态、安全组与来源限制；控制台内核对 sshd/ssh 服务、监听端口和认证日志，禁止盲目关闭防火墙 |
| 文件校验失败 | 保留现有目录，重新传输；不使用截断包继续部署 |
| 数据库认证失败 | 保留管理员连接，核对角色、密码、HBA 首匹配；必要时恢复本次 HBA 备份并 reload |
| 迁移失败 | 保留错误和当前 revision，停止后续启动；不 stamp、自动建表或清库绕过 |
| 应用失败 | 保存脱敏日志与失败命令，先查看依赖/配置；不升级锁文件碰运气 |
| 模型失败 | 核对平台模型连接与授权、Key/额度/网络；不能用健康检查代替真实聊天通过 |

已有数据库升级前需另按[数据库规范](../guides/database-operations.md)备份。
本次空库部署失败不意味着可以删除或恢复任何已存在数据库。

## 5. 请返回这份回执

```text
部署时间 / 执行人：
目标机器标识（不含登录密码）：
实际应用用户 / 项目目录 / 工作区目录：
代码分支 / HEAD / 源码快照标识 / 是否有未提交改动：
交接文件校验：通过 / 失败
依赖版本（Python、uv、Node、pnpm、PG、Redis）：
数据库角色权限：非超级用户；没有 CREATEDB/CREATEROLE/REPLICATION/BYPASSRLS
业务库及角色名（不含密码）：
SCRAM 认证：正确密码通过；缺密码拒绝；错误密码拒绝
认证测试覆盖：IPv4 / IPv6 / Unix socket（未启用者标不适用）
迁移：Platform / GraphHarbor / Runtime 应用表分别成功，平台 head 检查通过
进程：Runtime API / Runtime Worker / Platform API / Platform Web
健康响应：Runtime 所有 readiness checks；平台 status 与 database_ready
访问方式：SSH 转发命令 / 前端 URL（不含密码）
登录、新项目、模型连接、真实聊天、刷新后读取：逐项通过 / 失败 / 未执行
重启后复查：四进程、登录与新会话读取（确认无运行任务再重启）
保留配置和回退备份位置（不回传文件内容）：
未配置的可选服务 / 已知问题 / 待处理项：
最终结论：完成 / 部分完成 / 阻塞
```

不要在回执中附 .env、连接密码、token、模型 Key、完整用户聊天或数据库备份。
若缺少模型配置，回执应写“基础设施和登录通过，真实模型链路待配置”，不能写整套部署完成。
