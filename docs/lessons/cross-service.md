# 跨服务契约经验库

> 适用范围：Platform API、Runtime Service 与 GraphHarbor 之间的 HTTP 契约、Delegation、授权隔离和跨服务测试。
> AI 读取时机：开始处理跨服务契约或 Delegation 改动前按需读取。

---

## [坑] Delegation operation 测试依赖固定数量或索引

- **场景：** 新增或调整 Delegation `scope.operation` 枚举时
- **错误：** 用固定枚举数量、列表索引或连续切片推断测试边界；新增合法 operation 后，旧测试误报或把 operation 分类错位
- **正确：** 按 operation 名称集合和资源白名单断言；新增 operation 同时补充专属隔离测试，避免测试结构依赖枚举顺序
- **日期：** 2026-10-06

## [坑] 旧服务忽略条件字段会把 CAS 降为无条件写

- **场景：** 跨版本扩展 metadata 条件更新，旧服务可能接受请求但忽略未知字段。
- **错误：** 给普通 PATCH 增加条件字段就认定原子保护生效，或在新接口不可用时退回普通 PATCH。
- **正确：** 条件更新使用独立 URI，旧服务明确返回 404/405；比较、授权过滤和写入在同一数据库操作中完成，并验证并发与旧版本拒绝。
- **日期：** 2026-10-09；F07 收尾经验，用户已批准沉淀。

## [坑] 后台资料采集复用过期委托且历史大页重复膨胀

- **场景：** 长会话异步转换超过初始短时委托有效期，历史checkpoint各自携带累计消息和状态。
- **错误：** 只把HTTP交付改为202，却继续复用请求起点的委托；一次读取100个完整checkpoint导致慢响应或大body超时。202只是接收任务，不是资料交付成功。
- **正确：** 每次读取先核对当前会话权限并通过已有用途机制签发短时委托；缩小单页、保留总采集上限、冻结截止点和不完整标记。测试过期凭据、跨页顺序、边界截断，并用同一真实长来源复验。
- **日期：** 2026-11-20；Task14用户已批准沉淀。

## [坑] 来源容量、模型预算与历史完成状态混为一谈

- **场景：** 完整会话包含工具消息、执行清单及多次审批恢复。
- **错误：** 用手填文本上限拒绝服务端完整snapshot，或裁剪来源后误称完整；把每条Run都success作为会话完成标准，未考虑正常审批interrupted历史和倒序返回。
- **正确：** 分别约束手填、来源、签名接收及模型可见预算，保留原文hash及不完整标记。历史终态同时核对可信时间和全部状态，未决、error/cancelled或时间不明保持失败；完整来源不等于文件初态可恢复。 终态修复生效与裁判请求成功分别验证；超时／未知用量不能当低分或通过。发生OOM或隧道失联时重新核对实际内存、服务身份及健康，不以ping或旧PID替代当前状态。
- **日期：** 2026-11-20。证据见通用出题治理项目Task14；用户已批准知识沉淀。

## [坑] 历史接口忽略筛选参数与租户别名差异需分页复核并对齐

- **场景：** `platform-api` 平台助手读取目标 Run 的持久化 checkpoint 状态及 Runtime 诊断追踪数据。
- **错误：** 假定上游 `POST /threads/{thread_id}/history` 的 `metadata={"run_id": ...}` 过滤生效而只取 `limit=1`，一旦有后续 Run 写入即误判 `run_mismatch`；且默认租户在鉴权域传 `TenantRecord.id`（UUID）而运行时实际以 `tenant_id="__default"` 落库，导致运行诊断全部查不到。
- **正确：** 读取 checkpoint 采取先探最新 1 条、未命中再带 `before` 游标向后有界分页匹配目标 `run_id`（附游标去重防死循环）；默认租户（`slug == "__default"`）向 Runtime 统一传递 `tenant_id="__default"` 保持跨服务契约一致。
- **日期：** 2026-11-25；用户批准沉淀，证据见[平台助手接入 MLflow 追踪诊断专项](../projects/20261125-platform-assistant-mlflow-diagnostics/verification.md)。
