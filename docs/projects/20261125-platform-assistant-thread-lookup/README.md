# 平台助手按 Thread 检索运行与脱敏活动摘要

用户在日常使用平台聊天时，常常只在界面顶栏看到 `thread_id`（或前 8 位短编码），没有报错时界面也不会直接高亮每个 `run_id`。当用户把 `thread_id`（或前 8 位前缀）发给平台助手，希望排查该会话或了解“这几次对话都干了什么”时，原有助手只能要求用户同时提供完整的 36 位 `thread_id` 和 `run_id`，导致无法直接下手。

本项目扩展平台助手的跨服务只读查询契约（`platform-api` 与 `runtime-service`），支持：
1. **按 Thread 列出 Run**：接收完整 36 位 `thread_id` 或 8–35 位十六进制前缀，在当前用户有读权限的 Thread 范围内解析目标会话并列出最近 Run 的编号、状态、起止时间与配置概览；多条前缀命中时返回候选列表让用户确认，绝不越权泄露。
2. **结构化脱敏活动摘要**：在不暴露原始对话正文、工具输入参数和工具返回内容的前提下，投影出每轮对话调用过的工具名、执行成功/失败状态及审批中断标记，让助手安全回答“会话里干了什么”。
