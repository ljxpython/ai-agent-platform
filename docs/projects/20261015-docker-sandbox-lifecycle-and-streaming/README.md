# Docker 对话级沙箱生命周期管理与原生流式传输改造

## 项目概述
- **时间：** 2026-10-15 至 2026-10-17
- **目标：** 在纯 Docker 生产部署环境下（无 K8s），实装低开销的“每个对话（Thread）一个按需沙箱”生命周期管理机制（无交互超时自动销毁容器归零内存，再次唤醒按需秒级拉起并挂载宿主机持久化卷），同时将工作区大文件预览/下载彻底脱离 RPC Base64 内存缓冲协议，改造为宿主机/沙箱直出的原生 HTTP 二进制流式传输与智能压缩打包，根治文件下载慢、超时及并发 502 踩踏。
- **负责人：** @AI 协作 / 用户评审
- **模板类型：** 标准模板
- **状态：** `done`（实施完成、远端生产云主机部署成功、Playwright 真实浏览器闭环全通过）
- **改动级别：** 治理改动 / 链路改动

## 改动范围
- **影响服务：**
  - `runtime-service`：沙箱生命周期管理器（按需启动/空闲销毁）、Sandbox Node 原生流式下载端点、智能压缩打包策略、连接池与超时解耦
  - `platform-api`：文件流式反向代理透传（`StreamingResponse`）、空闲读取超时模型（Idle Timeout）、鉴权 Ticket/透传
  - `platform-web`：下载防抖加锁、Loading 状态、Toast 提示、请求取消（`AbortController`）
- **改动级别：** 治理改动（涉及生产沙箱拓扑、容器生命周期与数据持久化安全）
- **预计工作量：** 2 人天

## 关键决策
1. **彻底放弃预热池（Warm Pool），采用按需冷启动：**
   在小内存机器（如 4核 3.6GB）上，预热池会白白消耗 200MB~1GB 宝贵内存。采用“**无状态临时容器 + 有状态宿主机卷（Stateless Container + Stateful Host Volume）**”架构，容器按需秒级创建（`docker run -d`），不用时停机销毁，内存开销归零。
2. **下载/预览完全脱离容器运行态：**
   宿主机上的工作区目录为持久化存储事实源。用户在前端预览或下载文件时，**绝对不拉起 Docker 容器**，直接由宿主机或 Sandbox Node 守护进程从磁盘直读流式返回（`FileResponse` / `sendfile`），哪怕容器当前处于销毁状态，用户也可以极速秒级下载。
3. **彻底拔除 RPC Base64 传输大文件反模式：**
   数据面与控制面完全分离。禁止将二进制文件 Base64 编码为 JSON 走 `/v1/rpc`。开辟原生二进制 HTTP 流式端点，逐块（Chunked，如 64KB）流式传输。
4. **空闲容器自动回收策略（Reaper）：**
   容器内部无运行中的 Run、且超过设定的空闲时长（默认 10~15 分钟）无交互，后台自动 `docker stop` / `docker rm` 释放容器，数据完好保留在宿主机磁盘。
5. **智能归档打包（Smart Zip Streaming）：**
   工作区打包下载时，对 `.pptx`, `.docx`, `.xlsx`, `.zip`, `.png`, `.jpg`, `.mp4` 等已压缩文件强制使用 `ZIP_STORED`（存储模式，无损写入），消除无谓的 CPU 压缩空转。
