# Dear Agent 长期记忆操作与交互使用指南 (User & Dev Guide)

本文档归档并汇总关于 **Dear Agent 长期记忆（User Long-Term Memory）** 的两大核心问题：
1. **前端功能概述与具体操作使用指南**
2. **底层记忆的存储落库、触发提取、跨会话自动召回机制与端到端实测用例**

---

## 一、 前端功能概述与操作使用指南

### 1.1 功能入口与多项目隔离
- **入口路径**：登录系统后，进入左侧工作区（Workspace）选择具体项目，点击 Dear Agent 导航项中的 **“长期记忆”**（页面路由：`workspace-dear-agent-memory`，组件文件：[`DearAgentMemoryPage.vue`](file:///Users/lijiaxin/PyCharmMiscProject/ai-agent-platform/apps/platform-web/src/modules/dear-agent/pages/DearAgentMemoryPage.vue)）。
- **项目作用域隔离**：记忆严格以 `(tenant_id, project_id, user_id)` 三元组进行隔离。切换顶部项目时，页面内置 `scopeGeneration` 令牌机制，自动终止未完成请求并丢弃反序响应，杜绝多项目切换产生的数据串扰。

---

### 1.2 页面核心功能概览

整个记忆控制台由六大核心能力组成：

#### 1. 记忆状态感知与治理总控
- **状态横幅与指示**：
  - **未开启（`status === 'disabled'`）**：明确提示“当前项目未启用记忆沉淀”，写操作置灰。
  - **只读快照（`ready` 且缺少 `project.runtime.execute`）**：提示“当前为只读快照”，允许查看与导出，禁止任何写操作与开关切换。
  - **快照过期（`snapshotStale`）**：检测到后台有新版本时提示用户刷新。
  - **配额暂停（`pause_reason`）**：达到内部上限（如 `candidate_limit` / `source_limit` / `tombstone_limit`）时明确提示暂停自动提取，引导用户人工清理，绝不锁死人工删除权限。
- **自动候选推断开关**：用户可一键切换是否允许智能体在对话后自动提炼候选记忆，设置即时保存生效。

#### 2. 正式记忆库管理（Formal Memory CRUD）
- **分类标签**：清晰区分为 **偏好设定（`preference`）** 与 **事实信息（`fact`）**，配合清晰 Badge 显示。
- **新增录入**：
  - 输入记忆内容（严格按照 Unicode 字符计数，上限 1000 字符）。
  - 可选设定 **到期日期（`YYYY-MM-DD`）**。采用前端本地时区适配，保存为用户本地当日结束时刻（`23:59:59.999` ISO 格式），杜绝跨时区日期早于服务器当前时间的 `400` 错误。不填则为永久有效。
- **就地编辑**：
  - 支持原地展开编辑框修改内容与到期时间。
  - **未改动保护**：编辑时若未改动到期日期，提交时原封不动保留原有的 `expires_at` ISO 字符串。
- **安全删除与一键清空**：
  - 单条删除与全量清空均接入平台标准 `ConfirmDialog` 弹窗。
  - 清空文案明确声明：“将删除你在当前项目中的全部生效事实和待确认候选，同时关闭自动候选推断；历史聊天记录不会被删除。”，杜绝歧义。

#### 3. 候选记忆人机协同审核（Candidate Review）
智能体在对话中自主分析提炼出的记忆会进入“待审核候选”列表，等待人工裁决：
- **原文证据追溯（`quote`）**：
  - 候选卡片直接展示产生该条记忆的**用户原话片段引用（`quote`）**；若历史遗失则展示“历史记录缺少原文”，绝不伪造依据。
- **来源会话回溯**：
  - 卡片展示 `source_thread_id`，点击通过 Vue Router 命名路由跳转回关联的 Dear Agent 聊天会话。
- **三向审核裁决**：
  1. **直接采纳（Accept）**：转为正式记忆，立即入库生效。
  2. **替换旧事实（Accept & Replace）**：弹出已有正式记忆选择器，用户指定一条旧事实传入 `replace_fact_id`，完成原子级替换（旧事实注销并记入墓碑，新事实生效）。
  3. **拒绝（Reject）**：永久忽略该候选并记录指纹，避免后续对话重复推断。

#### 4. 数据备份导出与双模式恢复导入（Backup & Restore）
- **便携 JSON 导出（Fresh GET）**：
  - 点击“导出 JSON”，前端强制发起全新的全量读取请求（不拿本地搜索过滤后的残缺数据），将事实投影为 `[{ text, category, expires_at }]` 下载为 `dear-memory-YYYYMMDD.json`，并自动清理 ObjectURL 释放内存。
- **双模追加导入与严格预检**：
  - 支持**选择本地 `.json` 文件** 或 **直接粘贴 JSON 文本**。
  - **客户端严格前置预检**：体积限制 1.5MB、条数限制 1~100 条、`text` 长度 1~1000、`category` 仅限 `preference` / `fact`、`expires_at` 必须为有效未来时间。
  - **导入预览统计**：提交前实时统计并展示“有效条数”、“与现有库/文件内重复条数”、“校验错误条目（定位到具体行和错误原因）”。
  - 导入成功后，严格依据后端返回的 `added` 与 `skipped` 字段如实展示提示。

#### 5. 静默轮询与 409 CAS 冲突防吞
- **后台静默同步（`silentFetchMemory`）**：
  - 当检测到后台有提取任务正在运行时（`extraction.status === 'running'`），自动启动每 3 秒一次（最多 70 次 / 210 秒）的静默轮询。
  - 静默轮询绝不开启全屏骨架屏，不会打断用户浏览，且**绝对不冲掉用户正在打开的编辑弹窗草稿**。
- **409 版本冲突防护（`memory_revision_conflict`）**：
  - 当用户提交与后台变更发生版本冲突时，弹窗绝不强退、输入内容绝不丢失，前端持久提示黄色冲突横幅，自动同步最新 revision 供用户复核后重试。

#### 6. 共享会话隐私安全提示（Privacy Shield）
- 在聊天页面的权限设置（[`ThreadAccessControl.vue`](file:///Users/lijiaxin/PyCharmMiscProject/ai-agent-platform/apps/platform-web/src/modules/chat/components/ThreadAccessControl.vue)）中，当用户准备把会话设为“共享（`mode === 'share'`）”时，界面会自动浮现专属隐私告示：
  - 明确告知**“共享会话将自动停用个人记忆沉淀”**；
  - 提醒用户**“历史回答中若包含个人信息，共享后也将对协作者可见”**。

## 二、 记忆触发、存储与跨会话召回机制

### 2.1 触发与提取存储链路

```text
[用户在私有会话发言]
        │ (包含偏好或事实，如"我写组件一律用 Tailwind CSS")
        ▼
[Runtime MemoryMiddleware (后置链)]
        │ 校验合法用户消息 (过滤附件、工具返回值、非属主来源)
        ▼
[调用后台模型结构化提取 (提取 Prompt)]
        │ 限制 180s 预算、最多 2 次尝试、每 run 最多 5 条
        ▼
[写入 PostgreSQL candidates 候选工作集] ──(保留 quote 原文引用)
        │
   ┌────┴────────────────────────┐
   ▼                             ▼
[用户在前端点击"接受"]       [用户选择"接受并替换旧事实"]
   │                             │
   └──────────────┬──────────────┘
                  ▼
[持久化至 PostgreSQL facts 正式记忆表] (三元组: tenant_id, project_id, user_id)
```

1. **提取前提**：必须为当前项目、当前私有未共享会话、经鉴权的合法用户消息。共享会话会直接关闭提取和注入。
2. **提取内容**：模型判定具备“持久有效性”的喜好（`preference`）或事实（`fact`），临时指令会被忽略。
3. **入库门禁**：提取出的记忆初始状态为 **候选（Candidate）**，绝对不会未经确认直接擅自当作既成事实生效，必须由用户在前端控制台点击 **“接受”**（或“接受并替换”）后才正式转为正式事实（`Fact`）。

---

### 2.2 跨会话自动召回机制（Recall）

当记忆转为正式事实后，用户在该项目下发起任何新一轮对话时，系统自动执行隐式召回：

```text
[用户发起任意新对话或新会话]
        │ (输入 query)
        ▼
[MemoryStorage.context(scope, query)]
        ├─ 1. 词法召回：对 facts 扫描分词命中项 (英文正则词 / 中文连续双字切词)，按命中度排序取最多 7 条
        ├─ 2. 基础偏好兜底：追加未命中的 preference 偏好条目 (最多 3 条)
        └─ 3. 上下文预算控制：转义特殊字符，总计最多 10 条、4000 字符内
        ▼
[隐式注入 System / Model Prompt]
        ▼
[大模型感知并生成符合个性化画像的回答]
```

- **全项目跨会话可用**：只要在同一个项目下，新建任何 Thread 均可自动共享并使用该用户的正式记忆。
- **召回优先级**：强相关的条目优先召回；通用的使用偏好（`preference`）常驻兜底。
- **存储故障降级**：如果记忆库在召回时遭遇异常，系统自动记录降级日志，普通会话继续正常问答，绝不阻断正常聊天。

## 三、 端到端测试操作步骤（以 TC-MEM-01 偏好沉淀为例）

你可以在本地按照以下三步进行一次完整闭环验证：

### 【步骤 1：在聊天会话中触发偏好提取】
1. 进入当前项目的 Dear Agent 聊天页面。
2. 发送明确包含偏好的句子：
   > **“老王，记住了，以后只要让你写前端组件，不管是啥，一律用 Tailwind CSS，我绝对不用纯 CSS 或 SCSS！”**
3. Agent 正常响应本次对话。

### 【步骤 2：在记忆管理页面审查并接受】
1. 切换到左侧菜单 **“长期记忆”**（`workspace-dear-agent-memory`）。
2. 在 **“待审核候选”** 列表中，找到刚提炼出来的卡片：
   - 分类应为：`preference`。
   - 内容摘要：包含“前端样式强制使用 Tailwind CSS”等语义。
   - 原文引用（Quote）：清晰包含你刚才输入的句子片段。
3. 点击该卡片上的 **“接受”** 按钮。该条目随即移入上方的 **“正式记忆”** 列表中。

### 【步骤 3：跨会话验证自动召回】
1. 点击左侧聊天列表的 **“新建会话（New Thread）”**（确保清除上下文历史）。
2. 发送一个不包含任何技术栈限定的简要提问：
   > **“帮我写一个用户登录卡片的前端组件代码模板。”**
3. **验证结果**：
   - 检查 Agent 输出的组件代码是否**主动采用了 Tailwind CSS 类名**（如 `class="flex flex-col p-4 bg-white rounded-lg shadow"`），而非行内样式或 SCSS。
   - 若符合，则证明：**输入捕获 → 结构化提炼 → 原文追溯 → 人工审核入库 → 跨会话词法召回 → 上下文隐式注入** 整个长期记忆闭环完全成功！
