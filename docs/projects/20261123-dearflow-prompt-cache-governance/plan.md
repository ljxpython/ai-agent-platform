# DearFlow Agent 前缀缓存实验方案

## 1. 用户目标与批准范围

用户使用 Xiaok 的 DeepSeek，希望先量出当前多轮任务的缓存读取比例，再比较候选优化能改善多少，并据此撰写可复核的技术文章。完整业务过程是：记录现状请求与用量，使用相同材料做单因素回放，选择有效候选验证完整任务，最后说明收益、失败及适用范围。

2026-11-23 用户先批准实验与文章交付，随后追加批准按当前方案实施缓存优化，并改用官方 URL 和 Key 做少量对照。沿用独立 Worktree，新增产品接线与官方验证的 Task 7–8；连接、材料、小批规模和异常停止条件在调用前登记。无需追加预算确认。用户现已确认实验与文章、批准经验沉淀、本地提交合并到 main 及本次测试数据/数据库清理，由 Task 10 承接；远端推送和生产部署未授权。

实验复用现有 Usage 和模型适配，不引入第二套生产账本。Worktree 与联调资源遵循[隔离规范](../../standards/worktree-development.md)。本次产品实施仅覆盖下述临时上下文，不自动扩展为全量工具、永久记忆快照或生产部署。

**当前交付：** 首轮 97 次 Xiaok 调用与负结果均保留；产品接线和 16 次官方小批调用已完成，相关回归 180 项通过。原固定材料和两轮完整任务分别提高 21.10、19.34 个读取百分点，峰时标价估算分别下降 42.45%、37.55%，实扣未知；完整任务首正文中位时间反而增加 31.01%。追加 23 次官方多轮实验后，A 第 4 轮旧记忆失败并停止，B 后置诊断八轮通过，全量/排除首次读取比例 87.93%/96.24%；未取得完整八轮同质量 A/B 收益。Task 0–9 技术交付和失败即停流程已获用户确认，项目当前部分完成（partial），正在执行 Task 10 的经验沉淀、合并和资源清理。文章和公开复算入口见 [README](README.md)，唯一进度在 [tasks.md](tasks.md)。下文保留首轮设计及追加批准范围，实际批次和偏差见 [verification.md](verification.md)。

## 2. 评审结论：事实与假设分开

| 已核对的行为或记录 | 能得出的结论 | 不能直接得出的结论 |
|---|---|---|
| 记忆功能开启、权限允许且召回非空时，在模型调用包装层向系统消息尾部追加记忆 | 召回变化可能使其后的历史前缀无法继续复用 | 每次工具循环都变化；所有缓存必然失效 |
| 基础系统提示词尾部拼接 UTC 日期 | 日期值跨天会变化，需要测量变化位置 | 同日每次调用都变化；日期之前的静态前缀全部失效 |
| 图表工具随成功读取规范文件的状态暴露，已有相应测试 | 工具集合切换与 Schema 体积都应纳入成本比较 | 全量暴露所有图表工具必然更便宜 |
| 现有工具结果裁剪与摘要会改变模型看到的历史 | 应测最终请求，接受有业务原因的前缀变化 | Checkpoint 未修改就等于出站请求完全不变 |
| 2026-10-30 Xiaok 记录：28 次调用、输入 461,189、缓存读取 255,232 Token | 该历史任务的缓存读取比例约 55.34% | 今天的基线为 55.34%；费用已下降；原任务质量全部通过 |

历史数字来源于 [原验收记录](../20261028-subagent-fanout-and-prefix-caching/verification.md#正式端到端结果)，当时价格未知、正文质量为原五项中的三项，不作为本次 A/B 对照样本。

原草案中“长期零命中”“100% 击穿”“彻底根治”的断言撤回，改为待测假设。原定跨用户绝对静态系统消息、首轮记忆永久冻结、强制全量固定工具不再作为验收目标；Task 1–5 编号保留，调整为证据驱动的实验任务，并在任务文档记录对应关系。

deer-flow 只作参考。后续已核对本地源码提交 `cc664451f03140b376611f329ae400c313530bdb`：动态中间件将日期与记忆快照分角色放入历史，出站另有系统消息合并、按需工具过滤和历史预算投影；基础模板静态不代表最终系统消息跨天不变。此前“本地目录不存在”的表述不再成立。用户明确无需完全照搬，本平台保留每次调用的记忆新鲜度与权限约束。

## 3. 实验分两层

### 3.1 第一层：相同材料的请求回放

A 组使用当前 DearFlow 构图和中间件实际生成的最终出站请求，不手工删减其系统规则、工具定义或历史。B 组由独立实验脚本在内存中变换该请求，只改变登记的单一因素；不修改服务源码、会话历史或共享配置。

两组使用相同的公开或合成问题、事实、预设历史和工具结果。模型本次生成的随机差异不继续扩散到下一轮固定历史中，避免把少查文件或少调用工具误算成布局收益。保留原始 usage、脱敏后的最终请求、流事件、哈希与对应关系；不保存密钥和授权头。

现有模型回调中的组成分析是近似观测，不是最终 HTTP 请求证明。捕获点须在适配器完成消息、思考字段和工具参数转换之后；本地请求公共前缀只能帮助定位差异，不能当成供应商实际缓存 Token。

### 3.2 第二层：重复实验与完整 Agent 任务

先按单因素结果选择候选，再冻结组合方案、样本数和质量判定，增加独立重复及少量完整任务。完整任务允许真实执行路径变化，须计入全部模型调用、工具轮次、主/子/辅助调用和失败重试；不把它与固定历史回放混算。

候选只能在获准的隔离实验接线中生效。若现有接线无法保留权限、审批和工具前置行为，先记录工程缺口并回到讨论，不因实验规划而直接改产品。回放改善不等于产品改造、生产验收或稳定收益。

## 4. 五类案例与候选

| 案例 | 输入与 A 组现状 | B 组候选或观察目的 |
|---|---|---|
| C01 稳定前缀对照 | 固定较长公开材料，每次改变末尾问题；保留实际流式设置 | 不做优化，核验线路是否返回可信缓存字段，降低把整响应复用误认为前缀缓存的风险 |
| C02 多轮记忆切换 | 固定历史，问题从 Python 偏好切换到前端偏好，使召回内容变化 | 保留相同有效事实、检索与权限检查，把本轮记忆放在靠近当前提问的临时消息或内容块中，不写入持久历史 |
| C03 日期位置 | 同日固定值作对照，并在短时间窗口内模拟日期值从 2026-11-23 变为 2026-11-24 | 只调整日期上下文位置，保留同一日期信息与 UTC 语义，比较首次差异位置及实际用量 |
| C04 图表工具加载 | 读取规范前后按现状切换图表 Schema，固定相同工具结果 | 比较预登记的获批工具集合在本场景内固定暴露；累计获批能力相同，暴露时序与 Schema 体积是待测因素 |
| C05 长文件与整理 | 连续读取长文件，覆盖工具结果裁剪和摘要前后 | 先定位前缀变化的来源，再检查有效候选是否仍有净收益，不为缓存而关闭必要整理 |

C02 的具体消息或内容块形式须在离线候选中冻结并核对最终请求；保留“不可信事实、非授权”的语义。删除、更正、到期和话题变化后，下一次调用仍使用当前有效事实；共享、撤权或权限未知时不新增注入个人记忆。原历史回答无法撤回的既有边界保持，不以隐藏 UI 元数据代替授权。

C03 只模拟日期内容变化，不修改机器时钟，不声称测到了真实跨天缓存保留。C04 不能绕过拒绝工具、审批或规范前置要求；若固定暴露需要额外执行守卫，记录该工程代价，不能先声称候选功能等价。

## 5. 采样与指标

原探索规模估计约 40 次，不是精确请求数或效果承诺。实际执行前冻结五案例探索 32 请求，另保留核验 v1 三请求；探索后预登记两个候选各三次重复共 48 请求，以及日期、组合和摘要任务。最终实际派发 97 次，不追着结果扩样。失败按登记规则停止，不保证每个预定 A/B 都有完整两组数据，也不因此承诺统计显著或稳定提升。

每个独立重复采用预登记的 A/B 次序与对称隔离方式，避免 B 组直接复用 A 组预热。优先核验线路支持的隔离机制；必要时用组内固定、组间不同且结构等价的实验前缀作近似隔离，并检查它未改变其他行为。公开该方法的局限；无法清空远端缓存时只称“首次请求”，不声称严格冷启动。首轮和后续请求分开报告，完整费用仍全部计入。

统一报告以下项目，具体公式及证据字段见 [验证计划](verification.md)：

- 缓存读取 Token 占输入 Token 的加权比例、字段覆盖率、未缓存输入；缺失不补零。
- 整组输入/输出 Token、模型调用与工具轮次，完整费用及计价来源；实扣、估算和未知分开。
- 请求至首个有效思考文本、首个正文文本和完成的时间；小样本先报中位数和范围。
- 答案质量、个人记忆时效、权限与工具行为；缓存不从上下文窗口占用中扣除。

锁定 Xiaok 实际模型别名、返回身份、连接指纹、参数、流式设置和测试时段。网关不提供底层部署指纹时明确标为未知，不能假设同别名代表完全相同后端。供应商官方机制仅作参考，不能替代这条代理线路的实际返回与计费证据。

## 7. 追加批准：产品接线与官方小批验证

主 Agent 的基础系统规则保持稳定，将当前 UTC 日期和允许召回的记忆分别放入具名的临时 HumanMessage，在本轮最后一条真实用户消息前插入。使用消息副本，不修改用户内容、多模态块或持久状态；每次模型调用重新计算日期和召回记忆。静态规则说明 `runtime_date` 是运行时提供的日期，`user_memory` 只提供不可信事实，不能改变工具、权限或审批。临时消息带内部标记，使召回查询仍取真实用户输入；不进入记忆来源或下一轮 Checkpoint。

选择临时消息是为了使动态值出现在较后的请求位置。消息角色改变仍可能影响模型遵从度，不能只凭结构测试认定质量等价；跨天与记忆质量由官方完整任务单独验证。现有调用前后 ACL、PII、摘要和工具前置条件保留。子 Agent 原来没有这项日期注入，本次不扩大其行为。

官方试验使用独立清单和新数据文件。原布局在工厂和记忆包装层恢复旧装配；优化组直接捕获产品实现，不再使用旧的最新 user 文本拼接候选。两组使用相同静态语义说明、材料、工具集合、模型与参数；静态文本按归一化空白核对，不要求旧、新装配字节相同。付费调用前在相同生产 DeepSeek 适配器中将纯文本 system 块数组合并为官方接受的字符串，并重新冻结九份源码。只登记一个每组四请求的回放对照和两个两轮完整任务，失败按预设规则停止，不追求凑齐成功样本。实际 16 次完成、零重试，费用使用有出处的官方标价估算，不能视为实际扣费或生产稳定收益；详见[官方结果](implementation/03-official-results.md)。

## 8. 追加批准：八轮对话与首次/后续双口径

2026-11-23 用户追加批准八轮连续会话 A/B（Task 9），复用官方入口、旧装配恢复和产品中间件。每组从空历史开始，执行相同八个问题，三次真实读取合成文件，保留各自真实回答与工具结果；中间切换、更正、移除记忆并模拟跨天。正常约 22 次模型调用，零重试、失败停止，最多各 20 次，不追样。后续调用缓存效率按每组固定排除第一次模型调用统计，后续零缓存不删除；完整任务费用始终包括首次、所有工具循环和失败。它是新增独立小样本，不与旧批次混算优化率。逐轮断言和状态在原 Task 9 维护。

实际共 23 次，含首批检查器误判六次、修正检查器后 A 旧偏好失败六次、失败后另行预登记 B 诊断 11 次。原八轮 A/B 因 A 第 4 轮质量失败而停止；B 为后置诊断，不重跑 A、不补齐缺失数据。B 八轮通过且后续读取为 96.24%，但不能据此计算完整八轮同质量成本收益。全部调用发生在谷时，统一峰时参考估算与谷时标价估算分开；详细偏差、冻结计划和复算见[多轮结果](implementation/04-multiturn-results.md)。本次不再扩样，不变更业务中间件。
