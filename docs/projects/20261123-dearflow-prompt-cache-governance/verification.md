## 1. 执行前登记

每个实验版本在首次调用前固定以下信息，变更后另开版本，不替换旧失败或混算不同配置：

- 案例、组别、独立重复标识、请求轮次、次序、两组隔离方法、首轮/后续标记、预热与等待间隔。
- 流式设置、温度、思考模式、输出上限、输入规模、缓存相关参数；输出限制须足以完成登记的质量检查。
- 每批次请求数、配置估算工程保护、零重试/失败停止条件、允许发送的数据及执行环境。用户已明确无需追加额度限制；保护值不代表实际账单硬封顶或新增人工审批。
- 预登记的质量与权限检查、探索后扩样的决定方法。底层路由、价格、字段或部署身份未知时明确标记。

模型或路由身份变化、两组材料不可比、用量对不上、质量或权限检查失败时，保留样本并停止扩大该候选；按登记的条件诊断。不得无限重试或追加样本凑收益。

## 2. 逐请求证据与指标

### 2.1 读取比例与覆盖率

保存原始 usage 与归一化结果，核对 prompt_cache_hit_tokens、input_token_details.cache_read 等实际返回字段，而不是仅抄看板汇总。逐请求记录输入、输出、缓存读取及字段是否存在；网关没有返回缓存字段时记为未知，不记零。

对输入量与缓存读取量均有效的同一请求集合计算：

`缓存读取比例 = Σ缓存读取 Token / Σ输入 Token`

不平均逐请求百分比。同步报告已知/全部请求数和缺失请求；其输入量可知时报告输入量覆盖率。必要字段缺失则整组完整读取比例未知，只能标明“已知样本比例”。分母为零时不计算比例。

A/B 变化报告为百分点差，同时列绝对输入、缓存与未缓存输入。完整用量缺失时不宣称完整组收益；失败样本与未知项不删掉。

### 2.2 费用

优先取得 Xiaok 可关联请求或实验批次的真实计费证据；只有同一时间窗的账户总扣费而有其他流量时，不归因到本实验。若价格已知但无实扣证据，按实际线路的计价计算并明确标为估算；缺价格或必要用量则完整费用未知。

首次请求、预热、重试、失败及完整任务的主/子/辅助调用均纳入。平台失败兜底或账本中的零估算不证明供应商没有扣费，实扣、配置价格估算与未核实分栏。费用下降比例只在口径一致、覆盖完整且 A 组费用大于零时计算。

### 2.3 延迟、任务与上下文

从同一客户端开始派发请求计时，分别记录首个有效思考文本、首个正文文本和请求完成；连接建立、保活、空事件不算有效输出，无对应文本记为不适用。失败请求单列时间与原因，不混入正常完成延迟。

小样本报告数量、中位数与范围；增加重复前冻结统计方法，不用少量样本宣称稳定尾延迟。记录网络、排队及隐藏路由的归因局限。

固定历史回放不把本次随机输出带入后续预设输入。完整任务则保存真实执行路径、模型调用、工具轮次、输出质量及权限检查；两层结果分开。缓存不会从输入窗口占用中扣除，窗口峰值另报，不把读取比例当成上下文缩减。

| C03 日期 | 同日对照与短窗口内模拟日期值变化；两组日期和 UTC 语义一致 | 内容变化实验，不代表真实跨天保留，不改机器时间 |
| C04 工具 | 预登记获批集合，记录读取规范前后 Schema 数量、字节、顺序和哈希；核对拒绝/审批/规范前置 | 计入固定集合的额外输入；边界不能保持时记录不等价，不能仅按命中率选优 |

本地字符/字节最长公共前缀及近似 Token 数仅用于解释布局，不冒充供应商内部序列、真实 Token 边界或可保证的缓存上限。输出与工具 Schema 的不同序列化位置以实际请求和线路观测为准。

A/B 尽量采用对称、可复核的实验缓存隔离方式，并登记可能共享服务端缓存的残余影响。无法核验强隔离时，不宣称严格独立或清空缓存；首次请求不等于冷启动。预热对称执行，费用全部保留。
