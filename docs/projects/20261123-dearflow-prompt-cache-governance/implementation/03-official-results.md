## 对照怎样对应产品

A 不是直接把 B 的 HTTP 字符串挪回去，而是在工厂和记忆包装层恢复旧的装配：日期拼接基础系统规则、记忆追加系统消息，跨模拟日期续轮时重建旧图并保留 saver。B 直接使用新产品中间件，同一个图在每次模型调用时重新计算日期并召回记忆。两组都使用相同的当前静态语义规则、工具和最终生产适配器。

固定材料两组的静态内容在归一化空白后相同，真实用户历史和工具定义相同；旧、新装配保留各自必要的空白差异，不声称逐字节完全相同。B 的临时 `runtime_date` / `user_memory` 位于当前真实用户消息前，系统内容在四请求间稳定。

付费调用前发现框架将 system 表示为纯文本块数组，而[官方 Chat Completions 规范](https://api-docs.deepseek.com/api/create-chat-completion/)要求字符串。在 `runtime/modeling.py` 的 `ChatDeepSeek` 适配边界仅将这种数组以空行合并为字符串；拒绝非文本 system 块，不改原消息或 user 多模态。两组共用该修正，并在实际调用前重新冻结九份源码。没有因这个已发现的格式问题先发一次失败付费请求。

[当前结构证据](evidence/official-product-layout-check.json)包含九份源码、依赖版本、16 个请求哈希、system 类型和临时消息位置。固定材料在日期/记忆切换处，本地规范化 JSON 公共前缀为 A 8,840、B 28,541 字节；这只是位置诊断，不是供应商缓存 Token。旧 [八源码结构快照](evidence/product-layout-check.json)是 Phase 5 的历史准备证据，不再代表当前源码或已执行清单。

## 用量、费用与局限

16 条实际响应同时提供原生 `prompt_cache_hit_tokens` 和标准 `prompt_tokens_details.cached_tokens`，值全部一致；与本地 SDK 归一化结果也全部一致，`adapter_cache_comparison="matches"` 为 16/16。模拟夹具中“SDK 可能未透传”的边界分支仍有测试，但这次实际线路没有出现该缺口。

价格按 2026-11-23 [官方定价快照](https://api-docs.deepseek.com/quick_start/pricing)估算，每百万 Token 未缓存输入 0.30、缓存读取 0.006、输出 1.20 USD。两批均处于官方所列工作日 UTC 峰时窗口，统一用该价格计算。16 次合计估算 **0.022440552 USD**，没有账户实扣证明；不要与旧 Xiaok 的 1.8859788 USD 混算或比较线路优劣。

每个场景仅一个 AB 块，两组有对称 24 字符标记，但无法清空或证明服务端缓存隔离。首次零缓存不等于验证了严格冷启动，少量成功任务也不代表统计显著、长期稳定或所有语义等价。这批数据支持继续采用当前布局做后续验收，不支持承诺生产统一缓存率或费用节省。
