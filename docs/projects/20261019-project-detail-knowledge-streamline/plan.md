# 项目详情与知识中台交互收敛 - 整体方案

## 背景
在当前 `platform-web` 前端界面中，存在两处名称与形式极其接近的“知识库”入口：
1. **入口 A**：项目详情页中的 Tab「项目知识库」（`ProjectDetailPage.vue` + `ProjectKnowledgePanel.vue`）；
2. **入口 B**：左侧一级导航「项目管理 ➔ 知识库」（`ProjectKnowledgePage.vue`）。

这两处入口存在以下严重体验与架构缺陷：
- **认知混淆**：两处页面都叫“项目知识库”，但入口 A 没有上传按钮、没有检索沙盒、没有图谱可视化跳转，用户误以为系统知识库功能残缺或不知道该去哪里上传管理文档；
- **职责重叠**：两处同时维护了相同的文档列表和任务列表 API 调用（`GET /capabilities`, `GET /documents`, `GET /jobs`），在用户端造成了视觉与功能上的割裂；
- **缺乏流向引导**：入口 A 作为项目看板，未向用户指引左侧一级中台的存在，导致用户在项目详情中迷失。

## 目标
1. **贯彻方案 A（极简收敛原则）**：明确界定两处页面的职责边界，左侧主导航是全功能中台，项目详情页是概览看板。
2. **强化导航流向**：在项目详情页的「项目知识库」面板中，增加显眼的全局知识底座健康徽章与一键跳转按钮【进入项目知识库工作台 ➔】，引导用户前往全功能中台进行上传与检索。
3. **消除冗余与维护一致性**：保持只读资产状态看板的简洁性，同时不破坏现有 Vitest 单元测试与 Playwright E2E 测试兼容性。

## 方案设计

### 整体架构与交互流向

```
┌──────────────────────────────────────────────────────────────────┐
│              项目详情看板 (ProjectDetailPage.vue)                 │
│                                                                  │
│  [项目概览与成员 Tab]       [项目知识库 Tab] (聚焦概览与引导)      │
│                                 │                                │
│       ┌─────────────────────────┴────────────────────────┐       │
│       ▼                                                  ▼       │
│  [底座健康状态与资产总览]                   [操作流向显式引导]     │
│  • 引擎状态: 在线(Healthy)                   • 提示: 完整管理与检索  │
│  • 已收录: N 篇资料                          • 按钮: [进入知识工作台]│
└───────┬──────────────────────────────────────────────────┬───────┘
        │                                                  │
        │ 点击跳转                                          │ 侧边栏常驻
        ▼                                                  ▼
┌──────────────────────────────────────────────────────────────────┐
│            企业级知识中台工作台 (ProjectKnowledgePage.vue)         │
│                                                                  │
│  • 4大监控指标卡 (已入库文档 / 解析排队中 / 引擎状态 / 文件上限)     │

└──────────────────────────────────────────────────────────────────┘
```

### 关键改动点

#### 1. `apps/platform-web/src/modules/projects/components/ProjectKnowledgePanel.vue`
- **改动：**
  - 在卡片顶部新增高亮引导区域「知识中台导航条」：
    - 清楚展示检索引擎底座状态（在线 / 未配置）；
    - 给出明确文案说明：“完整资料上传、切片溯源、检索沙盒与图谱可视化已收敛至知识中台”；
    - 增加 BaseButton：`[进入知识库工作台 ->]`，点击通过 `vue-router` 直接跳转至 `/projects/:projectId/knowledge`；
  - 保留原有已发布资料和任务历史的轻量视图，但精简空状态文案，直接提供“点击前往中台上传文档”的快捷引导链接。
- **理由：** 保证在详情页中既能快速总览状态，又能一键直达核心中台，彻底消除“重叠但残缺”的劣质交互体验。

#### 2. `apps/platform-web/src/modules/projects/components/ProjectKnowledgePanel.spec.ts`
- **改动：**
  - 补充对“进入知识库工作台”跳转按钮的测试断言；
  - 保证原有的禁用状态提示和文档列表测试用例持续 100% 通过。
- **理由：** 保证改动有测试保驾护航。

## 链路影响

### 受影响的调用链路
本次改动纯属前端表现层与交互路由收敛：
`User Click [进入知识库工作台]` ➔ `vue-router.push({ name: 'workspace-project-knowledge', params: { projectId } })` ➔ 渲染 `ProjectKnowledgePage.vue`。
后端 `platform-api` 与远端 `LightRAG` 契约保持 100% 不变。

### 契约变更
- 无后端契约变更。

## 风险和依赖
- **路由依赖风险**：确保 `workspace-project-knowledge` 路由名称在 `routes.ts` 中稳定有效，传递的 `projectId` 参数准确无误。
- **权限一致性**：若用户无 `project.knowledge.read` 权限，按钮应当置灰或隐藏，与路由守卫对齐。
