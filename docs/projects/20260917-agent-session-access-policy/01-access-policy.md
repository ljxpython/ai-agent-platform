# 访问档位与边界

## 目标

解决 `dearflow_agent` 与 `showcase_demo` 对 `write_file`、`edit_file`、`execute` 等工具每次都由 `interrupt_on=APPROVALS` 暂停的问题，同时保持隔离与可追溯。

## 方案设计

建议第一期采用会话级 `access_policy`，仅提供两个取值（待评审，不代表用户已接受缩减范围）：

| 档位 | 普通读操作 | 工作区写入与受限执行 | 高风险外部副作用 |
| --- | --- | --- | --- |
| `review`（默认） | 直接执行 | 每次审批 | 每次审批 |
| `workspace_write` | 直接执行 | 不逐次审批 | 每次审批 |

若需求是所有现有工具均免审批，可另选 `auto` 方案：关闭该会话的工具 HITL，保留鉴权、工具允许列表、沙箱与业务校验。这在技术上可实现，但会同时免除图片付费调用、部署、记忆写入、技能发布的逐次确认，需要评审明确接受这一范围；不应把它误称为只能写工作区。两档建议优先解决最频繁的文件和命令审批。

参考 `deepseek-harness`：其权限预设把 sandbox mode 与 approval policy 联动，`danger-full-access` 对应 `approval: never`。本平台复用“预设驱动审批”的思想，但不复用其“不设围栏”的含义；平台 Agent 仍必须受 Runtime 工作区 backend、文件权限和 Platform API 权限约束。

### 不可变边界

- 只允许线程所属项目的授权成员选择档位；前端不得通过 run payload 直接指定 Runtime 配置。
- 只对工具白名单取消逐项审批：`write_file`、`edit_file`、`execute`，且执行仍由现有工作区 backend 限制。
- `deploy_preview`、技能发布/撤销、外部写入、凭据或权限操作继续强制审批。
- 仅在线程空闲且无待审批中断时允许切换；运行或中断期间返回 409。先完成审批或取消运行再切换，不能用切档自动批准已有中断。
- 当前 run 使用固定策略快照；切换影响后续 run，不能声称立即撤销已开始的工具调用。权限撤销复用现有网关复核，紧急终止通过取消运行完成。
- Showcase 的 local 展示模式与 Docker 生产模式使用同一会话策略：`workspace_write` 下 `execute` 不逐次审批。local backend 仍须保持现有工作目录、环境变量、超时和输出上限约束；生产隔离由 Docker backend 提供。
