# Runtime 工具治理收敛专项

## 项目概述

- **启动日期：** 2026-09-20；沿用原专项目录，不重复立项。
- **目标：** Runtime 声明 Agent 工具并统一执行把关；Platform 管理用户禁用例外并签名下发；Catalog 仅展示，不参与执行授权。
- **状态：** 部分完成：后端与 Runtime 开发及本轮验证已完成；前端由用户接入，联合发布另行进行。实验阶段不维护旧项目：旧工具功能直接退役，不迁移旧授权、旧工具选择或旧运行状态。
- **级别：** 治理改动（跨服务鉴权契约、工具规则管理、旧数据/接口退役及联合发布）。
- **影响服务：** platform-web、platform-api、runtime-service（含全部 Agent、API 与 Worker）；interaction-data-service 无计划业务变更。
- **负责人 / 评审人：** 待指定；初估 10–16 人天，已移除旧数据保全与兼容恢复工作。
- **模板：** 多专题。前端、平台、Runtime、切换和验证可独立验收，旧全局 plan/tasks/verification 已被取代并移入 archive。

## 已确认方向

1. 工具上限及实际执行属于 Runtime；平台目录仅展示，过期/缺失不能导致普通对话失败。
2. 平台负责“谁不可用哪些工具”的规则管理与审计，Runtime 不维护用户规则表。
3. 不保留旧工具白名单、旧工具选择、双读双写或兼容开关；不维护旧功能语义，新禁用规则由管理员重新配置。
4. Agent 声明某工具不等于所有用户均可执行；资源隔离、操作 scope、审批继续有效。

## 已批准方案

- 新 `runtime_tool_restrictions` 只存项目/graph 全员禁用和用户禁用，拒绝取并集，无 Catalog 外键。
- 平台签名必填 `tool_overrides`（false-only map）及 `tool_policy_version`；空对象合法，缺失/查询失败/验签失败不能默认放行。
- Runtime 最终工具 = Agent 声明 ∩ 本轮可用能力 − 签名禁用项；required 缺失失败。
- 管理员前端只编辑例外，不计算或在普通 Run 中提交权限。新增规则时后端校验真实声明。
- 新 Run/恢复/HTTP 操作使用最新策略，活跃 Run 使用签名快照；紧急撤销需要取消任务/终端。
- 旧项目 false、Agent.context.tools 和旧运行状态直接退役，不转换成新规则或 Agent 变体；仅保留必要 schema 更新。

## 实施约定（已确认）

1. 第一版采用“项目全员 + 指定用户”的拒绝并集，不做角色规则及允许覆盖。
2. 禁用更新从新 Run/恢复生效，活跃 Run 通过取消完成紧急撤销。
3. 旧 Agent 工具选择直接退役，不保留空列表/选择子集语义，不派生兼容 Agent。
4. 工具名禁用与资源动作禁止的边界；execute/MCP 替代路径必须由沙箱/存储规则约束。
5. 切换时停止旧 Worker，旧任务/审批不继续执行；本次批准不扩展为清空其他项目数据。
