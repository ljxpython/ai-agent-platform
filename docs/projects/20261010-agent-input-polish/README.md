## 改动范围

- **影响服务：** 若实施，涉及 `platform-api`、`runtime-service`、`platform-web`；本轮仅文档。
- **改动级别：** 治理改动。不是因为按钮复杂，而是完整支持首条消息需要新增用途明确的无 Thread 模型引用授权，以及专属 Delegation operation。
- **预计工作量：** 后端/Runtime 约 3～4 人天，前端约 1～2 人天，联合验证约 1 人天；这是含失败边界的估算，不是承诺排期。
- **不涉及：** 新 Agent 图、工具、MCP、GraphHarbor 改造、业务 Skill、数据库迁移、自动发送。

## 关键决策建议

1. **用户已确认暂缓开发。** 缺按钮不等于 Agent 执行不可靠；目前也没有用户需求频次和效果收益证据。其余条目为未来重新立项时的备选，不构成实施授权。
2. 若决定投入，只做用户主动触发的纯文本草稿润色，默认关闭；先验证意图保留与延迟，再决定开启范围。
3. 复用 `suggestions` 的授权、模型引用与模型准备段；各功能保留自己的单次调用、超时、输出清洗及失败语义。标题生成不纳入这次收敛。
4. 前端只访问 Platform API；Platform API 不直接初始化模型；Runtime 不运行 Agent、不写对话，不读取历史来猜测意图。
5. 首条消息不创建空 Thread。为该用途建立严格受管的无 Thread 分支，原有 Run/suggestions 的 Thread 授权继续按当前规则执行。
6. `changed=false` 只表示合法结果与原文一致，不能代替模型失败。失败保留草稿，给出标准错误，用户仍能发送原文。
7. 润色成本不属于现有 Run Token 额度或 Run Usage。V1 不另造费用账本；广泛开启前必须有部署入口限流和供应商费用限制的真实证据，否则保持关闭。
