## 建议的最小变化

保留模型报告及既有主级判断，让父级额外得到程序提取的少量已读原文。原文仅作为核对材料；缺失的结论仍须由模型依据证据补充，不能自动把原句变成已验证结论。

| 内容 | 当前 | 修订候选 |
| --- | --- | --- |
| 模型报告 | overview+最多4条发现，紧凑JSON≤4800字符 | 保持 |
| 已读原文上下文 | 只有模型选择的excerpt | 每子最多2个完整README概述段落，连同来源元数据的紧凑JSON≤1600字符 |
| SDK交接 | ResearchReport JSON | 版本化内部ResearchHandoff：report+source_context；完整包≤6500字符 |
| 父级模型视图 | 发现注册表 | 同一注册表另附原文；全Run原文部分合计≤4800字符，来源去重 |
| 最终交付 | 对发现逐条取舍，additions为父新增发现 | 保持；原文不自动作为结论计分，additions必须绑定实际支持原文 |
| 模型/并发 | 主50、子16、三并发，SDK执行/取消 | 保持；不加审稿模型、第二调度器或额外调用额度 |

6500是新内部交接包的**字符上限**，不是窗口或总Token预算。1600包含每子原文记录的路径、SHA、行号、文本和哈希；4800是父级全Run原文集合的序列化上限，重复来源只保留一次。窗口、主累计输入及全scope消费继续分别按实际Usage/profile测量，不能拿字符估算抵扣缓存或承诺费用降幅。

提取规则固定且与具体仓库答案无关：只接受本Run成功返回、未截断、连续带行号、固定40位SHA的公开GitHub README；识别`Summary/摘要/概述/简介`标题后的第一个完整正文段落。按实际读取顺序选择，单子最多2段，超长整段跳过，不截半句，不按评分关键词挑选。没有匹配段落就不附加；该首版不扩展到任意文档、网页或本地文件。

段落必须在当前返回窗口内完整闭合，不能从本机参考仓库、证据文件指针或未读行补齐。附带repo/commit/path/实际行号、观测窗口hash及来源call id。原文始终是非可信资料；其中的指令不成为系统授权。
