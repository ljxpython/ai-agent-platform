## 可审阅的最小修订

现有路径为“来源→最多5条结构化发现→父级自由重写最终报告”。格式约束只能证明字段合法，不能阻止子级遗漏概述，也不能阻止父级二次概括时漏掉已有结论。建议分成两项明确的工程约束，保留现有SDK、调用次数、3路并发、权限及取消行为。

### A. 在已有子报告额度内区分直接答案与细节

`subagents/report.py`将现有最多5条发现调整为 **1条必需的overview + 最多4条补充findings**；总序列化上限仍为4800字符。overview沿用ResearchFinding的结论/条件/来源/置信度/未解点，回答所分派问题的整体行为；不是增加本题事实字段。无法回答也必须明确unknown与缺口，不能把参数/导出列表填作概述。

`code_explorer.py`、`researcher.py`同步Schema及现有ToolStrategy纠错消息。必要的短来源原句可由当前已读窗口校验后绑定到结论，但不把任意抓取原文全部带回主上下文；若这会超出4800总限额，先只实施overview与有界组合，不因增加引文另开预算。该项仍需真实语义验收，Schema不能证明模型概述必然完整。

### B. 对最终组合做显式取舍并确定性呈现

复用LangChain ToolStrategy，让主Agent在正常最后交付调用中返回一次结构化组合，而非再次自由重写全部子结论：

```text
ResearchSynthesis
  decisions[]
    finding_ref     # 当前Run内由程序派生的task_call_id + finding索引
    disposition     # include / disputed / excluded
    reason          # 争议/排除的具体理由；不得静默省略
  additions[]       # 父级新增的有证据发现，沿用ResearchFinding
```

程序只接受当前Run已成功验证子报告中的引用；每条已有发现必须恰好出现一次决定。未知/重复引用、缺条、过长或非法格式明确失败并在现有调用预算内纠正，不启动额外审稿模型。子任务失败保持失败，不能“引用”一个不存在的成功报告。

模型负责根据证据作选择/发现冲突。程序负责把选择后的**原结论、原条件、原来源、原置信度及原未解点**渲染为用户要求的中文表格；争议和排除另保留理由，不能悄悄丢弃。采用确定性行组合后，不再依赖父级重新转述来保存这些字段。它保证已交接信息有明确去向，不保证原结论准确，也不把所有子结论自动升为可信事实。

串行与委派共用同一最终Schema/渲染实现；串行没有子发现时decisions为空，由additions承载主级发现。两臂的调用/窗口等设置一致，唯一开关仍为Pro delegation；不把委派组专用答案清单用于串行组。串行从原文提取结论仍有模型遗漏风险，必须按同一原门槛实测。
