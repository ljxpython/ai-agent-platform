## A. 技能是否需要多个版本

**已决定：当前不对用户提供多版本管理，一个技能保留一份当前内容。**

一个 `(tenant_id, project_id, user_id, slug)` 对应一份当前技能内容即可。用户理解“导入技能、更新技能、使用技能”，不必理解候选、发布、digest 选择和会话版本绑定。只有明确需要“不同会话固定不同版本、可复现实验、审批发布、灰度或版本依赖”时，多版本模型才有清晰收益；目前讨论没有提出这些需求。

### DeerFlow 如何处理

用户指定的本地 DeerFlow 采用当前技能文件，加修改历史与内容恢复：

- `backend/app/gateway/routers/skills.py::update_custom_skill()` 校验并扫描内容，写入当前 `SKILL.md`，记录 `prev_content/new_content`，刷新用户技能提示词缓存。
- `get_custom_skill_history()` 返回历史；`rollback_custom_skill()` 取历史记录的 `prev_content`，重新校验/扫描后写回当前 `SKILL.md`，再记录一次回滚。
- `backend/packages/harness/deerflow/skills/storage/local_skill_storage.py::append_history()` 将记录追加到 JSONL；用户实现的历史位置是用户技能目录下 `.history/{name}.jsonl`。
- 未发现本项目同样的 `candidate → review → evaluation → active` 强制发布体系或 `dear_skill_bindings` 永久会话绑定。

所以它考虑了“修改后想恢复”，但核对到的管理流程并不是让用户并行维护、选择多个已发布版本。该 HTTP 回滚主要恢复 `SKILL.md` 内容，不应包装成完整技能包的任意历史快照恢复。

## B. 上传、更新和运行生效

**已决定：导入/更新 → 格式与安全检查 → 原子保存当前内容 → 后续新运行使用。**

- 首次导入创建技能；同名上传明确提示为更新，不能静默覆盖。更新携带当前内容标识做冲突检查，避免并发覆盖。
- 校验失败保留当前内容；保留包大小、路径、文件类型、身份隔离、正则扫描阻断和只读审查；审查不构成发布门槛，不新增 AI 扫描服务。去掉“必须在对话里调用评估工具才能发布”的产品门槛。
- 建议取消会话永久冻结；一个运行开始后使用其已选定内容，下一次运行重新读取当前技能，即便仍是同一个会话。
- “运行内不变”必须覆盖技能文件与延迟读取，不能只固定列表。如何利用现有运行工作区实现、是否需要运行级内容副本，实施前再核对，不能声称当前已经满足。
- 历史消息不会因技能更新而重写；续聊使用新技能也不保证模型忘记此前读过的旧技能内容。不承诺历史运行的完全可复现。
- 启用/停用、删除自定义技能已纳入本期；在线编辑、导出仍不纳入。建议更新维持原 enabled 状态，启停/删除只影响新执行，具体见 08 第 5.1 节。

不再计划 active/candidate/inactive/revoked 转换或旧绑定接管；新模型初始化后通过新接口上传。schema 迁移仍需可靠执行，记忆、外部任务等非技能数据不因该决定被清空。

## C. 技能属于谁，是否需要会话

**已决定：保持 tenant + project + user 私有范围，管理接口不依赖 thread。**

platform-api 从登录身份和项目权限确认操作者，再签发相应 Runtime 委托；runtime-service 校验委托并按三维 scope 访问技能。不能从前端传来的 user_id 直接决定归属，也不能删掉会话校验而不补上资源级权限。

这样没有会话的用户也能先导入技能，前端不必展示“治理上下文”。本次不默认新增项目共享技能或公共技能管理权限。路径、权限码、旧接口兼容方式待方案确认后写入 07。

## D. 公共技能目录与详情

**已决定：后端统一提供公共列表、文件树和按需文本内容读取，公共与自定义均覆盖。**

- 列表复用 Runtime 已有技能枚举与 frontmatter，不让前端再维护另一份 slug 清单；platform-api 负责平台访问入口。
- 所有内置技能全部展示，不设隐藏名单。是否验收/推荐的已有事实标识不作为展示或管理门槛；全可见不意味着允许修改公共文件。
- 推荐提供文件树与按路径读取文本内容，首次查看打开 `SKILL.md`。列表只返回元信息，不塞进所有文件内容。
- 公共与自定义技能使用清楚的来源标识，文件读取局限在目标技能包内；禁止越界路径，限制大小，不执行 HTML/JS 或脚本。
- 首次查看打开 SKILL.md，辅助文本文件同样可读；二进制文件只提供元信息，不把文本读取扩张为任意二进制预览。

只读文本详情与公共全可见已决定；具体大小限制、响应字段、错误码仍是 08 的技术草案。

## E. 数据库组织怎么收口

**已决定：保留 PostgreSQL，统一服务自有迁移与连接入口，业务查询仍归业务模块。**

先定单份当前技能的数据模型，再统一应用迁移与连接入口；业务查询仍由技能、记忆、外部任务、收件箱模块分别维护。GraphHarbor 自有表与 Runtime 应用表分清责任。

技能存储和迁移归 runtime-service，GraphHarbor 维持对标通用 Agent Server 的边界。**自有 Alembic、`src/runtime_service/db/migrations/`、独立 `runtime_app_alembic_version` 与 `python -m runtime_service.db upgrade` 已获用户批准，代码暂未实施。** 仓库级部署自动接入标“延后”；旧技能数据兼容标“不做”。核实依据见 08 第 3.4 节。减少产品版本不等于省略数据库 schema 版本管理。
