# 方案与影响

状态：已完成（done）。全实例本地认证按批准方案实施并验证通过；2026-09-21 新版运维包已上传并通过远端校验。

## 推荐方案：本机 PostgreSQL 实例统一密码认证

1. 私有备份 pg_hba.conf、相关 app-local env、角色原密码状态及已有 .pgpass（若有）。
   备份权限 600；密码、密码摘要不进入文档、控制台或 Git。
2. 为 lijiaxin 设置 SCRAM 密码，沿用上一轮服务器配置副本中已生成的 Runtime 密码，保持用户要求的一致性。
   platform_api 保留当前密码，不重置平台管理员登录密码、JWT 或模型 Key。
3. 更新本地 apps/runtime-service/.env 的 DATABASE_URI；检查受影响的本仓库脚本和配置。
   平台连接串已经含密码，先核验其确实匹配数据库存储值。
4. 将本机 pg_hba.conf 中 Unix socket、127.0.0.1 和 ::1 的 trust 规则改为 scram-sha-256，
   包括复制连接规则，reload 生效，不重启数据库。
5. 通过当前用户 ~/.pgpass（600）提供本机明确 host/port/role 的凭据，数据库名可匹配该角色的全部数据库。
   这允许遵循 libpq/passfile 的本地工具继续工作，但不是关闭认证；隔离验证时必须禁用该文件。
6. 重新建立应用连接并验证健康；需要重启 Runtime 时先确认没有进行中任务，仅重启相关应用进程。
7. 更新部署标准中“本地无密码”的现状说明，刷新服务器私有交接说明和对应配置完整性记录。
   腾讯服务器仅同步交接文件，不执行其数据库或服务操作。

## 影响

- lijiaxin 是共享超级用户：它的全部数据库连接都会受本机 HBA 收紧影响。
- 当前已建立的 PG 会话不因 reload 被踢下线，新连接必须认证；旧连接存活不能作为成功证据。
- 其他项目若使用不读取 .pgpass 的驱动，必须补密码；不能保证只改本仓库就覆盖全机客户端。
- 不降低 lijiaxin 权限、不变更库 owner，避免将本次任务扩大为数据库角色拆分。
- 保持监听地址和端口不变，不开放公网、不迁移业务数据、不清理历史。

## 未采用的较小范围备选

仅为 graphharbor_acceptance 和 platform_api 添加优先匹配的密码规则（socket/IPv4/IPv6）。
其他数据库继续原认证，减少其他项目影响；但共享超级用户仍可经其他 trust 库登录，
因此只能宣称两个库的入口校验密码，不能宣称整台 PostgreSQL 已完成密码认证。
用户若选该范围，实施前相应调整验证标准。

## 回退

保留管理连接，在关闭前完成新连接正反向检查。
异常时由管理连接恢复原 HBA 并 reload，恢复私有备份中的 env、.pgpass 和角色原密码状态。
备份不覆盖已有文件；先验证可读性和校验值。回退不涉及数据回滚或 DROP。
