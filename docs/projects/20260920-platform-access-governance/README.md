# 全平台菜单、页面与角色权限治理专项

## 项目概述

- **启动日期：** 2026-09-20；2026-09-21 进入分章讨论，2026-09-22 按用户批准实施。
- **目标：** 梳理全平台角色、菜单可见性、页面访问、操作权限和数据范围，形成前后端一致的访问控制。
- **状态：** 人工验收中（2026-09-22）。本期技术实现与自动化 Final done：固定角色、平台模型、页面/对象授权、撤权刷新、公告/账号审计、P1 私有 Thread 及个人记忆入口治理完成。最终 API 226 passed/13 skipped，Web 307 passed/1 skipped，10 个浏览器场景及真实模型审批通过；迁移、备份恢复、重启持久化及适用性能证据齐全，详见 07。用户人工验收按 08 执行并填写结果；共享/跨项目记忆、自定义角色等明确 deferred。已按用户批准恢复 Runtime audience 配置和重启预检，未修改 Runtime/GraphHarbor 业务逻辑；未提交或生产部署。
- **改动级别：** 治理改动，涉及跨服务访问控制与安全边界。
- **影响范围：** 仅 platform-web、platform-api；不修改 Runtime Server、GraphHarbor、interaction-data-service；若所选方案无法在此边界完成，列出阻塞和替代方案，不自动扩围。
- **负责人 / 评审人：** 待指定。
- **预计工作量：** 基线约 16–25 人天；P1 个人对话隔离为条件分支；自定义角色与 BYOK 本期不做，见 07。
- **模板类型：** 多专题模板；README 是唯一阅读入口，各章节自带任务与验证状态。

## 讨论方式与模块关系

每轮只讨论一章，通过 D01—D36 指定问题。每项都区分“代码事实”“推荐方案”“用户已确认”；推荐不等于批准。后续可直接说“讨论 D04”或“第五章选择 P1，但管理员不可接管”。已授权持续把讨论结果写回本目录，无需每次重新询问是否记录。

已讨论的决策按用户明确批准进入实施；D24—D28 作为自定义角色 deferred 后续问题保留。P1 授权事实源采用 Platform DB；13 个旧 Thread 的数据库历史在双库备份恢复验证后已按冻结 ID 清理，未擦除沙箱磁盘目录；自定义角色与 BYOK 本期明确不做。

按大型多阶段治理项目组织章节，不声称七章可独立上线：01 是分析基础，02/03 是同一前后端发布单元；04 的公告/账号修补可独立验收；05/06 是条件性扩展；07 只维护交付门禁，不复制各章任务进度。

## 与其他专项的边界

- [工具治理专项](../20260920-runtime-optional-tool-resolution/README.md)后端/Runtime 已有禁用例外实现，前端交接与联合发布依其自身记录；本专项统一平台入口授权，不修改已批准的工具签名协议。旧文档仍称本专项 deferred 的表述已被本 README 的规划中状态取代。
- [个人记忆专项](../20260920-dear-agent-memory/README.md)负责记忆存储、作用域和召回；本专项只核查平台入口与主体授权，不承诺用 Thread ACL 代替个人记忆隔离。
- 分支与成果专项已有能力必须纳入访问矩阵；不重新实现业务能力。
