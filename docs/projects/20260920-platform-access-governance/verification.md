# 全平台权限治理 — 后续验证计划

## 计划

### 单元与组件

- [ ] 路由权限 all/any、无项目、项目切换、未登录/身份过期。
- [ ] 菜单可见性与直接 URL 访问一致，按钮权限不冒充数据权限。
- [ ] 多角色组合、平台/项目角色及后端 IAM 矩阵。
- 现有入口：`apps/platform-web/src/router/guards.spec.ts`、`routes.spec.ts`、`apps/platform-web/src/services/auth/permissions.spec.ts`、`apps/platform-api/tests/test_iam_policy_engine.py`；后续按批准方案确定新增用例。

### 集成与安全

- [ ] 绕过菜单直接请求接口，缺少权限仍拒绝。
- [ ] 项目 A 的身份不能访问项目 B 的资源；列表/详情/导出/批量操作分别验证。
- [ ] 修改角色、成员或权限后，缓存和新请求行为符合批准的时效。
- [ ] 非授权主体不能提升自身权限；治理动作具备审计。
- [ ] 本专项不削弱现有工具治理的签名限制与操作校验。

### 端到端

- [ ] 各平台/项目角色按批准矩阵遍历关键菜单、页面、只读和写操作。
- [ ] 多项目切换、多标签页、直接 URL、权限撤销后重访。
- [ ] 工具权限管理与普通工具目录分别按各自权限访问。

### 适用的迁移与回滚

- [ ] 若修改角色/授权数据，先做存量映射、迁移失败保护及恢复演练。
- [ ] 若无数据迁移，记录不适用理由；仍验证代码回滚与权限行为。
- [ ] 性能关注权限计算与页面加载是否引入重复远程查询，阈值后续基线评审确定。
