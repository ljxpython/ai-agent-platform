# 08 人工验收用例

## 1. 验收目标与结论规则

本文供验收人按真实页面、真实 Platform API 和本机 Runtime 执行最终人工验收。自动化证据见 [07 实施顺序、任务总表与验收](07-implementation-and-verification.md)，本文不重复自动化测试过程。

本期验收范围：

- 固定平台角色与项目角色的页面、动作和数据范围。
- 全局模型连接与项目可选能力分离。
- Thread 默认个人私有、显式共享、管理员限时接管、删除与审批。
- 私人 Thread owner 的沙箱、终端和 `full_access`；共享者不得继承这些能力。
- 撤权后的新请求即时拒绝，前台激活/切换/拒绝时立即刷新，持续前台最多 60 秒刷新。
- 公告、服务账号、审计及开户绑定边界。
- 项目内个人记忆：同一用户、同一项目可跨 Thread 使用；换用户或换项目隔离。

不在本期验收范围：项目共享记忆、跨项目个人记忆、自定义角色、项目 BYOK、公共沙箱、Agent 健康拨测、Runtime/GraphHarbor 业务 ACL。

每个用例只能填写以下结果之一：

| 结果 | 含义 |
|---|---|
| PASS | 所有步骤和预期均满足，并留存证据 |
| FAIL | 任一授权、安全或业务预期不满足 |
| BLOCKED | 环境或依赖导致无法执行；必须写明阻塞原因 |
| N/A | 经确认不适用于当前环境；必须写明依据，不能用于掩盖失败 |

放行规则：P0 用例必须全部 PASS；P1 可以存在有依据的 N/A，但不能存在 FAIL。以下任一现象直接判定发布阻断：未授权用户读到私有内容、共享者获得终端或 `full_access`、撤权后新请求仍成功、无项目运维隐式获得业务执行资格、审计返回正文/密钥/token 原文。

## 2. 验收前准备

### 2.1 服务与配置

1. 在仓库根目录启动本地栈：

   ```bash
   bash scripts/local-stack.sh start
   bash scripts/local-stack.sh status
   ```

2. 确认 Platform Web、Platform API、Runtime API、Runtime Worker 均为 running/ready。
3. 确认 Runtime API 与 Worker 使用同一组上下文签名配置，并包含：

   ```text
   GRAPHHARBOR_RUNTIME_CONTEXT_AUDIENCE=graphharbor-worker
   ```

4. 准备一个可正常执行且包含人工审批动作的 Agent。审批用例必须能形成 `interrupted -> approve -> success`，不能用纯前端假数据。
5. 浏览器验收建议同时准备普通窗口、无痕窗口和移动端 390 x 844 设备模拟。

### 2.2 账号矩阵

账号名称可自行调整，但角色、成员关系必须与下表一致。除明确列出的关系外，不要附加其他平台角色或项目角色。

| 编号 | 身份 | 平台角色 | 项目 A | 项目 B | 用途 |
|---|---|---|---|---|---|
| U-SA | 平台超级管理员 | `platform_super_admin` | 无 | 无 | 平台治理、限时接管、跨项目治理事件 |
| U-OP | 平台运维 | `platform_operator` | 无 | 无 | 控制面、目录、模型、全局公告；验证无隐式执行 |
| U-PV | 平台只读 | `platform_viewer` | 无 | 无 | 平台治理只读 |
| U-PA | 项目 A 管理员 | 无 | `project_admin` | 无 | 成员、安全策略、项目会话治理 |
| U-ED | 项目 A 编辑 | 无 | `project_editor` | 无 | Agent 编辑与业务执行，不得改安全策略 |
| U-EX1 | 执行者 1 | 无 | `project_executor` | `project_executor` | Thread owner、跨项目隔离、个人记忆隔离 |
| U-EX2 | 执行者 2 | 无 | `project_executor` | 无 | 同项目 peer、共享与私有隔离 |
| U-NO | 无项目普通用户 | 无 | 无 | 无 | 无项目空态与直接 URL 拒绝 |
| SA-A | 普通服务账号 | 不适用 | 显式 grant | 无 | 项目 grant、项目共享与撤权 |
| SA-H | 高权限服务账号 | 超级管理员能力 | 按需 | 无 | 高权限对象保护 |

密码、API Key 和 token 只记录在本地安全位置，不要粘贴进本项目文档、截图或审计备注。

### 2.3 测试数据

- 项目 A、项目 B：均为启用状态，各有可用 Agent/Graph；项目 A 配置可执行模型。
- T-A1：U-EX1 在项目 A 创建的私有 Thread，标题使用 `UAT-A1-private-<时间戳>`。
- T-A2：U-EX1 在项目 A 创建、停在真实审批节点的私有 Thread。

## 3. P0 核心验收

### UAT-01 无项目用户与平台角色入口

**前置：** U-SA、U-OP、U-PV、U-NO 均无项目成员关系。

**步骤：**

1. 分别登录四个账号，记录默认落地页、左侧菜单和项目选择器状态。
2. U-NO 访问 `/workspace/overview` 和任一项目 Chat 深链。
3. U-OP 进入 `/workspace/control-plane`，选择项目 A 作为同步范围并同步 Graph/Tool 目录。
4. U-OP 直接访问项目 A Chat 并尝试创建 Thread 或发送请求。
5. U-PV 进入 `/workspace/models`，检查只读状态并尝试修改模型。
6. U-SA 进入平台治理页面，再直接访问项目 A 私有业务页。

**预期：**

- U-NO 落到总览空态，明确提示申请加入项目；业务深链拒绝并给出可见原因。
- U-OP 默认进入治理/控制面，可同步目录，但不是项目 A 成员，不能创建 Thread、发送消息或执行 Run。
- U-PV 可读平台允许的治理数据和全局模型摘要，所有写动作隐藏或禁用并说明原因。
- U-SA 可进入平台治理页，但不会自动成为项目成员，也不能默认读取私有 Thread。
- 移动端重要说明可直接看到，不依赖 hover tooltip。

### UAT-02 固定项目角色矩阵

**步骤：**

1. U-PA、U-ED、U-EX1 分别进入项目 A 的成员、Agents、模型与工具、Chat、会话治理页面。
2. U-PA 执行成员管理、项目安全/运行策略修改、Agent 编辑和一次业务执行。
3. U-ED 编辑 Agent 并执行；尝试修改成员关系和项目安全/运行策略。
4. U-EX1 创建 Thread 并执行；尝试编辑 Agent、成员关系、项目模型/安全策略。
5. 三个账号分别直接输入无权页面 URL，不能只检查菜单是否隐藏。

**预期：**

- U-PA 可管理项目成员、Agent 和项目策略并可执行，但不能管理全局模型连接或平台角色。
- U-ED 可编辑 Agent、使用已授权能力；不能管理成员或修改项目安全/运行策略。
- U-EX1 是真正执行者，可创建私有 Thread、发送消息和运行；不能编辑 Agent 或执行治理动作。
- 菜单、页面 guard、按钮和后端 API 结果一致；直接 URL 不能绕过权限。

**步骤：**

### UAT-06 `read/comment/edit/share/delete` 独立共享

**前置：** T-A1 仍由 U-EX1 持有；U-EX2 是项目 A 成员。

**步骤：**

1. owner 仅向 U-EX2 授予 `read`；U-EX2 尝试读取、发消息、改标题、继续分享、删除、打开终端和选择 `full_access`。
2. 依次增加 `comment`、`edit`、`share`，每次只验证新增动作和未授予动作。
3. 若目标为 project_admin，单独授予 `delete` 并验证；普通成员目标不应可获得 `delete`。
4. 撤销 U-EX2 全部共享，立即重试列表、详情和新请求。

**预期：**

- `read/comment/edit/share/delete` 按动作独立生效，未授予动作始终拒绝。
- 任何个人共享都不授予 `approve`、终端或 `full_access`。
- 删除只允许 owner、项目管理员或平台超级管理员；普通成员不能通过共享升级为删除者。
- 撤销后新请求立即 403，页面清除正文与工作区，不保留可继续操作的旧内容。

### UAT-07 管理员限时 takeover

**允许场景：** 已确认的安全事件调查、合规/法务要求、用户明确授权的故障排查、人员离职或账号不可用时的必要业务交接。不得用于日常浏览、绩效检查、好奇查看或绕过项目成员关系。

**步骤：**

1. U-SA 打开 `/workspace/thread-governance`，选择项目 A 并输入 T-A1 ID。
2. 未接管时定位会话，确认看不到标题和正文。
3. 选择允许的分类，填写不少于 10 字的具体原因、真实或验收工单号，期限设为 1 分钟。
4. 接管后读取 T-A1，确认页面显示有效期；检查审计中存在 grant 和 access 事件。
5. 立即结束接管，重新读取；再创建一次 1 分钟接管并等待过期后重试。
6. U-OP、U-PV 尝试访问相同治理入口或调用 takeover。

**预期：**

- U-SA 未接管时不能读取；接管必须同时具备分类、原因、工单和 1 至 60 分钟期限。
- 接管只增加临时 `read`，不会增加项目成员、comment、终端、`full_access` 或个人记忆读取资格。
- 手动结束或到期后立即拒绝新读取，页面清除私有内容。
- 授权、读取和结束均有审计；U-OP/U-PV 不能接管。

### UAT-08 删除与真实审批边界

**前置：** T-A2 停在真实审批节点。先记录审批项内容和指纹；另建可删除的临时 Thread，避免破坏后续用例。

**步骤：**

1. owner 在 T-A2 审批，确认 Run 从 interrupted 继续到 success。
2. 再准备一个审批 Thread，由 U-PA 从项目会话治理入口定位并审批。
3. 再准备一个审批 Thread，由 U-SA 通过平台治理流程审批；若需要读取私有详情，先按 UAT-07 takeover。
4. U-EX2 仅获 read/comment/edit/share 后尝试审批和删除。
5. owner、U-PA、U-SA 分别对各自临时对象验证删除；删除前确认二次确认提示。
6. 在审批页面打开后改变审批项或撤销资格，再提交旧页面内容。

**预期：**

- owner、项目管理员、平台超级管理员具备审批/删除治理资格；平台管理员读取私有详情仍受 takeover 约束。
- 共享者即使有 edit/share 也不能审批或删除。
- 审批只提交当前中断项决策，不能覆盖模型、input 或 config；审批项指纹变化时旧提交被拒绝。
- 删除需要明确二次确认；删除后 Thread、Run 和子资源均不可访问。

### UAT-09 子资源继承 ACL

**步骤：**

1. U-EX2 未获共享时，针对 T-A1 尝试 state、runs、messages、capabilities、文件、图片、工作区、SSE、终端和 Dear Memory 入口。
2. 只授予 read，再重复上述动作。
3. 增加 comment/edit 后验证消息与允许的编辑动作。
4. 撤销共享，再检查已打开页面、SSE 和新请求。

**预期：**

- 子资源不会绕过 Thread ACL；未授权均拒绝。
- read/comment/edit 只开放对应子资源动作，终端、`full_access`、delete、approve 和 owner 个人记忆不随共享继承。
- 撤权后新 HTTP 请求立即拒绝；断开浏览器 SSE 不等于取消已被服务端接受的 Run，二者须分开判断。

### UAT-10 撤权刷新、双标签与 60 秒上限

**步骤：**

1. U-EX2 在两个浏览器标签打开已共享的 T-A1，保持页面前台。
2. owner 在另一窗口撤销共享。
3. 标签 1 立即发起新请求；标签 2 不操作，记录自动刷新至失权状态的时间。
4. 再次授权后，让标签 1 失焦再激活；然后切换项目 A/B。
5. 角色从 executor 降级/移除后，重复新请求与前台等待。

**预期：**

- 撤权后的新请求立即 403；明确 403、页面重新激活、项目切换会立即刷新身份与对象权限。
- 无操作且持续前台的页面应在 60 秒刷新周期内发现失权。验收允许调度抖动上限 65 秒；超过 65 秒判 FAIL。
- 两个标签都清除正文、工作区、待发送缓存和可执行控件；迟到的旧响应不能恢复内容。
- 已被后端接受的事务/Run 不承诺自动回滚；需要停止时单独执行 cancel/close 并验结果。

### UAT-11 服务账号 grant、项目共享与撤销

**步骤：**

1. SA-A 无项目 grant 时用 API Key 读取或执行项目 A，记录结果。
2. 为 SA-A 增加项目 A grant，但保持 T-A1 私有，再读取 T-A1。
3. owner 将 T-A1 设为项目共享，动作只选 read/comment；SA-A 再读取并发送允许请求。
4. SA-A 尝试终端、`full_access`、delete、approve 及个人 ACL。
5. 移除项目 grant 后立即重试；随后撤销 API Key 再重试。

**预期：**

- SA-A 必须同时具有显式项目 grant 和项目共享，才能访问项目共享 Thread。
- 服务账号使用稳定主体 ID，不借用自然人身份；首期没有个人密钥 ACL。
- 项目共享不授予终端、`full_access`、delete、approve。
- 移除 grant 后新请求立即拒绝；撤销 Key 后返回未认证。

### UAT-12 公告 scope 与归属

**步骤：**

1. U-OP 发布 G1；U-PA 发布 PA1；项目 B 管理者发布 PB1。
2. U-OP 打开公告管理列表；U-PA 打开项目 A 公告范围。
3. U-OP 尝试编辑/删除 PA1 和 PB1；U-PA 尝试编辑 G1、PB1。
4. 编辑 G1、PA1 时检查 scope/项目字段；尝试通过请求篡改把 PA1 迁移为全局或项目 B。

- 普通编辑不能改变公告归属；前端锁定归属，后端篡改请求也拒绝。
- 本期没有普通迁移入口；未来迁移必须同时具备源/目标授权。
