# F05：Agent 模型上下文 PII 脱敏

## 项目概述

- **启动日期：** 2026-10-09。
- **目标：** 按已批准方案补齐模型外发文本隐私保护，复用现有安全出口和 Agent 执行能力。
- **负责人：** 用户负责安全与产品方案评审；后端/Runtime 开发者负责实施；前端由用户同事接手。
- **模板类型：** 标准模板。检测、模型接线和旁路保护必须一起验收，不拆成独立专题。
- **改动级别：** 治理改动，涉及个人数据、模型外发和安全失败语义。
- **状态：** 已完成（`done`）；后端 Runtime/API、前端错误消费与草稿保留、Playwright 端到端浏览器闭环验证及全链路四态联合验收均已 100% 绿灯完成。本地隔离服务栈持续保持运行就绪供用户亲手验收。
- **本次授权：** 实施全栈闭环开发与 Playwright 自动化测试闭环，保持服务运行供用户验收，不修改无关文件，不部署现役，不提交 Git。
- **预计工作量：** 评审后 Runtime/API 实施及验证约 5–8 人天；前端最小接入由同事估算。真实环境准备时间另计。

## 结论：有条件做，收窄后做

如果目标只是避免 Langfuse 留下消息正文，**不需要再造 F05**：当前适配器已在导出时删除 input/output/exception/status 正文，错误与诊断也有安全出口，应复用并补回归。

如果部署确实要求**指定类型的标识符不进入外部模型的文本上下文**，当前存在真实缺口，建议实施本方案。Open-SWE 的追踪脱敏和可选外部 LLM Gateway 不能证明本平台模型调用已受保护。

同事方案方向可取，但“五个检测器 + 一个 middleware”不足以完成目标：摘要、标题、推荐问题、个人记忆提取、视觉工具的文本问题都可能单独调用模型。只改主 Agent 会留下旁路。

不建议直接照搬 DeerFlow：其用户消息保留原 state，远程工具结果则在工具边界改写；异常时继续放行原文；部署级 HMAC 可关联不同用户。本平台建议统一使用**模型请求副本**，保留现有消息/工具/审批事实；启用保护后处理失败阻断外发；占位符限定在受信 Thread 作用域。

## 服务分工

| 层 | 是否开发 | 本方案范围 |
|---|---|---|
| runtime-service | 后端完成 | 唯一检测/HMAC 算法；四图主子、三类摘要及旁路请求副本保护；真实收包、取消、重启/轮换/回退已验 |
| platform-api | 后端完成 | 复用精确错误投影、HTTP/SSE 与 Thread 委托；私有策略防注入/公开剥离已验，不复制检测算法 |
| platform-web | 最小交接 | 同事接入安全失败说明和原有错误态；不做浏览器检测、密钥输入或独立管理页面 |
| GraphHarbor | 复用 | 原生 Run/checkpoint/SSE/恢复；不新增引擎、表或执行状态机 |
| Langfuse/OTel | 复用 | 保持正文删除、metadata 白名单和导出故障隔离；不改为保存“脱敏后的完整正文” |

## 范围限制

- 本方案保护的是配置检测器识别到的**模型外发文本**，不是完整 DLP，也不是数据存储匿名化。
- 用户消息、工具原始结果、checkpoint、消息队列、工作区和人工保存的记忆仍可包含原文；访问保护沿用现有 ACL。
- 图片、音视频、文件二进制中的 PII、工具自身向第三方发送的参数不在本期保证内。需要禁止这些外发的部署，应先停用相应能力，不能用文本脱敏替代。
- 不新增脱敏映射表、自动还原、项目级策略 CRUD、前端开关、外部隐私 SaaS、NER 或客户历史数据清洗。
- 生效契约仅同步已批准且已验证的增量；其他专项的 draft 不因本专项实施而毕业。
