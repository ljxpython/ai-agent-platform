## 探针与实际输出

一次性命令使用 `<runtime-python> -B - <<'PY'`，临时 Python 经 stdin 执行，没有写入业务代码或新常驻脚本。复现的核心调用/断言如下：

2. 官方 `_aprocess_large_message` 比较 79999/80001 字符，backend 的 `awrite` 返回 `WriteResult(error="unavailable")`。阈值内不写；超阈值写失败保留原消息，exit 0。
3. 同模型 profile=12000/1024，对比官方 `create_summarization_middleware` 与本项目 `ConversationOffloadingMiddleware`；前者 `_truncate_args_trigger=("fraction", 0.85)`，后者 `None`，exit 0。
4. 使用含 4000 字符 `write_file.content` 的旧消息及足够大的后续 tail，调用两者 `_truncate_args(messages, total_tokens=11000)`；官方模型请求参数为 43 字符，本项目仍为 4000，原始 AIMessage 完全未修改，exit 0。
5. 50000 字符 ToolMessage 经官方 `_process_large_message`，没有外置；`count_tokens_approximately` 为 12505，平台 12000 容量/256 输出的 input_budget 为 10720，exit 0。未实际调用 provider 或演练 overflow 恢复，不能推断一定溢出。
