> **发起与确认日期：** 2026-11-17。
> **授权范围：** 用户先确认设计，后追加“开始实施直到所有任务开发完成”，并明确使用当前环境。本轮实施 T18–T20，使用合成或获准测试资料，仅专用测试项目配置临时模型并在收尾停用/替换原凭据；不包含 Git 交付、生产部署、Docker 或共享主服务配置变更。
> **涉及范围：** 平台助手用户指南、Runtime 文档选择与阅读、Platform API 文档读取及用户指南版本校验。

## 1. 用户要完成什么

用户在平台前端打开助手，询问平台有哪些功能、功能在哪里、如何操作。例如“怎样创建 Agent”“怎么把刚才的聊天拿去评测”“上传的资料在哪里使用”。

助手根据问题选择相关用户指南，读取当前正文，说明实际页面入口、操作步骤、结果位置和必要限制。文档没有覆盖的功能或按钮，应明确说明资料不足，不能参考其他产品猜测。

本方案只维护少量面向用户的短文档，介绍平台功能及前端操作，不收录服务器启动、环境变量、Docker、数据库部署、日志查询和运维排障。此范围约束针对用户指南，不代表移除助手已有的 SQL、运行诊断、日志或源码工具。

## 2. 原问题与当前实现

以下问题核对于实施前。2026-11-17 已移除两份 Python 内置正文，默认资料改为 `docs/assistant/manifest.json` 列出的六篇用户指南。模型沿现有授权回调获得短目录，按 ID 读取当前正文；未指定 ID 时仅返回目录，不再进行关键词匹配。普通文档 revision 变化不再拒绝历史访问；源码和数据库版本约束保留。

实施前，助手通过 Runtime 的 `search_documents` 工具回调 Platform API。未配置外部资料时，API 使用两份内置指南；外部资料通过 `manifest.json` 中的文件清单读取。

原检索按空格拆分查询，选择每篇文档的首次匹配位置，再按清单顺序返回最多五篇。指定 `document_id` 时会按行读取并忽略 `query`。2026-11-17 离线抽取原函数复现：默认资料查询“评测”有一条结果，“评测集”“怎么创建评测集”“通知中心”均无结果。该失败保留为问题依据，修复后的真实模型验证另见 [实施证据](implementation/03-guide-and-diagnostics-optimization.md)。

现有证据抽屉已经展示文档标题、行号与返回的正文片段。本方案沿用该展示，不新增全文预览抽屉。

原 `revision` 是资料清单提供的字符串；内置资料固定使用 `platform-assistant-v1`，不是自动计算的内容版本。原历史校验将文档与源码放在同一分支，标记变化会触发 `assistant_history_source_revoked`。现在用户指南的 revision 仅表示来源标记，SHA256 表示本次正文；工具撤权及项目/会话当前授权仍会复核。

## 3. 用户指南的内容与维护

### 3.1 初始目录

在 `docs/assistant/` 维护以下六个主题及人工目录，标题、页面和步骤已对照当前前端核对。知识库项目页上传尚未接通实际提交，指南明确说明该限制，不把弹窗提示写成上传成功。

| 文档 ID | 标题 | 适用问题 |
|---|---|---|
| `overview` | 平台与项目入门 | 平台能做什么、从哪里开始、如何进入项目 |
| `agents` | Agent、模型与工具 | 如何创建 Agent、选择模型、配置可用工具 |
| `chat` | 聊天、会话与产物 | 如何发起和继续对话、处理审批、查看及下载产物 |
| `knowledge` | 知识库使用 | 如何上传资料、管理文档、在聊天中使用知识 |
| `evaluation` | 评测与改进 | 如何把会话转成评测资料、发起评测、查看结果 |
| `settings` | 个人设置与通知 | 如何修改个人资料、查看通知及进入关联任务 |

六篇指南已创建，功能是否可见仍取决于用户权限和实际接入状态。正文只维护一份，不保证每项操作向所有用户开放。

### 3.2 写作规则

每个功能说明回答以下问题：

1. 该功能帮助用户完成什么。
2. 从哪个页面进入。
3. 点击什么、填写什么、按什么顺序操作。
4. 完成后在哪里查看结果。
5. 需要什么权限或前提，有哪些用户可感知的限制。

指南以当前前端行为为准。看不到按钮时，可以说明所需权限和联系管理员的方式，不扩展为后端排障教程。

每篇保持短小，优先完整读取。内容过长时按用户功能拆篇；不得为满足固定 80 行窗口而截掉完整操作步骤。读取仍需保留明确的长度限制，超限时说明截断和缺失范围，不能假装已经读完。

只维护一份业务说明来源，不同时扩写外部手册和 Python 内置常量中的同一套操作步骤。不直接扫描或发布 `docs/projects/`、`docs/standards/`、工程手册和运维记录；现有材料经核对后可以用于编写指南。

目录先人工维护，沿用明确文件清单。给模型的信息只需文档 ID、标题和适用问题；物理路径由后端清单解析。无需自动抽取摘要、生成编目流水线或另建文档管理系统。

## 4. 模型选文档，工具读取最新正文

当前流程：

```text
用户提出平台使用问题
→ 现有助手获得简短的指南目录
→ 模型选择相关文档 ID
→ 工具读取当前正文
→ 模型依据正文说明前端操作，并引用证据
```

- 由现有助手在工具调用时判断意图，不新增分类 Agent，也不单独增加一次模型分类调用。
- 简短目录作为助手可见的背景信息，不强制每次先调用目录工具再调用阅读工具。
- 同时涉及两个功能时，可以读取两篇；无法判断时先读平台概览或向用户澄清。
- 后端按获准文档 ID 读取当前文件，不接受模型指定任意宿主路径。
- 不建设中文分词、2-Gram、Jaccard、相关性打分或向量检索。当前范围是几篇用户指南，不建立通用搜索系统。
- 阅读复用 `search_documents(document_id="", query="", line=1)` 与原 API；`query/line` 仅保留调用兼容。Runtime 每轮模型调用时沿 `authorize` 获取目录，临时追加到本次系统消息，不写入共享提示或历史。
- 目录最多 32 篇，按 ID 从正文开头读取，最多 300 行或 16,000 字符，超限明确 `truncated`。目录缺失会说明不可用，普通聊天仍可继续；现有源码窗口保持 80 行/8,000 字符。
- 返回继续保留来源、内容哈希、证据编号和适用的行号；既有路径白名单、防路径穿越和软链接逃逸约束保留。

回答当前平台的具体入口、按钮和操作步骤前，助手应重新读取相关指南。旧对话中的操作说明只作为背景，以本次读取的内容为准。普通聊天、创意交流及不依赖平台操作细节的问题无需读文档。

资料不存在、读取失败或内容未覆盖问题时，明确说明情况；不得用公开搜索结果替代本平台的实际按钮与流程。

## 5. 文档只维护当前内容

用户已确认：文档只向前维护，Agent 直接读取最新内容，不建设旧文档快照、历史版本恢复或引用版本仓库。

当前每次阅读工具调用取当前正文，普通用户指南的内容更新不再作为拒绝访问或继续使用会话的理由。`revision` 保留为来源标记，不再与历史回执比较来决定指南会话访问权限；内容哈希标识实际读到的内容。

这不要求重写旧聊天消息或恢复旧引用时的原文，也不把旧回答视为最新说明。新回答需要当前平台操作事实时重新读取。

调整仅针对这里明确发布的用户指南。登录、项目与会话归属、工具撤权等当前授权校验继续保留；数据库、源码和日志的访问规则不随本方案改变。移除普通指南版本比较也不能顺带关闭整个历史授权校验。

API 回归已覆盖修改正文和 revision 后继续访问历史、重新读取新内容；工具撤权仍拒绝。真实模型同一会话的更新前后两问均重新读取，返回新步骤和不同哈希，未建设历史文档快照。

## 6. 验证要求与范围

本轮已按以下可观察行为进行 API、Runtime、真实模型及浏览器证据展示验证。结果与未覆盖范围见 [实施证据](implementation/03-guide-and-diagnostics-optimization.md)，不把分层测试说成完整 GraphHarbor 部署验收。

| 场景 | 预期行为 |
|---|---|
| “怎样创建 Agent” | 选择相关指南，回答实际入口、步骤和结果位置 |
| “把刚才的聊天拿去测一下” | 模型判断与评测相关，不依赖问题含有固定关键词 |
| 同时涉及知识库和聊天 | 按需读取相关指南，不强制所有问题都读全部文档 |
| 更新指南后继续提问 | 读取新正文；用户指南版本变化不阻断会话访问，不沿用旧步骤 |
| 指南缺失、未覆盖或超限 | 明确说明资料不足或截断，不编造按钮与操作 |
| 普通聊天 | 可直接交流，不强制查文档 |
| 无权限、任意路径和其他资料类型 | 原有授权及路径边界仍生效，源码和数据库规则不被误改 |
| 证据展示 | 文档来源、正文及行号等信息与本次实际读取一致 |

从真实前端使用问题中选择少量代表问题验证模型选文档和回答效果，明确记录未覆盖问题；不能仅靠工具 HTTP 成功或模型声称读过资料验收。

本轮不涉及自动编译、启动 Hook、CI/CD 文档发布流水线、Docker、全文预览新界面或外部搜索基础设施。并行的排障优化按 plan.md 第12节实施，任务仍只在 tasks.md 维护。
