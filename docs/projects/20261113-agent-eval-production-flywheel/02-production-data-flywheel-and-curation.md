# 02-生产数据回流、隐私脱敏与人工审核

> 修订：2026-11-13。评审方向已确认；修订稿待实施评审。职责、路径与阶段见 [README](README.md)。

## 目标

1. 将获准的生产信号转为有来源、可复现、有人审预期的评测用例，保留从问题发现到修复验证的证据链。
2. 在数据首次离开允许边界之前完成授权与清洗；失败输出、点踩和模型推导都不能自动成为标准答案。
3. 复用 EvalFlow 审核与版本能力，只补源侧导出和评测发布缺口，避免两套审核台和两份题库真源。

## 方案设计

### 1. 现有能力与权威归属

现有 `EvalFlow: eval_platform/curate.py` 已实现 candidates()/publish_reviewed()，要求审核状态与 review_note，拒绝覆盖已发布目录；`eval_platform/dataset_registry.py` 已管理原生草稿、冻结快照及新版本。原生审核源码位于 `EvalFlow: mlflow/genai/review_queues/__init__.py`，页面位于 `web/src/experiment-tracking/pages/experiment-review-queue/`。

这些能力尚不能证明「生产授权导出与审核闭环已完成」：
- 当前 collect 主要处理既有评测报告；线上来源、资料权限和隐私处理需补。
- CLI 中的审核字符串不是生产身份验证；产品审核者须来自认证上下文并校验其角色。
- 原生队列的完成状态不自动等于 fixture、预期和发布审批全部完成；需要扩展校验。
- 现有 curate JSONL 导出保留作离线交换/旧版本能力。产品发布复用原生 Dataset 与冻结快照，不能再由 Agent API 维护可双向编辑的 JSONL 仓库。

| 事实 | 权威系统 | 另一侧只保存 |
| --- | --- | --- |
| 源反馈/事件、数据可访问性、外发授权、删除/撤销 | Agent 平台 | 不敏感引用、授权版本与有效期 |
| 评测标注、fixture 验证、预期审核、题库发布 | EvalFlow | 候选/版本 ID、hash 与发布回执 |
| 原始生产资料 | 现有受控存储 | 默认不复制；确需复制须另有数据范围与保留政策 |

优先在 EvalFlow 原生审核中增加必要的脱敏副本、fixture 和预期字段。Agent Web 保留反馈、源资料授权和必要跳转；只有验证原生 UI 缺少不可替代业务能力，才新增最小 Vue 入口，仍不复制题库状态机。

### 2. 有界回流流水线

1. **候选捕获**：消费专题 01 的源事件；记录事件、分类线索与证据完整性。先按项目内稳定指纹去重，保留发生次数及所有来源；语义聚类仅用于分组，不能自动删除不同预期的案例。
2. **源侧授权与清洗**：核实源对象 ACL、数据类别、目的、允许的接收方/模型和有效期；不满足条件转受限待处理，不向外部 LLM 发送。
3. **受控准备**：只将获准的最小清洗副本传入 EvalFlow；按政策选择是否调用 LLM 提炼场景。保留转换版本、语义变化和缺失上下文说明。
4. **评测审核**：人工确认问题真实含义、正确预期、适用指标、初始状态与资源映射。允许结论为误报、预期拒绝、产品缺陷或无法复现，不能强迫全部变成 Badcase。
5. **草稿与冻结**：用当前已支持契约导入草稿，经 fixture/preflight/审核检查后冻结，记录 dataset ID/version/hash；发布与审核分别记状态。
6. **主动验证**：在获准的独立评测资源中复现。可重建旧环境时记录原配置失败与修复后通过；无法重建时仅声明「根据已审核场景构建的回归」，不声称精确重放生产现场。

完整链路关联：source_event → export_package → candidate → review_revision → dataset/version/case → evaluation/attempt → Run/Trace。历史重评分可以校准裁判，不证明新 Agent 已修复。

### 3. 外发前隐私与授权

Runtime 既有 `Agent: apps/runtime-service/src/runtime_service/runtime/pii.py` 面向模型请求副本，不能据此假定全部 Trace、文件和日志都已脱敏。先核对调用位置及策略覆盖，避免跨仓 import Runtime 作为评测基础库。

数据边界按以下顺序执行：
- 源域本地检查 Prompt、工具输入/输出、检索片段、附件/文件名、metadata 和异常。秘密默认拒绝导出；规则覆盖手机号、邮箱、证件、Token/Key 等已支持类别，并测试绕过形态。
- 正则命中/未命中不等于安全判定。姓名、合同、商业信息或无法判定类别的资料，需要源域人工处理或获准的内部处理方案；无批准则停留源域。
- 外部模型仅处理导出政策允许的字段，明确服务提供方、目的、地域/保留限制及可发送范围；先批准后发送，不能用「LLM 会脱敏」替代授权。
- 替换值在同一用例中保持一致，保留业务关系；原值映射不进入题库、日志、Git 或外部模型。原文/脱敏 Diff 仅向获准源域审核者展示，EvalFlow 默认只见清洗副本。
- 将生产 Trace 本身的上报前清洗纳入核对；清洗异常时拒绝该内容外发。新增监控故障不停止主业务，原执行链已批准的隐私策略保持不变。
- 模型提炼读取的 Trace/工具文本均是不可信数据；不能执行其中指令、调用任意 URL 或生成可自动执行的代码。输出按契约校验，再人审。

导出授权记录最少包括源 tenant/project、审批主体、数据范围、目的、目标实验/存储、允许模型、策略版本、有效期及撤销状态。导出时及发布前重新校验权限；源资料可见不自动意味着可作为共享评测资料。

### 4. 复现材料与 fixture

取消「小于 2MB 就可一键复制原文件」和「截取前 200 行自动复原」规则。体积限制是容量保护，不能作为隐私准入条件。

**证据时点：**
- 优先引用已有不可变上传对象或获准的输入快照，并记录采集时间、原对象版本及 SHA256。
- 审核时读取的 Workspace 文件仅能标为「审核时状态」；如果已被执行修改，不可标为运行前输入。
- 没有保留输入状态时，人工构建最小合成复现，并说明重建内容；不为方便默认全量快照所有生产 Workspace。
- 文件之外的知识语料/索引、工具连接、业务时间、模型/技能/审批配置都要标明已冻结、已替换或不可重建。

**存储与装配：**
- 生产派生材料进入带 ACL、有效期和审计的受控 artifact 存储；优先复用实际可用的存储，不预设新对象存储产品。
- 题库保存 artifact 引用、哈希、大小、类型及授权来源；只有经过审核的合成/可公开 fixture 才可进入 Git。
- 保留 2 MiB 为拟定单文件初始容量上限，Task 2.0 同时冻结总量、文件数和类型限制；超限转人工精简或受控引用，不自动截行当成等价样本。
- 通过正式文件 API 读取及注入，禁止任意宿主路径、路径穿越、符号链接越界、压缩包逃逸和任意 URL 下载。
- 哈希确认字节完整性，不证明语义正确。输入材料、产物预期和保护文件分别定义，保护文件只用合成内容，禁止真实秘密进入对抗题。

### 5. 状态、幂等与发布确认

源侧导出与评测侧审核分开管理，避免共享一张多方写入的状态表：

| 对象 | 拟定状态及规则 |
| --- | --- |
| 源导出 | pending_authorization → ready → exported；可 revoked/expired/failed。只有已记录接收回执才为 exported；失败保留同一 export_id 重试 |
| 评测候选 | pending_review → approved / rejected / needs_material；审核锁/版本防并发覆盖，审批者身份来自认证系统 |
| 发布操作 | pending → published / failed；审核完成不自动改 published；记录 request_id、输入 hash、返回 dataset/version/hash 与错误 |
| 原生审核队列 | 保留其原生状态；扩展将上述业务校验映射到原生界面，不篡改上游枚举或再造原生答题存储 |

发布以「候选审核版本 + 目标集合 + 内容哈希」绑定请求幂等键。同一键不同内容拒绝；远端结果未知先查原键/已有版本，确认无发布事实后才重试。发布成功必须返回冻结版本和一致哈希；未收到可信回执不能将候选标为已入库。

复用 DatasetRegistry 的导入、publish()、frozen() 与原生记录完整性校验；补充跨系统回执及补偿，而非依赖分布式事务。部分失败可只补投影/标签，不能再次执行 Agent 或重建已冻结版本。前端须展示失败原因和「结果确认中」，不能只显示成功 Toast。

### 6. 题库生命周期与数据删除

默认路径是：获准候选 → 开发草稿 → 人审发布 → 修复验证 → 固定回归版本。开发集、固定回归、独立盲测用途以专题 03 为准；已用于调试的题及其改写后代不再宣称未见。

发布包分为完整 Case、fixture 清单、来源/授权/审核记录；不要把这些外围元数据硬塞进当前 v1 Case。可执行 v1 示例只维护在[专题 03](03-standard-benchmark-schema-and-synthesis.md)，v2 支持完成前禁止产生标为 v2 的可执行发布版本。

Task 2.0 为原始来源、清洗副本、草稿、冻结数据集及历史证据分别冻结保留期、访问范围和删除责任。与现有会话/Workspace 生命周期联动，不因评测留存偷偷延长原资料保存：
- 源资料过期或撤权后，禁止继续抓取/导出；受控副本按授权与保留政策删除或隔离。
- 删除必要资料时，已发布版本标记 withdrawn/不可新运行，保留允许保留的审计摘要；不静默修改旧版本内容或伪造相同 hash。
- 历史 Run 只在允许范围内留证据；必要删除采用明确的缺失/撤销记录，报告可复现性下降。
- 原始资料及 reviewer/tenant 关联信息不得随共享题库无条件公开。

### 7. 界面与操作体验

复用 EvalFlow 原生队列的列表、审核人及标注交互，补三块内容：清洗后场景、fixture/缺失依赖、正确预期与适用指标。提供来源证据受权跳转、拒绝/补材料、预检和发布回执。

原始敏感 Diff 保留源域；跳转时再次鉴权。先验证原生认证与项目映射，不能把默认无认证 reviewer 当作已批准生产审核人。若必须增加 Agent Web 入口，遵循 Vue 模块与页面规范，仅暴露源侧授权动作和必要状态投影。
