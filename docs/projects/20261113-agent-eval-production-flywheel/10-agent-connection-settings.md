## 用户怎样使用

用户打开同一个EvalFlow入口，在连接配置中填写Agent平台API地址，保存为“本机开发”或“服务器”。进入对应连接并用该平台账号登录，再使用原有出题、编辑、发布和运行流程。地址由EvalFlow后端访问，不由浏览器直连；页面始终显示当前连接名称和地址。

| 连接示例 | EvalFlow后端访问的地址 | 实际指向 |
|---|---|---|
| 本机开发 | `http://127.0.0.1:38375` | sshmy1上的回环端口，通过既有SSH反向隧道访问Mac的Agent API2142 |
| 服务器 | `http://127.0.0.1:2142` | 与EvalFlow同机的服务器Agent API；异机部署使用实际可达且受信的HTTP(S) origin |

两条连接均已在当前环境保存并验证，不是所有环境的固定端口。输入的是Agent平台API根地址，不是Runtime8123、EvalFlow9128或浏览器聊天页地址。隧道只负责网络可达，不共享代码、数据库或虚拟环境；复用既有38375转发，不重复占用端口。

从Agent的两个转换入口提交会话后，通知携带受信连接标识，打开EvalFlow时自动进入资料所属连接。直接进入EvalFlow时可以选择已保存连接。普通成员沿用原权限交付资料；资料负责人确认用途后再出题，发布与运行仍分开确认。

## 实施前的代码基线

- `eval_platform/config.py::EvalConfig`只保存一套platform_url、project_id、agent_id、model_id与执行账号；`environment_id`参与目标环境配置，不能未经核对直接当作来源平台的可信身份。
- `eval_platform/workbench_access.py::platform_call`通过全局EVALFLOW_SOURCE_URL/TOKEN回查来源和权限；authoring_api的登录、命令签发及运行同样绑定当前单套配置。
- `web/src/evaluation-tasks/AuthoringPage.tsx`已有平台登录和现有工作台；`authoringApi.ts`、流式请求、结果/诊断请求目前没有平台连接维度。
- 当前network.service_url校验HTTP(S) origin的语法，**不构成任意前端输入地址的可信白名单**。不能仅增加文本框，就把已保存的账号、平台令牌或source token发往用户任意指定的URL。
- 当前工作项以UUID保存，权限主要按project_id和用户身份判断；两套数据库即使使用相同UUID，也不能据此视为同一平台。连接标识必须参与请求、权限、资料及幂等隔离。

以上为实施前基线。09解决两服务不依赖共享磁盘、可以跨机部署；本专题新增同一EvalFlow的连接配置与路由。实现与实测范围以下方任务和证据为准，09结果不替代新增双环境验收。

## 已批准的最小范围

### 1. 地址在前端填写，连接资料在服务端保存

复用现有页面与表单组件，增加“Agent连接”的名称、API地址、保存/验证和选择操作；只有EvalFlow自身的已认证管理员能新增或修改，平台普通成员只能使用已获准连接。复用现有原生身份解析与管理员检查，不新增业务角色体系；不能因为某个Agent平台授予用户管理员身份，就让其取得其他连接的配置权。

地址先通过服务端准确origin允许列表和格式校验，再执行登录或探测。首批允许列表只登记上述两个明确地址；其他地址须按环境管理流程明确登记，不能因前端填写而自动信任。拒绝带账号密码、路径、query或fragment的地址；禁止跟随重定向，不使用环境代理。未允许的目标不能收到凭据，也不能触发网络探测。

每条连接关联自己的项目、Agent、模型、来源认证及执行配置，复用EvalConfig字段。平台用户登录到所选连接，不能假定两平台同名账号或UUID等价。服务端私有凭据按连接保存，不向浏览器回传，不写localStorage、URL或公开日志。保存后的连接标识、origin和项目固定；换平台必须新增连接，不能把旧连接凭据自动发送到新origin。名称、执行目标及凭据可经重新验证更新。

### 2. 同一个地址贯穿登录、来源与评测执行

首次范围内，一个连接中的平台登录、命令核验、成员/来源回查和执行API指向同一套Agent。复用原Bearer、正文绑定签名、成员/项目权限与用途授权；不另建鉴权协议。切换连接会切换对应身份上下文，不能复用另一连接的登录态、缓存或旧请求结果。原生页面和SSO的影子账号映射也须检查连接范围，不能按同名账号合并权限或提升EvalFlow管理员权限。

Agent到EvalFlow的交付携带服务端配置的连接标识，并与受信来源、签名及项目绑定；query或请求头只能选择连接，不能成为授权依据。通知自动选择连接，保留原工作项跳转和请求恢复。

### 3. 后台任务固定连接，已有资产继续保留

工作项、来源授权、发布版本、任务和执行证据记录所属连接；用户/项目权限、幂等键及原请求恢复均包含连接范围。历史默认配置中的现有记录归入当前本机开发连接，保留ID、题库、版本、Task和Trace，不删除或复制业务资产。

启动时冻结连接及目标配置。之后页面切换到另一连接，不改变已提交任务的执行、审批、停止、补收或重评地址；重启后仍恢复原绑定。本轮不提供连接删除或更换origin/项目的操作，保留已有资产和任务绑定。所有连接共用原任务并发限制与出题线程池，不增加调度器或常驻进程。

题库继续作为独立资产，来源授权到期不使题库失效；新的取源与执行各自校验当前权限。连接离线不删除题库或转去另一连接执行；需要实时身份确认的操作明确报告无法确认。跨环境迁移或共用同一题库执行不作为本轮默认能力，后续如需复用须明确目标和权限。

### 4. 沿用 SSH，保持部署边界

Mac开发仍运行自己的Agent API/Runtime，既有反向隧道让EvalFlow可访问本机API。服务器连接直接访问服务器Agent，无需借道Mac。不新增公网回调端口、不开放本机API到公网，不共享两边数据库；本机或隧道离线时明确提示本机连接不可用。

EvalFlow后端按Remote-First在sshmy1修改验证；前端在Mac构建，禁止服务器重度打包。当前服务器Agent有3个已跟踪修改及未跟踪部署文件，升级前须核对保存，不直接覆盖；本专题规划不授权生产升级或改写这些文件。
