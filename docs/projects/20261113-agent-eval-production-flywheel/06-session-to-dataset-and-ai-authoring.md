## 你最终会怎样使用

**访问恢复（2026-11-15）：** 用户关闭旧的本地EvalFlow标签页后，browser-skill已在原127地址重新登录、读取原题库及两条运行记录，普通刷新通过。此次访问阻塞已解除，可以继续人工验收；底层浏览器原因未确定，不宣称永久修复。原16项的功能验证记录不变，详见[访问排查](implementation/17-local-browser-access.md)。

你和 Agent 完成了一段对话，其中上传了销售数据，补充了退款规则，又批准它生成报告。你希望留下的不是一段聊天截图，而是一个以后能重复测试的案例：**给它哪些资料、怎样提问、应遵守哪些规则、最终应该得到什么结果。**

本专题把这件事做成一条连续的流程：

1. 在 Agent 平台选取当前 Session 或一批会话，点 **“转为评测集”**。确认资料用途；Agent 平台只提供获准的上下文、环境和来源记录，不生成候选用例。
2. 打开 EvalFlow 接收页，查看自动整理首版的进度。EvalFlow 的评测 Agent 生成题目、所需环境、建议答案和评分方法，并说明缺少什么；不要求重新讲一遍业务。普通成员未获AI用途授权时，只交付资料，由项目管理者继续确认。也可以在 EvalFlow 直接新建用例。
3. 在 EvalFlow 用自然语言修改，例如“退款按发生月份算，再加一个拒绝写文件的分支”。AI 展示具体改动，保留已经确认的业务规则；确认、增删改查、扩题和指标管理都在这里完成。
4. 满意后 **“发布版本”**。它进入题库，但不会自动启动 Agent。
5. 需要验证时在 EvalFlow 点 **“运行评测”**，选择 Agent 配置和题库版本。结果默认进入本次执行的完整 Session，可展开各轮 Trace，另看评分过程和文件证据；原题、来源和历史运行均能找回。

本专题流程已在本地实现。当前入口是 Agent 聊天顶栏的“转为评测集”和 EvalFlow 的“评测集工作台”；实际按钮与可复制输入见[人工验收手册](manual-acceptance.md)。你的亲自验收仍待进行。

### 三个词说清楚

| 页面中的词 | 对使用者意味着什么 |
|---|---|
| Session（会话） | 从开始到所选截止点的用户消息、Agent 回答、工具调用、审批及相关文件/环境。不是一条消息，也不是浏览器录屏 |
| 评测集草稿 | AI 与你共同编辑的一组题，可修改、保存、继续讨论，不运行被测 Agent |
| 题库中的版本 | 已发布、内容固定的评测集，如“经营简报 v1”。后续修改形成新草稿，发布为 v2，不覆盖 v1 |

“评测集”和“题库”不做成两个需要互相导入的系统：前者是一组题，后者是管理和查找这些已发布题目的入口。数据和版本仍由 EvalFlow/MLflow 保存。

## 方案设计

### 入口一：从线上列表向评测平台提供资料

使用者在 Agent 平台所属项目的会话列表按 Agent、时间、反馈或执行状态筛选，选中一条或多条会话，点“转为评测集”。不要求先有差评，也可以把一段成功操作作为评测资料。Agent 平台只显示资料提交状态和“打开评测平台”入口，不生成题目、不维护可编辑题库。

系统先显示本次选择的会话数、可使用的资料范围及缺失情况。已有有效授权覆盖时直接继续；缺少资料用途授权时，只让有权管理该项目的人确认一次批次范围。批量操作允许部分成功，但每条失败都要说明原因；不把没有权限的会话偷偷跳过后显示“全部成功”。

资料成功交给 EvalFlow 后，由 EvalFlow 的评测 Agent 默认从每个会话提炼一个完整场景，可以建议拆成多个独立问题，但需保留关联关系和拆分理由。重复内容合并为建议，不删除来源。用户在 EvalFlow 可以说：

> 这些会话里，重点保留退款计算和审批写文件的问题。重复问法合并，成功案例保留两条对照。先给我草稿，不要运行。

输出包括题目、原始依据、应有结果、所需环境、建议指标和未解决的问题。每条题都能回到获准的源会话；来源已撤权时不再显示正文。

### 入口二：把刚做好的完整 Session 和环境交给评测平台

Agent 会话页的“转为评测集”默认选取到当前截止点的完整会话，不让用户重复粘贴聊天。后台固定截止点、消息/运行 ID 和内容摘要；如果消息被上下文压缩，读取有权限的原始历史，不能把当前摘要称为完整原文。找不到原始历史时如实显示缺失。用例生成在 EvalFlow 接收资料后完成；提交资料不等于发布题库或启动评测。

完整取证和最少外发是两件事：原始资料只在授权范围内保留；发送给整理模型的内容按用途筛选和脱敏。相关环境按下面的表处理：

| 资料 | 怎样留存、怎样用于新测试 |
|---|---|
| 用户消息、助手回答、工具调用及返回 | 保存有序记录和原 ID。用户轮次可成为新测试输入；原助手回答和工具返回是历史证据，不冒充新 Agent 的结果 |
| 上传附件、工作区文件 | 区分运行前文件、每轮补充文件和运行后产物；记录安全路径、内容摘要及来源时点。新执行只恢复必要的运行前资料 |
| Agent、模型、提示词与工具配置 | 留存不含密钥的版本/摘要和受管配置引用；比较“原配置”和“待测配置”，实际执行后再核对 |
| 知识库、MCP、外部服务 | 记录资源范围和可用版本。能冻结则冻结；只能读当前状态则标明漂移风险。已保存的工具返回只能用于明确标注的模拟模式 |
| 记忆与会话状态 | 只提取完成该题必需、已获准的初始事实；不复制整个个人记忆库，不把旧会话结束状态当开始状态 |
| 人工批准、拒绝和补充说明 | 作为历史事实和测试分支。新运行按测试策略重新等待人操作，或使用提前批准的隔离测试决策；旧批准不授权新的生产写入 |

历史 Session 没有文件初态时，系统不能凭结束文件“还原”出一个假初态。页面给出三种明确选择：

- **评历史回答：** 使用已有回答和证据评分，不重新执行 Agent。
- **补资料后回归：** 用户提供或确认初始文件，显示“人工重建环境”，再独立运行。
- **生成模拟场景：** AI 给出替代数据，经确认后作为合成分支；来源和结果都标明模拟。

对以后新产生的会话，在获准采集范围内增加运行前及每轮新增附件的快照能力；只采集列入范围的资料，不全盘复制工作区。旧记录不会因新增采集代码自动具备初态。

### 入口三：在 EvalFlow 直接新建用例

不强制每道题都来自线上 Session。用户可以在 EvalFlow 手工新建用例、上传获准材料，或直接告诉评测 Agent 想测什么。例如：“新建两轮算术题，先算31加24，再把24改成14；答案分别55和45，不允许调用工具。”

这些用例标为“直接创建”，不伪造来源 Session。AI 可先给出完整草稿，用户也可自行填写；随后进入同一套编辑、确认、版本发布和运行流程。需要文件或工具环境的题必须补齐环境声明，不能因没有线上来源而跳过运行前检查。上传材料仍按平台账号、项目权限和获准用途管理。

### 在 EvalFlow 的同一个编辑页面里完成 AI 讨论

EvalFlow 页面顶部一直可见：评测集名称、草稿/版本、来源、环境是否齐备、最近一次运行。主体显示题目列表与选中题详情，旁边是评测 Agent 对话；来源、环境和原始证据可以展开查看。用例确认、增删改查、批量操作、指标和版本管理都在 EvalFlow，用户无需回到 Agent 平台编辑题目。

用户可以直接说：

> 只改第二题。净收入按销售减退款，不扣成本；增加缺少退款文件时先询问的情况。再加一个指标，检查报告是否解释计算依据。

AI 需要给出可检查的结果，而不是一句“已优化”：

- 第二题哪一段输入和预期改变了；哪些已确认规则保留。
- 新增“缺退款文件”题，预期是先询问，不能编造数字。
- 新指标“计算依据清楚”：检查报告是否说明口径、数据来源和计算过程；使用何种评分方法、看哪些证据、怎样算达标。

AI 建议作为草稿修订展示，用户可一键采纳、仅采纳部分题或继续提意见；普通改写不要求逐题审核。只有业务规则冲突、关键资料缺失或权限变化时集中展示“需要你决定”。发布时确认本次版本的内容和仍未解决的问题，不把每一步都变成审批。

原始证据不可被 AI 改写。已确认业务口径单独结构化保存，后续生成、扩题、评分和结果解释都读取同一版本。并发修订检查草稿版本，超时重试先对账，避免旧建议覆盖新确认。

### 保存、发布和运行各做一件事

| 操作 | 用户得到什么 | 不应发生什么 |
|---|---|---|
| 保存草稿 | 可继续编辑的内容和讨论历史；自动保存状态可见 | 不固定题库版本、不执行被测 Agent |
| 发布版本 | 固定的题目、环境声明、业务规则和指标配置，显示 v1/v2 | 不自动创建评测运行 |
| 运行评测 | 所选版本及 Agent 配置对应的新任务，可查看进度和结果 | 不使用未发布的临时修改、不复用旧助手回答伪造执行 |
| 用新标准重评 | 用新评分标准检查同一份旧运行证据 | 不声称 Agent 又执行了一次 |

发布成功页可以提供“现在运行”的下一步按钮，但必须由用户明确点击。刷新、返回、服务重启后，从“我的评测集”仍能找到草稿、全部发布版本和运行历史。EvalFlow 原生页能看到相同的 dataset/version/task/run 关联，不要求用户记 UUID。

### 多轮与人工审核场景怎样运行

**固定轮次回归**用于比较改动前后的行为：从独立 Thread 和隔离工作区开始，依次发送固定用户输入，Agent 每轮重新作答。用户输入依赖上一轮结果时设置明确前置条件；条件不满足就记录偏离或进入预设分支，不能强行发送“同意上面的计划”制造误导。

**AI 模拟用户**用于探索复杂对话：按既定业务目标和用户设定，AI 根据新 Agent 的回答追问、纠正或补充。模拟器只知道正常用户应掌握的信息，不读取隐藏答案和裁判评分。轮数、时间与调用预算受任务配置限制；模拟器的“目标达到”不等于测试通过。保存实际全部轮次、模型配置及停止原因，不承诺再次生成完全相同的对话。

两种模式在界面和结果中分开标注。动态发现的好案例可整理并固定为下一版回归题；动态运行的分数不与固定轮次分数直接混为一个改善结论。

涉及写文件、审批和工具限制时，优先检查真实调用、权限回执、文件变化和逐轮输出；需要评价报告解释是否充分时再用模型。单纯文字“已保存”不能证明写入，文字“没有保存成功”也不能因包含“保存成功”就判违规。证据不足显示“无法判断”，不自动通过，也不冒充 Agent 质量失败。

## 跑完评测后，怎样看到全过程并定位问题

用户已确认：默认查看本次执行的总 Session；复用已有 Session/Trace 组件；裁判过程必须透明；部分 Trace 缺失时保留已收到的证据。这些是本专题正式验收要求，不能只交付分数和一句原因。

### 先进入完整 Session，再展开每一轮

每道题的结果提供“查看本次执行 Session”。一次真实执行对应自己的 Session，同一道题重跑会产生新的执行 Session；一个评测批次有多道题，就分别展示多个 Session，不拼成一段对话。

页面明确区分：

| 名称 | 用户看到什么 |
|---|---|
| 来源 Session | 用来整理用例的原始线上会话；直接新建的题没有此项 |
| 评测执行 Session | 本次 Agent 重新作答的全部轮次及运行记录；结果默认打开这里 |
| 评测助手对话 | 用户在 EvalFlow 修改题目和讨论结果的记录，独立于被测 Agent |
| 评分过程 | 裁判/规则对本次执行的判断记录；关联指标和证据，不混入被测 Agent 对话 |

历史证据重评继续关联原执行 Session，并新增评分记录，不伪造新 Agent 执行。结果入口传递执行 Session、所属实验和本次 case/attempt 关联，不能只取最后一条 Trace；链接不是权限凭据，打开时继续校验授权。

### 两层查看，不再造一套 Trace 系统

| 查看层次 | 页面应展示的内容 |
|---|---|
| Session 总览 | 用户轮次、Agent 回答、每轮状态、审批等待/恢复及证据缺失提示 |
| 展开某轮 Trace | 调用树/执行时间轴、模型调用、工具调用、顺序、耗时与错误 |
| 点击执行节点 | 获准采集的请求/响应、工具参数与返回、检索证据；截断、脱敏和未采集分别说明 |
| 环境与文件 | 初态、运行后产物和可获得的差异；缺初态不宣称能够比较 |
| 点击失败指标 | 跳到对应轮次、Trace/Span、回答片段或文件断言，而不只显示一串编号 |

审批中断和恢复可能产生多条 Trace，应按同一业务轮次组织，记录 `turn_index` 与所有 `run_id/trace_id` 的对应关系；不能将每个恢复 Run 当作新一轮用户输入。没有权限或未采集的内容明确说明，不为了“全链路”补造证据。

现有可复用代码包括 `TracesV4SessionDrawerContent.tsx` 的会话排序/查看、`useTracesV4DrawerSessionUrlState.ts` 的 Session↔Trace 切换，以及 `model-trace-explorer/` 的节点时间轴。新入口已接通，并已用S01三轮四次运行及B多轮审批真实验证；上方业务轮次与下方原生运行记录分别标明。

### 每个指标都能打开评分过程

“查看评分过程”展示本次实际采用的指标名称/版本、标准、阈值、裁判模型/参数、评分提示词和送入裁判的证据；每次模型调用的响应、结构化判断、理由、错误、重试、耗时及可取得的用量均保留。多次裁判调用不能只留下最后一句理由。请求/响应受资料授权和脱敏约束，不记录密钥；若内容被截断或未保留，必须明确标注，不能声称完整可复核。

页面还要解释“这些判断怎样得到分数，以及为什么达标或不达标”，并把所引证据定位到具体轮次/节点/文件。代码规则指标展示实际值、期望值、规则版本和比较结果，不伪装成模型意见。透明指可审计的输入、响应与计算过程，不承诺暴露模型不可观测的内部思考。

评分记录按本次 task/case/attempt/metric 关联；同一 Session 重评会有新的评分记录，旧记录不覆盖。评测 Agent 分析失败时读取同一份获准证据，将观察到的事实、推测的原因和建议验证步骤分开，不能把模型意见直接写成确定根因。

### Trace 不齐时，已有记录仍然可看

完整性以执行器登记的运行清单为依据，比较每次运行是否应产生 Trace、已收到哪些、还缺哪些；不能只统计页面已查到的 Trace，也不能把 Trace 数等同用户轮数。列表分页或截断不能被误报为完整。

例如：“本次登记5次运行，收到4条Trace；第二轮审批恢复的记录采集超时。”页面保留这4条记录，并区分运行中、采集延迟、采集失败、已取消、未启动或访问受限；不知道原因时不擅自归因。

“重新收集记录”只补取已有运行的证据，不重新执行 Agent，不重复审批或工具副作用。当前收集器需从“等待全齐，超时返回空列表”改为保留部分结果及缺失清单；后到记录按稳定ID去重。

按指标声明判断证据是否足够：受影响的指标显示“证据不足，无法判断”，可由现有独立证据完成的检查保留结果；总体同时展示执行状态、证据完整性和质量结论，存在必要证据缺失时不能显示完整通过。审批和文件证据也要单独检查，不能以Trace齐全代替其他证据齐全。取消在运行启动前发生时显示“未启动”，不虚构缺失Trace。

### “加一个指标”如何变成可执行配置

例如用户说“再检查报告有没有说明净收入的计算依据”，AI 建议：

| 配置 | 这个例子里的内容 |
|---|---|
| 指标名称/对象 | 计算依据清楚；检查最终报告及第三轮已确认的业务规则 |
| 执行方法 | GEval；若需检查跨轮规则变化则用 ConversationalGEval |
| 评分步骤 | 是否写明销售减退款；是否说明退款按发生月份；是否引用可核对的资料；是否引入未要求的成本扣除 |
| 阈值 | AI 给建议和理由，发布前显示并冻结；不把示例阈值默认为业务承诺 |
| 证据要求 | 最终报告、确认规则、允许外发的资料片段；缺任何必要证据则不评分 |
| 版本 | 保存指标 ID/版本、规则/模板摘要、裁判模型配置；旧运行仍显示当时标准 |

确定金额是否为 1500、拒绝后文件是否不存在、受保护文件摘要是否不变，使用本项目已有确定性断言，不交给语言模型猜。暂不支持的指标显示“需要新增实现”，不静默降级为通用语义评分。AI 不能生成任意 Python 在服务器执行。

新增语义指标在可控的正确/错误样例上试评，展示误判和理由后再纳入版本；未经独立校准的分数仍是辅助证据，不自动批准生产发布。历史 AI 评审授权沿用，不伪称独立人审或盲测。

### 模型调用和资料外发

复用现有受管模型适配，生成模型、模拟用户模型、裁判及可能用到的过滤/Embedding 模型均须显式配置。不能因为合成器默认值而调用未批准的第三方模型。默认走已获准文本上下文，不要求开启文档向量化。

官方隐私文档说明存在默认遥测及关闭设置；本期需在导入 SDK 之前配置关闭，并验证结果上传、缓存、日志和异常路径。禁止自动登录/推送 Confident AI；只允许批准的模型端点，不能把关闭遥测当作“没有任何网络外发”的证明。撤权和清理覆盖合成中间数据、模拟会话及评分缓存。

## 三个从头到尾的验收案例

下面保留原始验收场景，**不是逐项执行日志**。当前准确按钮和可复制步骤见[人工验收手册](manual-acceptance.md)，实际运行结果、失败与覆盖边界见本篇Final及[回放说明](acceptance-replay.md)。验证使用真实产生的合成Session，不使用生产客户资料。

### 案例 A：从线上会话列表整理并运行

1. 在隔离项目新建第一条 Agent 会话，先问“31 加 24 是多少？只回答数字”，再在同一会话追问“我把上题的 24 改成 14，现在是多少？”。另开第二条会话，用同义问法重复这两轮，作为去重来源。
2. 在 Agent 平台会话列表选择这两条，点“发送到评测平台”，确认只使用这些合成内容；此时仅形成资料交付记录，Agent 平台不生成候选题。
3. 打开 EvalFlow，对评测 Agent 说：“生成算术回归集，保留连续两轮修改数字的场景，重复问法合并；答案分别为 55 和 45，不允许调用工具。先保存草稿。”
4. 查看来源和题目，确认第二轮仍处于同一个场景、旧助手答案没有直接当标准答案。即使源回答错误，预期也由算式确定。
5. 发布“算术会话回归 v1”。预期：版本可见，运行历史为空，没有新的 Agent Run。
6. 点“运行评测”，选择现有受管 Agent 配置。预期：新独立会话两轮回答 55/45，工具调用数为零；如失败应保留实际证据，不能为验收改通过。
7. 刷新页面，从题库重新找到 v1 和本次结果；在 EvalFlow 打开同一个原生 Dataset 和 Run，数量和关联一致。
8. 点击“查看本次执行 Session”，能看到两轮及各自 Trace；来源会话另设入口，不与本次执行混淆。点某条规则能看到实际答案55/45、期望值及判断结果。

### 案例 B：完整 Session、文件、审批和业务规则修改

先在隔离工作区准备两份 UTF-8 CSV，运行前记录初态。`sales.csv`：

```csv
order_id,sale_date,amount
S1,2026-09-20,600
S2,2026-10-02,1000
S3,2026-10-15,800
```

`refunds.csv`：

```csv
refund_id,order_id,refund_date,amount
R1,S1,2026-10-05,100
R2,S2,2026-10-18,200
R3,S3,2026-11-02,50
```

在同一个 Session 依次说：

1. “读取这两个文件，算 2026 年 10 月销售和退款，先说明采用的口径，暂时不要写文件。”
2. “确认：销售按销售日期归月，退款按退款发生日期归月，净收入只等于销售减退款，不扣成本。”
3. “生成报告，写到 report.md，写入前请我审批。”通过现有审批界面批准。

正确业务结果是销售 1800、退款 300、净收入 1500。九月订单的十月退款应计入；十一月退款不计入十月。必须保存原始文件初态、三轮消息、审批事实及新文件产物。

在 Agent 平台把 Session 和环境发送到 EvalFlow，由 EvalFlow 评测 Agent 整理成草稿后，对它说：

> 保留刚才确认的口径；扩成批准写入、拒绝写入、缺退款文件三种情况。原始两份文件不能修改。增加“报告是否解释计算依据”指标。第三轮再要求增加一个“统计月份”字段，不能因此判成忘记前两轮信息。先给我草稿。

预期看见：

- 批准分支：只有批准后才能写 `report.md`；金额准确、解释口径、原文件摘要不变。
- 拒绝分支：文件不存在，正常拒绝不算故障；“没有保存成功”不应被关键词误判为已经写入。
- 缺文件分支：先询问/说明无法计算，不能把缺失退款视为零，也不能编造 1500。
- 新增字段与已确认金额并存；评分按每轮已生效规则判断，不能让后来的要求倒罚前一轮。
- 审批可预设隔离测试批准/拒绝，也可选择真人在线操作；超时和取消有明确状态，不能自动放行。

先发布 v1，不运行；再选择固定轮次模式执行三个分支。随后从同一场景选择 AI 模拟用户模式，检查生成的追问是否围绕业务目标、是否遵守轮数限制、是否保留完整新会话及证据。模拟结果单独展示。最后用自然语言改一项评分标准，确认只产生新草稿/新标准重评，不覆盖 v1。
