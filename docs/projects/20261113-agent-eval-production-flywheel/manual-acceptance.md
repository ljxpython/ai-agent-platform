## 先说清楚你在验什么

这套功能面向三类人：业务人员说明场景和正确口径；项目负责人决定哪些资料可以用于评测；开发者和测试人员运行题库、查看过程、定位问题。同一人可以在本地测试中兼任这些职责。使用现有平台账号，不需要新增flywheel-reviewer角色。

两个平台分工如下：

- **Agent平台**：你和被测Agent聊天；向评测平台提供获准的整段会话及环境；执行真实测试。
- **EvalFlow**：AI整理和修改题目，你管理题目、发布固定版本、启动评测并查看结果。

正常顺序是：**在Agent平台聊天 → 转为评测集 → AI自动整理 → 提意见改题 → 确认发布 → 运行 → 查看完整过程**。EvalFlow右侧对话框只用于改题、加指标和解释结果；业务对话仍在Agent平台。无来源直接新建是另一个可选入口。发布不会自动运行。

“合成资料”就是专为测试编写的虚构数据；“AI模拟用户”是另一个功能，指AI扮演用户，依据Agent的新回答继续追问。合成资料也可以用于固定轮次回归，不等于必须用AI模拟用户。

| 路线 | 你将验证什么 | 建议顺序 |
|---|---|---|
| 主线：Agent对话转评测集 | 四轮业务对话、自动出题、AI改题、发布运行和定位 | 先做，下方给完整输入 |
| A：直接新建 | 无源会话也能做题库；修改、发布、运行、找回 | 可选补充 |
| B：已有会话 | 当前Session和批量会话进入EvalFlow，历史评分不重跑 | 可选补充 |
| C：文件和审批 | 退款口径、AI扩题、人工批准/拒绝、真实文件证据 | 用下面两份虚构CSV |
| D：诊断和保护 | 动态模拟、裁判、补收、取消、撤权 | 最后做；只撤专用样本 |

每一步分别记“系统流程是否正确”和“Agent是否答对”。Agent答错、系统如实定位问题，不等于流程坏了；绿色表示达到当前阈值，仍要核对扣分原因。硬性违规被漏判或裁判引用错轮次，应记录为评分问题。模型输出不保证每次措辞相同。

## 主线验收：把Agent平台的一段完整对话变成评测集

这是本轮最重要的路线。“线上”在这里指Agent平台里真实发生的会话，不要求你连生产服务器。本例金额是虚构业务资料，但聊天、转换、模型出题、重新执行和评分都是真实调用。

### 主线1：在Agent平台完成四轮对话

在第0步指定项目里打开dearflow_agent，新建对话。以下四段逐条发送，每一轮都等回答结束，不要一次粘成一条。

**第1轮：让Agent先澄清口径。**

```text
我们要做11月销售和退款核对。这是一组虚构业务资料，请仅依据本会话，不联网、不调用工具、不读写文件。订单：O101在11月1日付款1200元；O102在11月2日付款800元；O103在10月28日付款500元；O104在11月3日付款300元但状态为已取消、实际未收款。退款：R1对应O101，11月5日退200元；R2对应O103，11月6日退100元。先列出你需要我确认的统计口径，不要直接算净额。
```

**第2轮：确认两种统计口径。**

```text
口径确认：按现金收付，销售按实际收款日在11月、退款按实际退款日在11月，不论原订单月份。O104未收款必须剔除。净流入=本月实收减本月退款；本月订单净额另列，只扣本月订单的退款，不能混淆。请算两种口径并解释差异。仍不调用工具，不写文件。
```

正确值：实收2000，现金退款300，净流入1700；本月订单退款200，订单净额1800，差额100来自跨月订单退款。

**第3轮：追加变化和证据边界。**

```text
追加一条：O102在11月8日又退款50元。请更新两种口径，列出对比表，并区分事实、推测和待核实事项。有人说退款是商品质量差导致的，但我们没有原因字段，不能把这个说法当结论。最终回答控制在300字内，禁止调用工具和写文件。
```

正确值：净流入1650，订单净额1750，差额仍100。不能把退款原因断言为商品质量差，也不能把订单净额称为利润。

**第4轮：确认容易混淆的规则。** 本次录像中Agent表格正确、文字有错误，因此实际发送了纠错内容。你的回答若没有同样错误，使用下面的中性确认即可，不必虚构错误。

```text
最后确认：新增50元同时计入两种口径的退款；订单净额不等于利润，没有成本不能说净赚。请给出最终简短核对结论，保留1650、1750和差额100，并将“质量差导致退款”明确标为缺乏证据。仍不用工具。
```

### 主线2：在聊天顶部点击“转为评测集”

名称填 `我的验收-11月退款核对`。保持业务会话类别，阅读并勾选资料用途确认，然后提交转换。项目管理者可同时授权这批资料由AI整理；普通成员只能交付，需项目负责人继续授权。

应打开EvalFlow的同名评测集，显示 **已带入1段Agent会话、8条消息**，随后自动整理首版。你不需要在右侧重新描述原来的业务。展开“查看原对话”能读到来源正文；原始结构、来源编号和环境说明放在详情中。没有文件的本例不需启用文件初态采集。

若模型整理失败，原资料和失败记录应保留，点击“重新整理首版题目”主动重试。网络回执丢失时使用原提交的重试入口，不反复新建同名评测集。

### 主线3：给AI修改意见，检查它实际改了什么

等首版生成，在右侧 **给AI的修改建议** 粘贴：

```text
保留原四轮题目和来源。请核对第二轮1700/1800，第三、四轮1650/1750；数字允许千分位或不带千分位，用语义指标核对，不用格式敏感的数字子串检查。增加整段对话评分，检查能吸收用户纠正、净额不能称利润、不能编造退款原因。再加一题：本月实收2000元，有退款但金额未提供，必须先询问退款金额，不能编造净流入。两题都不联网、不用工具、不写文件。正文已经自足；退款原因未知是测试边界，不是阻塞条件。最多两题，不发布、不运行。
```

点 **按意见修改题目**。应保留原四轮并新增一轮题；展开“查看实际修改：逐题对照上一稿”核对。再展开题目下的“业务规则、环境、文件、审批与评分方法”，应有整段对话评分和零工具限制，环境为“独立环境回归”。

如果AI用“净流入为”“净流入是”作禁止子串，继续指出：这些词会误伤“净流入是多少还不能确定”，应删除此禁止规则，由语义指标判断是否编造数字。这也是本次录像里实际做过的一轮评审。

### 主线4：确认发布，然后单独启动运行

两题左侧“发布这道题”均勾选。页面下方勾 **我同意这些题目在24小时内用于隔离回归与评分；发布后由我启动运行**，点 **确认并发布选中2题**。下方“已发布版本与历史运行”应出现题库v1、已发布尚未运行。

再点 **运行已发布版本**，只点一次。该按钮会真正运行被测Agent；发布本身不会运行。期间可离开，回来点左侧 **评测集**，在列表打开同名条目，找到版本和这次运行；无需记实验编号。

### 主线5：确认系统记录完整，再看回答好不好

等待“评测已完成”，展开 **同名评测集 · 验证**。应有两题：四轮核对题和一轮缺金额题。每题有自己的执行Session，不能误当作原始来源Session。

1. 四轮题应能查看4轮输入、回答和各自执行时间线；点击“查看本轮执行时间线”，查看模型节点、实际输入输出及耗时。
2. 核对第2轮1700/1800，后两轮1650/1750；没有成本不能称利润，没有原因字段不能编造退款原因。
3. 缺金额题应先追问，不能假设退款为0或编造净流入。
4. 展开每项评分，查看标准、分数、理由及“本指标裁判调用”；模型请求和返回能追溯。裁判失败或缺证据应明确显示，不能当作通过。
5. 刷新并重新打开同名评测集。题库v1和原运行仍可找到，不应因为刷新新增运行。

```text
保留A01的两轮提问、55/45逐轮精确预期及零工具限制。
另加A02：问“10减3，只输出数字，不调用工具”，精确预期7，工具调用上限0。
说明增加了什么；不修改A01，也不自动发布运行。
```

生成后展开 **查看实际修改：逐题对照上一稿**。应看到新增A02，A01规则保留。

接着手工把A02题号改为 `A02-delete-check`，点 **保存草稿**；刷新确认修改保留。再点A02下面的 **删除这道题**，保存，确认A01未删除。

若想验“部分采纳”，先再请AI生成A02；只勾A01，点 **仅采纳选中题目，全局口径保留上一稿**。这保留上一稿的全局业务规则；它与“发布选中题目”是不同操作。普通输入保存不要求手写JSON，批量JSON编辑只是高级入口。

### 第4步：发布一题，确认没有自动运行

1. 勾选发布按钮前的24小时隔离回归与评分用途确认。
2. 只勾A01上方 **发布这道题**，其他题不勾。
3. 若显示“有未保存修改”，先点 **保存草稿**。
4. 点 **发布选中 1 题**。
5. 找中间下方 **已发布版本与历史运行**。

应出现“题库v1”（若你此前发布过，以实际版本为准），状态已发布。**此时没有新增评测运行**。未选题不进入这个版本，但草稿可继续保留。

### 第5步：明确启动，再查看完整过程

在刚发布的那一行点 **运行这个版本**。不要回到普通Chat发送“开始评测”。

等结果出现，展开名称后的结果行，再查看：

- 运行方式为固定轮次回归；执行Session是新会话，不是整理题目时的AI对话。
- **业务第1轮**有55，**业务第2轮**有45；每轮能打开执行时间线。
- 工具检查通过，实际没有工具调用。
- 页面保留执行状态、规则结果和失败原因。若Agent答错，应按实际判失败。

### 第6步：离开再找回

点 **返回评测集列表**，打开另一条记录，再返回列表。在“搜索评测集”输入 `我的验收06-A`，点 **搜索**，打开原条目并刷新。

题目、已发布版本和历史运行应仍在。以后就从这个入口找题库与结果，不需要记实验编号。再次点击旧版本的“运行这个版本”会新增一次运行，不会覆盖原结果；修改草稿也不会改变旧版本。

## B：把你和Agent实际做过的Session送进来

### 第7步：准备一段真实测试对话

回Agent平台，在指定项目中新建普通对话，依次发送：

```text
请计算31加24，只输出数字，不使用工具。
```

等它回答后，再发：

```text
把刚才的24改为14，重新计算，只输出数字，不使用工具。
```

等第二轮完成。这里是被测Agent本身的真实Session，不是在EvalFlow和评测AI讨论题目。

### 第8步：交付当前会话

在聊天顶栏点 **转为评测集**。核对弹窗的会话、资料范围和缺失提示，确认资料用途后转换；自动跳转或使用“打开评测平台”进入接收记录。

在EvalFlow展开 **查看原对话**，技术来源在详情中：应看到这段对话的两次提问和两次回答，以及对应运行。交付后在源会话新增一句话，不应悄悄改变已经固定截止点的资料。

给右侧AI输入：

```text
根据收到的完整会话生成一题。核对31+24=55、31+14=45；来源回答只是证据，不自动当标准答案。
本次选择历史回答评分，使用原有对话，不重新执行Agent。保留来源和缺失说明。
```

授权、发布和运行按第2、4、5步操作。此处的“运行”是执行评分，应标明 **历史回答评分，没有重新执行Agent**；原Session运行次数不增加。

如果改为回归，选择“独立环境回归”或补齐初态后再运行。旧会话只有最终文件时，不能凭它声称完整恢复了运行前环境。

### 第9步：批量交付

另建一段相同结构的合成对话。聊天顶栏点 **筛选会话做评测**，在 **筛选会话** 界面限定当前项目/Agent、时间或反馈，选中刚创建的两段，点 **使用选中的 2 个会话**，继续发送到EvalFlow。

应显示两段来源，各自的消息顺序和运行记录可区分；无权或失败的来源应有具体说明，不能把部分成功说成全部成功。批量收资料仍不等于发布或启动Agent。

## C：文件、业务口径与人工审批

### 第10步：直接新建文件案例，附上两份虚构资料

EvalFlow新建，名称填 `我的验收06-C-退款报告`。展开 **也可以粘贴文本资料**，依次填写文件名和正文，每份都点 **加入这份资料**。

文件名 `sales.csv`：

```csv
order_id,sale_date,amount
S1,2026-09-20,600
S2,2026-10-02,1000
S3,2026-10-15,800
```

文件名 `refunds.csv`：

```csv
refund_id,order_id,refund_date,amount
R1,S1,2026-10-05,100
R2,S2,2026-10-18,200
R3,S3,2026-11-02,50
```

页面应同时列出两个文件名。这里生成真实的测试输入文件，粘贴不是把文件内容只写在聊天里。也可通过“附加资料”选择文本文件；此前已验证上传API，自动浏览器的原生文件选择器没有录通，本文以粘贴路径完成验收。

“希望验证什么”填：

```text
用所附两份合成CSV测试2026年10月退款报告。销售按sale_date归月，退款按refund_date发生月份归月。净收入=销售减退款，不扣成本；不得修改两份原始CSV。
请先用calculate独立核算，正确销售1800、退款300、净收入1500。
生成C01三轮固定回归：第一轮读取文件并说明口径，不写文件；第二轮用户确认口径，仍不写文件；第三轮请求用write_file写/workspace/work/reports/report.md，必须等待我在线批准。
报告严格三行：销售：1800、退款：300、净收入：1500，各占一行，用中文冒号，无标题、空行、千分位或末尾换行。
只授权write_file对上述准确路径的测试写入。文件检查为前三轮不存在、不存在、精确三行内容；原始CSV保持不变。
输入通过{{sales.csv}}和{{refunds.csv}}引用附件。不要把核算结果写入被测Agent提问。先给草稿，不发布运行。
```

建立草稿、授权AI并生成后，核对金额、三轮及审批设置。展开 **业务规则、环境、文件、审批与评分方法**，第三轮 **工具审批** 应为 **运行中等我决定**，写入范围仅指定文件。

### 第11步：用一句话扩充场景并添加指标

右侧输入：

```text
保留C01与确认口径。使用expand增加两个有区别的分支：C02第二轮请求同一路径写报告，但预设拒绝，报告始终不存在；C03仅提供sales.csv，缺少退款资料时必须先询问补充，不编造金额，不写报告。
C03允许用request_information表单提问，只检查真实表单中的问题和字段；不要求模拟器填写表单。
添加“计算口径说明清楚”的语义指标，明确读取该题的回答/工具证据、评分标准和阈值；文件与权限继续用代码规则，不用关键词“保存成功”判断实际写入。
只生成草稿，说明变化，不自动发布。
```

应看到三个不同分支。检查C03没有偷偷附上退款文件；C02拒绝后文件不存在；语义指标有具体评分依据。若AI生成的配置不满足，继续指出缺项，保存其修订，不为了得到绿色结果降低规则。

### 第12步：发布并在线批准

只选择C01发布，再点该版本 **运行这个版本**。当状态变成 **等待工具审批**，在 **已发布版本与历史运行** 中展开这一次结果，找到：

**需要你决定：C01 第3轮工具请求**。

核对工具为write_file、路径为 `/workspace/work/reports/report.md`、正文金额正确，再点 **批准这次工具调用**。审批按钮在这条运行里面，不在题目编辑区或普通Chat。

应继续原第三轮；首次执行和审批恢复记录归在同一个业务轮。最终展开 **文件证据**，确认三行内容；原文件保护检查通过。若Agent额外请求execute/present_artifacts等未授权工具，应该停止并保留已完成动作，不能自动放行。只看到“我已写完”不算文件验收通过。

然后选C02、C03发布另一版本并运行：拒绝分支报告不存在；缺文件分支先发起补料请求且不伪造净收入。表单中断是C03预期时可以通过相应检查，不等于整段任务已经生成报告。

若要核对源文件初态采集：在Agent新会话尚未上传文件前，打开“转为评测集”的环境采集详情，启用 **为后续运行保留上传文本初态（24小时）**，再上传这两份CSV并完成对话，交付后检查初态只有CSV，旧报告不进入新执行环境。过去没有采集初态的会话不会因此自动补全。

## D：看懂评分、试AI模拟，再检查保护措施

### 第13步：核对完整Session和裁判

打开C01结果：先看上方 **业务第1/2/3轮**，再点 **查看本轮执行时间线** 或 **查看本轮恢复时间线**。应可查看模型和工具节点、参数、返回、耗时与错误。下方原生查看器按Run记录展示，审批恢复可能多一条；这不代表多了一次用户提问。

展开失败或通过的指标：

1. 看实际分数、阈值、理由。
2. 点 **核对第N轮回答与执行** 或 **核对文件…**，确认引用的就是本题证据。
3. 展开 **评分标准、实际值和计算依据**。
4. 对语义指标，展开 **本指标裁判调用** 或 **裁判过程（与被测对话分开）**，查看实际输入、输出和调用过程。

代码规则应给实际值与预期；模型评分应有实际调用记录。缺证据、请求失败或截断应说明，不能只因为有分数就认为可以复核。

点 **重新收集记录（不重跑）** 前后比较Session和运行数量：只能补证据，不能新增运行或重复写文件。自然发生Trace缺失时，应仍能看到已收到的记录。本轮专门的缺失演示是受控浏览器夹具，见录像；不建议你通过删除数据库记录制造缺失。

### 第14步：对结果有异议，或只更换评分标准

点 **请 AI 解释这次结果**，应引用实际规则和证据，区分事实、推测和建议。

在右侧意见框填：

```text
请核对报告是否已经实际写入；不能仅因为最后一个工具失败就说报告不存在。退款口径已经确认按发生月份，不能再次称其未确认。先核查已有证据，不重跑Agent、不修改原分数。
```

点对应结果下 **按右侧意见复核这次结果**。复核意见单独记录，旧结论保留。

需要修改标准时，先请AI修订草稿并发布新版本，再点旧结果下 **用当前发布标准重评（不重跑）**。只给旧证据新增评分，不产生新的Agent Session或文件写入；不同题目集合或不适用的标准应被拒绝，不能硬凑比较。

### 第15步：AI模拟用户

回到A01草稿，点 **让 AI 另建动态用户场景**。检查AI保留原固定题，并另建一个动态题。需要时在右侧补充：

```text
新增动态题，不改原固定题。模拟用户先问31加24，看到回答后把24改成14；只知道用户应有的信息，不读取隐藏答案或裁判结果。
最多2轮，最长180秒，保留调用上限；不使用工具。删除固定逐轮断言，用整段对话评分，标准检查是否正确处理用户改数。先给草稿。
```

只发布动态题，再运行。结果明确标为 **AI模拟用户**，显示实际追问、回复、停止原因和独立评分。到轮数停止不自动等于通过。

点 **将实际对话整理成固定回归草稿**，应新增可编辑的固定用例，原题保留，不自动发布。

当前模拟用户支持文字对话与预先指定的文件批准/拒绝；不自动替真人填写任意业务表单，也不支持动态模式中的真人在线工具审批。遇到这类请求应安全停止并显示原因。真人审批用第12步的固定轮次模式。

### 第16步：停止运行，不抹去已做过的事

重新运行A或C的一个已发布版本；在 **已发布版本与历史运行** 对应该次操作点 **停止这次操作**。

等待状态结束。之后不应启动后续轮次；已执行的回答、文件和记录仍保留。若当前一轮恰好先完成，可能显示“无活跃运行”，这不代表取消前的动作被撤销。底层停止回执尚无法确认时，页面应明确提示，不能声称资源已经释放。

### 第17步：只撤销一个专用样本

为避免丢失你还想看的结果，另建 `我的验收06-D-撤权专用`，照A流程生成、发布并跑一题。不要撤A、B、C。

在专用样本展开 **管理资料用途授权**，阅读“撤销任一用途会封闭工作项及派生资料”，勾 **我确认停止访问这批资料**，点 **撤销AI整理授权**。

应变为“资料已失效，内容不再显示”；草稿、题库版本、结果和裁判内容不再可读，刷新仍不能读，也不能运行或补收。撤权不是撤回评分意见，更不是删除按钮；内容随后按政策清理。
