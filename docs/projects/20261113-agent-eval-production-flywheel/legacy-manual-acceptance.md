## 这套功能给谁用

本次开发的是团队内部的Agent质量保障流程：把发现的问题变成测试题，改代码或模型后再跑一次，检查问题是否解决、其他功能有没有退步。**它不是给普通用户做题的考试系统，也不会因为题库发布就自动训练模型。**

| 使用者 | 平时需要做什么 | 本清单对应步骤 |
|---|---|---|
| 使用Agent的业务用户 | 给回答反馈，描述哪里不对 | 第1–2项 |
| 项目管理者、资料负责人 | 决定测试材料能否用于评测，必要时撤权 | 第3、7、11项；本地仅项目管理员可导出自己会话的合成材料 |
| 业务专家、测试人员、评测运营 | 检查题目和正确答案，决定收录哪些题 | 第4–5项 |
| Agent开发者、测试工程师 | 用固定题库重新执行Agent，检查结果和退步 | 第6、8–10项 |
| 平台运维、平台开发者 | 验证身份、隔离、清理和恢复保护 | 第12项 |

你这次作为验收负责人，会在两个应用中扮演上述多个角色，普通用户不必走完整条流程。本轮开发采用获准的AI评审；这里的人工操作是检查审核功能，不代表已完成独立盲测。材料状态已改为中文，当前界面仍保留长编号和JSON编辑框，主要适合内部工程与评测人员，普通业务人员独立操作的易用性仍有改进空间。

## 本次新增或补齐了什么

- **把反馈和具体回答关联起来。** 可以保存、修改、撤回；没有运行记录时明确显示缺失。
- **把获准问题变成固定测试。** 单独授权合成资料，审核预期，通过后发布不可随意变化的版本，再调用真实Agent重做。
- **更可靠地判对错。** 检查实际文件、工具执行和审批，不只看Agent说了什么；取消、证据不足和安全失败分别报告，核对实际API/Worker及配置。
- **扩充并检查题库。** AI从20个候选中接受5题、拒绝15个重复改写；补齐七个文件、知识、多轮、安全及合法对照场景。
- **提供受控质量统计和独立巡检授权。** 分母、取消、拒绝和缺证据有说明；自动采样仍关闭。
- **落实资料生命周期。** 撤权后封闭历史访问并清理受控副本；恢复旧备份先应用当前撤权，避免旧资料重新开放。
