## 先知道这次在验收什么

以前，你要自己写题、审核材料、找题库、启动运行、找结果。现在希望做到：

**你说明想检查什么 → AI给出测试方案 → 你用一句话要求修改 → 你确认 → 系统固定题库并运行 → 在原处看结果。**

“工作项”就是保存这一整件事的记录；“题库版本”就是你确认过的一组测试；“回归”就是以后用同一组测试再检查一次。

本文主要使用你的平台管理员测试账号。业务人员负责说明问题，负责人确认业务口径，开发者看失败证据。新流程不要求使用flywheel-reviewer账号，也不会训练模型、修改代码或部署生产。

**验收时分开记两个结果：**

| 看什么 | 怎样判断 |
|---|---|
| 系统流程是否正常 | 是否按你的确认执行，资料/版本/结果能否找到，审批、取消、撤权是否生效 |
| 被测Agent是否答对 | 算式、金额、文件、解释是否符合事先确认的标准 |

例如：Agent算错，系统明确显示失败并给出证据——系统可能正常，但Agent质量不合格。Agent明显算错，系统却显示通过——评测判断有问题。不要把“有结果”或“AI说通过”直接当作验收通过。

## 第4步：让AI生成第一版

1. 在 **问题与方案** 页签，点 **生成测试建议**。
2. 等待“AI整理中”结束。可以离开再回来，不要重复点。
3. 阅读 **AI建议 · 第1版**。

**用这张表核对，不要求AI措辞一字不差：**

| 要检查的内容 | 正确预期 |
|---|---|
| 题数 | 只有A01一题 |
| 被测提问 | 计算31加24，只输出数字、不调用工具 |
| 预期 | 55，精确检查，允许去掉首尾空白 |
| 工具检查 | 工具调用上限0，并有对应检查 |
| 答案隔离 | “55”不能作为标准答案被塞进实际提问 |
| 执行状态 | 尚未运行；回归用途未授权，不能批准执行 |

如果AI把零工具检查说成“不支持”，或遗漏规则，先记录这个建议质量问题，再输入：

~~~text
请修正方案：零工具调用检查是允许的。保留当前提问，用精确答案检查55，并加入工具调用上限0及对应的必须通过检查。不要改变题意，不要自动批准。
~~~

点 **按意见修改方案**。修正后继续，原问题仍记入验收记录，不能因后来修好了就把首次问题抹掉。下文版本号按实际显示，不强求仍为1/2/3。

## 第5步：连续两次用自然语言修改方案

这两轮必须是同一题的连续对话，逐轮精确检查55和45，整个过程工具调用次数为0。不要新建另一道独立题，不要把答案写进实际提问。请说明相对上一版改了什么。
~~~

**预期：** 方案版本增加；A01有两轮，预期依次55、45；“本版改了什么”说明新增追问。

### 第二次：再增加一题，准备验部分采纳

点 **按意见修改方案**，等结束。

**预期：**

- 最新方案有A01、A02两题，A01原内容保留。
- 展开 **和上一版逐项比较**，能看出增加了A02。
- 点 **历史记录**，旧版仍在；展开 **查看当时的完整方案** 能读到旧内容。
