## 为什么还需要这一步

06已经跑通“会话资料→AI出题→发布→执行→诊断”的业务流程，但工作台绕过了评测平台的正式路由，单独铺满页面。用户进入后看不到平台导航；已有菜单也没有对应的正式路由。因此，业务流程跑通不等于平台内使用体验已经完成。

这一篇补齐页面整合。06的历史验证记录保留，不把它改写成曾经完成了这项工作，也不再另建一套题库或评测服务。

## 完成后，你怎么用

1. 从评测平台左侧“评测集”进入列表，搜索和找回已有草稿及发布版本。
2. 点击“新建评测集”进入填写页；没有线上会话也能直接建题。
3. 打开一个评测集，平台导航仍然可见；中间管理题目、版本和运行，右侧与AI讨论当前题目。
4. 从Agent聊天页点击“转为评测集”后的已有跳转，进入同一个平台内详情页，不进入独立页面。
5. 从评测结果回到对应评测集时，保留指定运行；刷新、前进、后退、复制链接另开页面都能定位正确内容。
6. 有未保存内容时，离开前提示选择继续编辑或放弃；加载中、无数据和读取失败分别说明，不把“正在加载”写成“还没有评测集”。

## 实测发现：登录体验也必须补齐

2026-11-16，平台整合实测发现：评测集接口使用Agent平台登录，原生实验/设置接口仍使用MLflow认证。原生接口返回HTTP Basic认证挑战后，Chrome弹出浏览器认证窗口，页面虽然可见，但自动化点击与键盘操作没有进入页面。用户确认看到了认证弹窗，并要求改为正式登录页面。

**用户已批准：先做登录页，保留现有权限。** 评测集仍用Agent平台账号，原生模块使用已有MLflow账号。不新增账号、不合并同名用户、不改变实验/批次权限；统一身份与角色映射不在本轮实施。

实现补充：原生模块增加页面内登录，登录后保留原地址；浏览器请求的401以页面错误处理，不弹HTTP认证窗。服务器以短期、不透明的HttpOnly会话Cookie衔接原生认证，原凭据只保留在所属服务的限时内存中，不写浏览器存储、Cookie或磁盘；每次原生请求仍交给原有认证与权限检查。会话最长1小时，退出、过期或服务重启后重新登录。此方式用于当前单进程隔离服务；多进程部署需先接共享会话管理，不在本轮部署生产。

Task 7.4同时验证错误密码、登录回到原链接、退出/到期、未登录拒绝、跨源请求拒绝，以及SDK原有Basic认证不变。后端改动仅限`eval_platform/`认证交互适配，不改`mlflow/`上游。
