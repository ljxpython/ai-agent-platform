# 04-生产化集成、可信比较与发布门禁

> 修订：2026-11-13。评审方向已确认；修订稿待实施评审。G0–G3、CLI 退出码和联合 Final 口径以本文为准。

## 目标

1. 在现有 EvalFlow 执行器、任务 API、结果页和 DatasetRegistry 上补生产化缺口，不重新创建评测中心。
2. 将完整性、安全与业务事实、语义退化、预算分开判断，明确什么阻断、什么告警、什么无法判定。
3. 验证真实 CI 对实际候选部署执行了评测，证据能回链到数据集、配置、Run/Trace；保留可关闭和可恢复能力。

## 方案设计

### 2. 阶段 0：能力验证与身份/部署对账

输出一张有证据的「代码已实现 / 已部署位置与版本 / 业务链路已验收」矩阵，包含：
- Agent API/Runtime/Worker、EvalFlow server/job worker、fixture 服务、数据库/持久文件/模型网关；确认实际运行版本、启停归属、网络可达及环境 ID。
- 对账两仓 2026-11-13 部署记录与 A04 沙箱准入阻塞；不以旧记录或 HTTP 探活清除 blocked。仅经授权核查远端，不改变准入策略绕过验证。
- Review Queues 的已认证审核人、实验权限、字段/状态映射、可用 UI；检查默认无认证模式不被误作生产人审。
- 原生在线评分对内置 Judge、注册 Judge、当前 DeepEval scorer/会话指标分别验证支持情况、后台执行和用量记录。原生不支持的部分优先放 eval_platform/ 的有界执行任务，记录选择理由；不引入预设 Celery。
- 必须进入批准方案的数值：采集开销/完整性目标、抽样最小样本量、每日 Token/请求/并发/重试预算、积压和数据保留期限。未冻结不得启用生产路径。

探针优先使用合成资料及所属隔离资源；本轮文档修订没有授权执行生产写入或真实模型调用。阶段 0 发现安全/权限/契约与已批准标准冲突时明确上报，不能把不匹配文档改成已合法。

### 3. 生产化接入与最小权限

- 保留现有本地模式；新增生产模式只能在明确配置和认证可用时启用。CI/平台服务使用有作用域、有效期及审计的身份，不复用开发者管理员密码或浏览器令牌。
- 校验 tenant/project、source/target experiment、dataset、profile、Run/Trace 的授权关系。Experiment 分组不是安全边界；不能按调用者上传的 tenant/project 字符串授权。
- 复用既有任务/数据集 API 语义，不新增通用 /api/v1/eval/trigger 占位接口。若需最小 Agent 网关，只代理已批准业务动作，任务和评分真源仍在 EvalFlow。
- 拒绝客户端任意文件路径、模型凭据、脚本或 callback URL；先用受权状态查询获取结果。确需回调再评审固定目的地、签名和重放/SSRF 防护。
- 生产端点与模型资源经受管环境/secret 引用注入；~/.my_best/.env 仅是已有本地开发资源来源，不要求 CI 或生产存在该文件。
- 任务目录、冻结 registry、profiles、原生 MLflow 数据及 fixture 一起纳入持久化/备份。当前本地文件锁不自动变成分布式租约；先明确单实例支持边界和恢复，再决定是否需要持久队列或数据库升级。
- 启动和审批恢复均核对配置快照；模型路由、Prompt/技能、工具/知识、执行镜像或部署代码发生漂移时停止混用并报告 error。缺少实际版本可证明性时不能声称候选提交通过发布门禁。
- 实施新增表/索引时提供增量迁移、幂等/唯一约束、兼容读写、备份与回滚方案，人工批准后执行。回滚不删除审核/运行事实。

### 4. 两种评测模式与比较协议

**historical：** 读取已授权历史证据，用于裁判/rubric 校准；不新调 Agent。可能有模型评分成本和处理耗时，不承诺秒级或零成本。不能证明新代码修复了旧问题。

**regression：** 使用专用评测身份、独立 Thread/Workspace、固定资源映射，通过正式 Platform API 主动运行。保留 UUID 幂等、接受未知对账、审批 interrupt、取消确认及 Trace 有限等待；不因评分/上传失败再次执行有副作用的 Agent。

比较前必须固定或核查：题库内容/用途/选题、case/family 映射、fixture/知识索引、评分代码与 rubric、裁判路由/参数、环境/工具版本、预算/策略版本。明确允许改变的变量，如 Agent Prompt 或模型配置；不同题库或不同裁判不直接生成版本防倒退结论。

Run manifest 记录两仓源码及 dirty 摘要、实际部署版本、执行配置快照、锁文件、模型返回标识、来源/fixture hash 和 environment_id。仓库文件变了但运行服务仍是旧代码时拒绝作为候选验收；不把 git HEAD 自动等同运行中的 Worker 版本。

逐题以 dataset/version + case_id 配对并汇总 family/suite；分开报告确定性失败、语义波动、样本数量、有效分母、错误/缺证据和成本/延迟。重复次数、接受波动、退化幅度在候选运行前冻结；不得通过无限重跑取最好一次或失败后临时改门槛。

### 5. G0–G3 门禁决策表

四个维度不是四种结果状态；项目 done/partial/blocked/deferred 也不是评测结果。下面是拟实现策略，必须带 gate_policy_version，不改写旧报告语义。

| 维度 | 判断 | 放行规则 |
| --- | --- | --- |
| **G0 完整性与可比较性** | 必需 case/metric、证据、发布回执、实际执行版本及比较条件完整 | 缺失、required error、错误使用 not_applicable、配置漂移或不可比 → error / exit 2，不放行 |
| **G1 安全与确定性业务事实** | 授权副作用、审批、权限隔离、声明的 hard_gate 断言 | 任一失败 → fail / exit 1，不接受其它分数抵消；正常拒绝按用例预期判断 |
| **G2 语义质量与退化** | 已校准语义阈值、逐题已知修复回归、suite/family 差异与波动 | 冻结策略中 blocking 项失败 → exit 1；观察项只出 warning；未完成校准不得宣称发布合格 |
| **G3 预算与效率** | 每题/批次硬请求、Token、时长上限；相对成本/步骤/延迟变化 | Agent 超出已批准硬预算按归因 fail；基础设施不足/必要计量缺失为 error；相对变化默认观察，经批准才阻断 |

旧方案中的 TaskCompletion 0.85、ToolCorrectness 0.90、相对步骤 15% 仅保留为校准候选，不是已生效标准。模型费用不可计算记 unknown，不记零；以可验证的请求/Token 上限控制，若门禁强制金额则价格证据缺失必须阻断。

not_applicable 必须来自开跑前冻结的适用性，不是现场评分失败的替代状态。报告同时保留所有安全失败与完整性错误：若两者并存，整体按 exit 2 标为不完整，并显式列出已确认安全失败，禁止提前返回而隐藏违规。

无论属于哪个 suite，实际安全违规都触发 G1；安全专题全通过只能表明已测样本满足规则。对政策允许的非安全豁免，须绑定 case/metric、理由、批准者、有效期与版本，报告仍保留失败；G0 缺证据和实际未授权行为不得通过改分或软警告绕过。

### 6. CLI、CI 与报告

现有 CLI 接受 baseline 报告文件路径，不把标签/Run ID 当作已经支持的参数。现有可用命令形态：

```bash
python -m eval_platform.run regression \
  --config "<private-config.json>" \
  --dataset "<frozen-cases.jsonl>" \
  --split all \
  --baseline "<baseline-report.json>"
```

若后续支持从服务端 Run ID 取 baseline，先在任务层解析/鉴权并保存快照，不静默改变参数语义。使用各仓已安装环境，文档命令不包含执行代理前缀。

| 退出码 | 含义 | CI 处理 |
| --- | --- | --- |
| 0 | 执行完整且所有必需门禁通过，可含非阻断 warning | 仅对证据绑定的候选版本放行 |
| 1 | 执行完整但业务/质量/安全/硬预算失败 | 阻断，保留逐题结果 |
| 2 | 配置、权限、基础设施、裁判、缺证据、不可比较或必要上传失败 | 阻断；修复/对账后显式重试相应阶段 |
| 130 | 主动取消 | 不放行，不把取消题计为通过 |

**真实 CI 是本期阶段 3 的验收项**，区别于上一期后置范围：
- 普通 PR 运行无密钥的单元/契约检查；可信 runner 的手动/定时或受控 PR 流程执行真实 smoke/回归，注入短期最小权限资源。
- 不在不可信 PR 代码中暴露生产秘密或执行任意合成脚本。任务指向批准的隔离评测环境，不在生产业务项目跑破坏性安全题。
- 将 commit/配置版本、dataset/hash、gate policy 和运行证据绑定到 check；超时、取消、exit 2、上传失败都不能被 continue-on-error 或管道吞掉。
- 保存完整、脱敏、受权的 report/manifest/逐题证据；日志只含必要摘要。PR 评论和外部通知仅在明确授权后发送，不能默认自动外发。
- 自动检查先接线并演练；默认分支保护/正式发布策略切换另需批准。没有可信 runner/secrets/沙箱时记录具体阻塞和请求，不能用本地 CLI 成功替代真实 CI。

报告给出判定、期望与实际值、证据引用和可验证差异位置；模型理由标为推断。没有证据的行号、根因或模型私有思维链不得编造；二进制或不支持格式显示可得的 hash/解析信息。

### 7. 关闭、回退与联合验收

采集、抽样、回流、v2 新发布、循环干预和 CI 强制策略分别可关闭。停止相关任务时先确认在途 Run/工具停止，保留已有结果、审核和回执；评分失败仅重评分，投影失败仅补投影。

迁移采用可恢复备份及兼容读写验证；回退保留冻结版本和审计记录。新增端点未配置认证/作用域时默认拒绝，不回退匿名。恢复到原本地模式也不能丢失旧版本或把生产 URL 静默变为开发地址。

联合 Final 需包含所有批准范围的单元/契约、真实跨服务 E2E、权限/隐私、故障恢复、性能对比、备份恢复与关闭回归。产品链路可报告真实业务 fail，但必须区分「系统正确检出问题」与「被测 Agent 可发布」。只有全部批准范围完成才将项目标 done；缺条件先完成其它可执行项，再记录 blocked。
