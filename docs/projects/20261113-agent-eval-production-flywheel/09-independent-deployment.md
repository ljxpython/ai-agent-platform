## 部署与接口契约

1. EvalFlow配置可达的`platform_url`和独立的`EVALFLOW_SOURCE_URL`，均为明确HTTP(S) origin；后者使用现有source token做权限回查。Agent配置准确EvalFlow接收origin、后台认证和同一签名密钥。两端不共享文件系统；上传、下载、停止和Trace继续用原接口与认证。生产应配置HTTPS；SSH只用于本次隔离开发传输。
2. `POST /api/evaluation/targets/snapshot`使用原平台Bearer认证和`X-Project-Id`。请求为`{agent_id, model_id, parameters: {temperature, max_tokens, top_p}}`；返回`evaluation-target/v1`，包含有效配置、Agent摘要、模型连接修订、平台执行账号的有效工具策略、Runtime资源声明和双方构建清单，`config_hash`绑定全部内容，不返回模型密钥。
3. `POST /api/evaluation/threads/{thread_id}/runs`使用相同认证及必填`Idempotency-Key`，请求为`{target: <完整快照>, run: <原运行请求>}`。新运行的context必须等于冻结context。恢复运行复用原target与原context，客户端不能注入或替换`evaluation_target`；它只在服务端验证后写入可信metadata。
4. API在提交/恢复前重取快照，Runtime在实际调用模型和工具前校验所属scope、核心参数及双方版本；执行回执记录目标摘要，EvalFlow收集后再次核对。无执行权限403、快照篡改/参数覆盖400、目标变化409、缺少新版本或证据契约503。旧服务必须一起升级，不回退跨仓读盘。
5. 模型连接`updated_at`与服务构建清单保证配置身份可核对，不承诺供应商模型权重绝对可复现。来源授权到期仅阻止继续取源；既有题库按自身访问权限读写和发布，新执行按题库实际发起者当前成员及执行权限检查。平台执行账号的工具策略与实际发起者的权限检查各自生效，不承诺后者所有个人工具限制自动继承到前者。有效原始资料用途每次向AI送源时复核，失效后只可使用已保存题目。
