## 两个平台各自做什么

**Agent平台**负责用户对话、获准会话/环境交付和被测Agent执行。**EvalFlow**负责评测Agent、用例生成与增删改查、AI修订、指标、版本、运行及问题定位；业务代码在`eval_platform/`，界面在`web/`，没有修改`mlflow/`上游核心。

现在可以走三种入口：从Agent交付当前完整Session、批量筛选并交付会话，或者直接在EvalFlow新建测试。三者汇入同一个评测集工作台：

**提供资料 → AI整理题目 → 反馈修改/手工编辑 → 保存草稿 → 发布版本 → 按需运行 → 查看完整Session和评分依据。**

保存、发布和运行分别操作。发布不会自动运行。已有版本与每次结果保留在同一工作项内，切换页面或刷新后仍能找回。

主要受众是业务负责人、项目管理者、Agent开发者和测试人员：业务方确认口径，管理者控制资料用途，开发者通过证据改进Agent。系统不会自动训练模型、修改代码或部署生产。

5. 以业务 Run/消息为反馈锚点，区分平台 Trace、MLflow Trace、审批恢复 Run；记录缺失与延迟。
6. 原生审核/评分优先做能力验证；不预设 Celery、第二套审核台或新的通用评测网关。
7. 契约以已运行代码为基线；v2 需覆盖导入、冻结、执行、评分、展示与旧版本读取。
8. 已修复题进入固定回归，不重新变成盲测。合成题按家族隔离，验收质量与覆盖增量，不考核低淘汰率。
