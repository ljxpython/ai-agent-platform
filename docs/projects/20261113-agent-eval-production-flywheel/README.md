## 职责与数据边界

| 所有者 | 负责 | 边界 |
| --- | --- | --- |
| Agent Runtime | 既有运行事实、工具/审批/预算事件、安全取证 | 新监控首期旁路，不自动终止任务；审批与权限仍由原执行机制强制 |
| Agent API / Web | 消息反馈、项目 ACL、源数据授权、受控快照/导出及必要入口 | 不运行评分引擎；不维护第二份题库发布状态；浏览器不直读数据库 |
| EvalFlow 扩展与原生 UI | 评分、评测审核、预期、题库版本、执行配置、比较与门禁 | 不直接读业务库、Runtime 源码或任意 Workspace；只接收获准的数据 |
| 既有可观测栈 | 低基数运行指标、趋势、告警与排障跳转 | 不把用户原文、Trace ID 或任意项目 ID 作为无界 Prometheus 标签 |

生产源记录的授权事实以 Agent 平台为准；评测审核和已发布数据集以 EvalFlow 为准。相互只保存关联 ID、状态投影与回执，禁止双向编辑同一真源。Experiment 名称或 project_id 字段不能代替权限校验。

生产敏感内容不默认跨租户进入集中实验。先定受众、导出政策和认证映射，再选择允许的实验与资料库；同一评测项目的合成数据基线不构成生产资料共享授权。

## 核心修订决策

1. 保留异步抽样、人审预期、确定性断言优先、历史/主动两模式；新增内容必须对应已证实缺口。
2. 点踩、拒绝审批、断流和工具异常先记信号；故障确认与严重度独立，不把正常拒绝算安全事故。
3. 三次同参只作为可校准线索。阶段 1 不新增自动熔断；生产干预须在阶段 4 单独评审和灰度。
4. 脱敏及外发资格检查先于外部模型调用；取消「小文件直接入库」与无证据的保真承诺。
5. 以业务 Run/消息为反馈锚点，区分平台 Trace、MLflow Trace、审批恢复 Run；记录缺失与延迟。
6. 原生审核/评分优先做能力验证；不预设 Celery、第二套审核台或新的通用评测网关。
7. 契约以已运行代码为基线；v2 需覆盖导入、冻结、执行、评分、展示与旧版本读取。
8. 已修复题进入固定回归，不重新变成盲测。合成题按家族隔离，验收质量与覆盖增量，不考核低淘汰率。
9. G0–G3 规则和退出码以专题 04 为唯一口径；缺证据、不可比较、取消均不能放行。
10. 全文将「零开销、全量故障检出、固定准确率」改为测量项；阈值在候选版本运行前冻结。
