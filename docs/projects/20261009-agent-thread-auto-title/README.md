# F07 自动对话标题：复用与实施

## 项目概述

- **启动日期 / 实施日期：** 2026-10-09。
- **目标：** 在现有会话命名链路上补齐安全边界和浏览器自动命名，复用同一个生成器与持久化事实源。
- **负责人：** 后端/Runtime 由当前开发者接续；前端由同事实施。
- **模板类型：** 标准模板。
- **状态：** 部分完成（partial）；T01-T05及T07A非前端源码/候选验证与交接已完成。仅剩T06/T07B前端与联合Final、B01正式CAS双包发布/正式源接入block；未部署现役。
- **本轮授权范围：** T01-T05与T07A非前端范围的实现、验证、文档同步；前端T06/T07B交同事，不发布外部包、不提交Git。

## 结论

**已按批准的 R1-R5 复用现有 HTTP 标题链路，补齐受管模型、精确授权与原子写入；前端自动触发由同事实施。**

首消息规则命名、手动改名、手动 AI 提炼、双聊天入口和 `metadata.title` 继续复用。API 新增显式 opt-in/内部 seed/公开 pending、首轮 success 校验与生成后复核；Runtime 改用受管一次非流式调用；GraphHarbor 提供通用数据库 CAS。没有新增 Graph title、TitleMiddleware 或 SSE。旧项目移除自动完成回调的决定由本次显式 opt-in、独立辅助请求和用户改名优先机制补充。

自动标题提升会话检索体验，不提升任务执行可靠性，也不是工业级 Agent 的必要门槛。已建成的超时、预算、取消、恢复、工具容错等能力继续复用；不以参考项目的文件名或 Middleware 数量决定完成度。

## 已批准决策

1. `Thread.metadata.title` 是唯一正式标题；不增加 Graph `state.title`，不靠 checkpoint 回放修改标题。
2. 自动/手动 AI 提炼共用现有 HTTP 链路与一个生成实现；保留当前手动改名和规则命名。
3. 首期为平台浏览器会话的 best-effort 自动请求；页面关闭不保证生成，Cron/IM/无人值守自动命名后置。
4. 自动命名必须验证成功回合、用户命名优先和原子条件更新；条件更新未具备时自动模式保持关闭。
5. 手动/自动 AI 均需 comment+edit，使用同一个精确标题委托与 CAS；人工改名仍只需 edit。辅助标题费用暂不进入 Agent Usage 合计，不新增 PII 治理。
