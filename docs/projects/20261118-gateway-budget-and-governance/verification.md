# AI 网关预算控制与财务熔断验证方案

> **当前状态：** 后端阶段验证（Phase）已有真实PostgreSQL、HTTP/Worker和进程恢复证据；完整主备/异步恢复组合、前端和性能/回退门禁未齐，整体验收（Final）未通过。文档修订历史保留在第4节。
> **进度归属：** 本文定义场景与保存验证证据，完成状态必须回写 [tasks.md](tasks.md)。阶段通过不代表整体验收通过，AI 不代替人工治理评审。

## 1. 统一口径与执行条件

- 权威来源是 Runtime PostgreSQL 调用账本及同事务预算派生，不是可选 Trace、整 Run completion 或 Redis 浮点累计。
- 金额按 Decimal / `numeric(28,12)` 比较，HTTP 使用十进制字符串；零费用、未知费用与部分已知不可混用。
- GLOBAL 是同 tenant 总预算；PROJECT 只约束相应项目。REJECT 针对之后新增的模型调用，允许已准入在途调用造成超支。
- 周期为 UTC 日、周日、月初，左闭右开；费用归调用开始周期。恢复中或不可核实不能按零放行 REJECT。
- 数据库无法持久化调用开始时，配置预算的调用不得发送到模型；ALERT 的账务降级不提供无持久证据运行保证。

集成测试使用真实 PostgreSQL、独立连接与多 Worker，不能仅用内存锁 / Mock 证明分布式一致性。重试、失败和边界费用可使用可控模型适配器精确断言；Final 另需真实认证和至少一条实际模型调用证据，标清哪些结果来自可控适配器，不能混称供应商真实扣费。

真实联调前读取 [Worktree 资源隔离规范](../../standards/worktree-development.md)，使用该规范管理资源，不启停共享服务。实施后按实际测试文件与现有脚本登记命令，不把规划中的文件名伪装成已执行命令。

## 2. 阶段验证（Phase）

### P1：控制面与受信契约

**对应任务：** Task 1。

- [x] CRUD 校验金额为正、精度不超过 12 位、非法周期 / scope 组合与项目不存在；错误遵守现有 Envelope，具体参数错误状态码按已冻结契约断言。
- [x] 覆盖普通成员、项目管理者、平台管理员；同 tenant 跨项目与跨 tenant 访问分别测试，GLOBAL 不能跨租户。
- [x] 策略集版本单调，创建 / 调额 / 改动作 / 改周期 / 删除可追溯；晚到旧版本、成功空集合和查询失败能区分。
- [x] 金额字符串无浮点往返损失；未知状态返回 null / 已确认部分金额，不把 `is_exceeded=false` 作为默认。
- [x] 内部策略解析 / 状态查询校验身份、签名方向、时效、防重放及方法 / 路径 / 请求体绑定；不能伪造跳过预算。
- [x] 策略保存与窗口就绪分开呈现，变更同步失败可重试；不兼容的 Worker 无法接收受 REJECT 保护的新调用。

**实际结果：** API专项30项覆盖CRUD/当前权限/签名/严格响应及pending恢复；Runtime真实PG覆盖旧session和关闭开关无法领取。该栅栏作用于整个Runtime执行域且粘性保留，包含空策略同步，不能解释成任意新旧Worker可透明混跑。证据见[后端验证记录第3、7节](implementation/01-backend-validation.md#3-专项测试与扩大回归)。

### P2：事务记账与多 Worker 一致性

**对应任务：** Task 2.1、Task 2.3。

- [x] UTC 跨日、周日、月末、闰年和跨年边界，恰好落在结束时间的调用归下一窗口。
- [x] 多连接 / 多 Worker 同时写入已知小数费用，GLOBAL 和各 PROJECT 金额与唯一账本事实总和完全一致；包含阈值恰好相等。
- [x] 同调用重复完成、取消 / 失败后重放、旧缺失事件晚到均不重计；部分 / 缺失转可信只补差额。
- [x] 实际两次模型尝试各计一次，同一事实重放仍沿用原 ID；新价格不改写历史价格快照。
- [x] 在账本、计入记录、两个作用域窗口及 outbox 各写入点注入失败，断言全部提交或全部回滚。
- [x] 并发首次越线只产生一条持久事件；ALERT / REJECT 都生成，调额 / 改动作 / 再越线不重复生成。
- [x] 已放行在途调用可使金额超过额度，超出部分仍准确记录；不得用“累计正确”替代“从不超支”断言。

**实际结果：** Runtime专项最终34项通过，四个独立PG连接精确累计；usage/contribution/window/event/second_scope五处故障均回滚。重复事实、补差额、旧价格和在途超支分别断言；不是金额预占或生产多Worker容量结论。

### P3：回填、周期历史与未知状态

**对应任务：** Task 2.2。

- [x] 本周期已有调用后创建策略，能回填已知费用；检查采集覆盖与降级记录，缺价格 / 用量不补零。
- [x] 回填同时实时结算，包含无策略时已启动的写入事务在回填之后才尝试提交；证明无重复也无遗漏。
- [x] 23:59 开始、次日结束的调用补记旧窗口；当天新调用、旧窗口迟到结算及双周期并发互不覆盖。
- [x] 调额 / 改动作不清零；调低到已用之下生成首次事件，调高恢复后续准入；改周期 / 作用域保留定义历史及生效边界。
- [x] Worker 重启、窗口丢失或不一致时重建；恢复前为 reconciling / unverifiable，核对完成后才可按完整余额准入。
- [x] 检测失联未闭合调用；故障恢复后可核实则补记，无法核实则保持未知，不能随连接恢复自动标完整。
- [x] 删除 Thread、清理 Trace 或重建投影后，有效预算及历史价格 / 费用不减少，重建依据仍保留。

**实际结果与边界：** 真实API/Worker重启、金额重建、失联夹具及Thread删除后均保留2.5 USD；晚提交竞争、采集缺口与历史定义有专项覆盖。Trace不参与记账/级联删除已做源码核对，未实际清理外部Trace服务。采集启用前全部供应商历史尚无覆盖证明；真实403费用仍未知，没有清成0。详见[恢复证据](implementation/01-backend-validation.md#5-进程恢复未知与通知)。

### P4：每调用准入与 HTTP / SSE 表达

**对应任务：** Task 3.1、Task 3.2。

- [x] 同一长 Run 中途达到上限，下一笔模型调用未到达供应商；主 Agent、子 Agent、摘要等已纳管辅助路径分别验证。
- [ ] 异步恢复、显式 / SDK 隐式重试、备用模型各自经过准入；预算拒绝不自动换模型重试。
- [x] 长 Run 中创建 / 修改 / 删除策略，下一次重新解析生效；旧响应不能覆盖新版本，无匹配策略与无法查询不能混淆。
- [x] GLOBAL 与 PROJECT 多策略同时命中，任一 REJECT 不满足即阻止；没有权限的客户端得不到其他项目明细。
- [x] 缺价格、用量缺失和结算不确定：ALERT 在已有持久调用证据的条件下可降级；REJECT 停止新增调用。无法持久化开始标记时两者均不调用模型。
- [x] 握手前超额为 429，不可核实为受控 503；Envelope、request_id、安全 extra、Retry-After 与重置时间符合契约。
- [x] 流内停止不能伪装 HTTP 429；安全错误 / 预算通知可见，刷新 / 重连可回读原因，不新增 Run 终态。
- [x] 已完成结果、历史读取、停止 / 取消和策略修复不被预算阻断；账务失败不能被观测 callback 静默吞掉后继续 REJECT 调用。

**实际结果与剩余：** 同步/异步、实际LangChain工具循环、辅助/嵌套guard和预算拒绝不retry/fallback有专项；真实认证→Runtime API→Worker→可控OpenAI HTTP已证明429、ALERT继续、SSE停止和历史回读。不是供应商付费成功或完整主备/恢复组合证据。首选maomaoai额度不足403；既有Resilience多轮工具 `KeyError: 'model'` 在无预算callback也可重现。P4第二项保留未通过，由账户维护者补额度后后端继续核验，前端消费另归P6。

### P5：跨服务事件与通知恢复

**对应任务：** Task 3.3。

- [x] 费用提交后、发送前退出，重启后事件仍可发送；接收成功未 ACK 时能安全重投。
- [x] Platform API 在持久化幂等接收、站内通知和投递任务后 ACK；重复事件只产生一份站内信。
- [x] 外部发送失败 / 超时 / 成功后 ACK 丢失均有记录和重试；可能重复时具有稳定事件 ID，不宣称外部 Exactly Once。
- [x] tenant、项目身份和签名不能伪造；旧事件重放不重复计费，不能把一个窗口事件改成另一个租户的通知。

**实际结果：** 重启后outbox attempts=2并ACK，站内前后均1份；HTTP新签名重投保持1份receipt。外部成功但ACK写入失败采用测试发送器，观察两次外部发送/一份站内信；本环境无外部通知渠道，没有向真实外部接收人发消息。
