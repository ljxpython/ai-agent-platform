## 3. 样本与质量核对

执行前冻结脱敏素材、业务参考规则、预期行为与授权。两类出题素材可来自不同 Agent，但不要求来源已接入 EvalFlow 重新执行协议，也不因同一次运行覆盖多个检查项重复计数。

| 场景 | 必须观察到的行为 |
|---|---|
| 非退款工程与文件素材 | 不新增无关财务规则；文件要求有素材或已确认业务规则依据，当前目标未核实不阻断内容完整题库。 |
| 非退款文本与多轮纠偏 | 保留确认事实和新规则生效轮次，按语义逐轮判断，不新增文件依赖。 |
| 真实退款正例 | 保留实际业务要求与必要核算；预期依据获准原始材料，不照抄旧助手答案。 |
| 文字与工具式澄清 | 文字追问用语义标准；request_information 只用于明确要求的工具式交互，不与零调用预算并用。 |
| 安全与文件断言 | v3 不使用 no_write，区分 attempted/blocked/executed；没有 write_file 不推定没有产物能力，题目需求与当前运行兼容性分开表达。 |
| 缺少或无法查询能力 | 不以固定 Agent 名称、完整 Manifest 或在线目标为门槛；资料充分则继续出题和发布，未核实的执行条件可见。 |
| 业务资料本身不足 | 澄清或保留草稿，不虚构预期；不与“当前没有可运行目标”混为一类缺口。 |
| 历史回答只有文本 | 不重跑即可评价文本；所选工具/文件指标缺证据时明确不可判定，其他独立指标可处理，整体不掩盖缺失。 |
| 显式新运行失败 | 当前权限、协议、用例能力或必要证据不足时拒绝该次启动；不修改或封闭原题库。 |
| 非法结构、修复耗尽、取消与并发编辑 | 有界失败，保留旧草稿与版本，不自动发布或覆盖新编辑。 |

每条被接纳内容检查业务条件完整、逐轮要求正确、预期有依据且题面不泄密。用例可以记录工具/文件等执行需求；未经核实的当前目标兼容性不能冒称通过，也不能倒过来成为所有题库内容的发布门槛。

## 4. 真实模型与操作链路口径

### 4.1 固定样本与分母

固定 10 次独立出题作业，文件类和纯文本类素材各 5 次。执行前冻结模型、参数、提示词/Schema 版本与样本，确认出题资料充分；不要求冻结实时执行目标或完整工具清单。包含非退款、真实退款正例、多轮及被测业务的澄清/安全要求；故意缺业务资料的出题负例单独检查，不混入成功率分母。

- **首稿通过率：** 首份候选同时满足结构与业务质量的作业数 / 10，要求 > 80%（至少 9 次）。不必要澄清、空集和无关回复不算成功；当前目标可运行性不计入出题首稿判定。
- **修复后通过率：** 在既有尝试与步骤上限内最终满足出题要求的作业数 / 10。
- **修复条件成功率：** 首稿失败、经有界修复通过的作业数 / 首稿失败的作业数；分母为 0 时写“不适用（无待修复样本）”。
- **失败与开销：** 格式、业务、泄密、模型/服务错误及取消逐次保留，不删换失败样本或追加调用抬高原比率。作业内重试和工具调用计入同一作业，记录耗时、Token 与实际返回的费用，缺失费用不编造。

10 次是冻结样本的冒烟门槛，不证明任意 Agent 的质量或自愈 100%。调整样本量或阈值须先说明原因并获确认，再重新冻结。

### 4.2 出题、历史评分与新运行分别留证

两类素材各至少一条完成“交付获准会话 → AI 候选 → 人工采纳 → 独立发布”，记录来源、候选/采纳版本与 hash、实际人工修改和发布结果。覆盖没有完整能力清单、目标离线或未支持重新执行的条件，不以另建手工题替代 AI 链路；人工修过的候选不计为首稿通过。

历史评分记录已有回答及指标所需证据，证明评分未调用目标 Agent 或产生新执行 Run。缺证据指标不得报通过，也不得因此阻止其他可独立评分的指标；总体结果须准确呈现不完整范围。

对现有支持目标验证显式新运行时的当前权限、协议及用例必要能力检查，按现有适配器核对 Session/Run/Trace 和适用证据；不把 HTTP 成功或 Run 结束等同质量通过。新目标/新图的执行适配仅在需求和变更范围获准后纳入，其新增证据要求写回 Task 3.3。

验证记录包含命令、代码版本、实际环境、样本/参数、预期与观察结果、失败和未覆盖条件。日志按授权保存，文档仅放脱敏证据。真实模型调用、资料发送与环境操作须处于获准范围，本轮已获准以合成/脱敏样本完成固定模型验证和所属测试服务操作；不包含生产部署与 Git 交付。
