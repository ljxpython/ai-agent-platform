# 一次启动自动执行：实施设计快照

本文件记录2026-11-20批准的一次启动自动执行设计和既有实现边界。用户随后批准客观执行验收优先、固定交互按需、动态模拟仅保留可选兼容；当前策略及验收以Agent仓同名项目plan.md的范围收敛节为准，[操作路线](../manual-acceptance.md#开发版自动执行路线)同步两类用例。六轮设计不代表所有任务必须多轮或调用裁判。状态唯一维护在Agent仓同名项目tasks.md，EvalFlow仓tasks.md只作映射；实施差异须回写唯一方案和任务。

## 发布可执行评测集后，一次启动自动执行和评分

**阅读说明：** 本文维护已批准的设计与边界，不另设进度清单。范围包含Task8–12的EvalFlow实现，以及用户追加批准的Task13运行时兼容修复；当前进展及证据分别见原tasks.md和verification.md。原Task1–7交付与证据保留。

### 用户过程与最终目标

用户在 EvalFlow 准备初始材料、逐轮请求、中途附件、决策规则和独立验证标准，审核后发布一个版本。点击“运行评估”时选择“重新执行任务”，平台创建本次会话，自动发送请求、在指定轮次上传附件、回应已配置的澄清和审批，最后收集工具记录与实际文件并给出各项指标、失败位置和依据。固定交互回归无需用户逐轮发消息或补传文件。

“评估已有会话”继续只使用历史证据，不发起新任务。两种模式的前置条件、结果来源和界面说明必须明确。自动执行包含如实报告业务失败、执行故障和证据不足，不保证被测 Agent 每次完成任务。

### 复用路线与本轮范围

1. 保留MLflow的实验、Run、Trace和结果页，按所选指标使用已锁定DeepEval4.3.4；ConversationSimulator保留既有可选兼容。复用工具约束、逐轮断言和文件验证，不增加AgentEvals或其他依赖。
2. 以完整输入、Agent自主执行、客观结果验收为主；有业务需要时覆盖固定多轮、分轮CSV/UTF-8文件、结构化澄清、计划审阅和受限审批。已有AI模拟及真人审批保持兼容，不继续扩建动态模拟器；隐藏标准不进入模拟用户输入。
3. Harbor 可作为未来代码/终端环境的外部执行器，Inspect 可作为独立框架备选；本轮不同时引入多套编排器，不升级依赖以追逐官网新 API。不把默认新会话的 Harbor 多步骤等同本项目同会话多轮。
4. 主要代码归属为相邻 `mlflow-eval-platform` 仓的 `eval_platform/`、相关测试及必要的 `web/` 编辑/运行界面。真实验收暴露工具调用未执行后，用户于2026-11-20批准Task13，在Agent独立Worktree修复runtime-service的流式工具名兼容；platform-api仍无本轮产品改动。此前“Agent仅文档”为扩围前边界，不再作为当前限制。
5. 复用现有受控运行及 `command.resume` 通道。若实测暴露必须改变 Agent 权限、安全规则或对外契约的缺口，先记录具体请求与失败，再单独评审；不通过删除限制或给所有审批自动放行完成回归。

### 可执行用例与运行约定

- **材料和可见时点：** 沿用 `Case.fixture`、`Turn.fixture` 和实际上传回执。保存内容摘要及所属轮次，禁止提前使用后轮附件、把产物当初态或通过重名覆盖改变已确认输入。当前支持格式沿用现有 UTF-8 文件契约；原始二进制 Excel 通用采集不在本轮已确认能力内。
- **独立原件核验：** 文件工具样例由评测器独立记录上传SHA256并在结束时读回比较；Agent仍实际读取业务文件，不要求其通过文件工具计算哈希，不因此开放终端。自动化用例只调整职责说明，保留原手工案例、原件保护和数值标准。
- **完整Trace取证：** 先查元数据并筛选本次Run，再逐条读取全部明细，避免复杂长会话批量batchGet失败；元数据不代替Span，无法取齐时仍明确报证据不足，不放宽评分门槛。
- **材料准备与运行分开：** 发布前可以由用户补齐初始文件和所属轮次，之后固定版本的运行无需重复上传。来源资料缺正文、附件或准确时点时必须显示缺口，不能声称已实现任意历史会话附件的自动恢复；已有资料足够的出题和历史评分继续可用。
- **交互驱动：** 每轮先等待 Agent 完成或进入已声明的中断，再推进下一步。固定回复与条件必须由评测集明确声明，不能由执行器替 Agent 编造正确答案。前置条件不满足、未知中断、预算超限时停止并保存原因。
- **结构化决策：** 信息补充按实际字段提交答案；计划审阅区分批准、要求修改与放弃，并绑定当前计划标识、修订与摘要；工具审批沿用动作及路径许可。响应记录绑定用例、轮次、Run 和中断，不让一种中断消费另一种响应。业务选择按实际配置的分支检查结果。
- **执行预算：** 工具审批复用连接配置已有max_steps预算，不另写死3次或按文件数限制；文件逐个写入、授权范围内修订均消耗同一预算。每次仍检查工具及精确路径，预算耗尽明确失败。固定澄清／计划回应按声明条目单独计数，长交互恢复请求不复用下一轮提交标识。
- **兼容与恢复：** 旧用例缺少新增字段时行为不变，历史内容摘要和发布版本不能因补默认值无故变化。沿用既有停止、幂等与真人审批恢复机制；取消后不得继续提交恢复请求。新交互的重启行为以实际验证为准，不默认宣称任意步骤均可无损重放。
- **运行前检查：** 校验本次模式、材料、引用、目标权限和可执行交互；必要条件不足时说明缺少哪一项。检查只约束所选新运行，不重新把运行目标可用性变成通用出题或独立发布的门槛。

### 指标与判定

任务结果、数据/产物正确性、工具使用、多轮一致性、用户决策、安全约束、效率/成本和重复运行稳定性是指标选择维度；每题只运行已配置且适用的指标，不虚构未采集的指标值。

能用程序证明的数字、文件、状态和工具时序，优先使用断言及材料复算；客观覆盖充分时允许仅规则指标。解释质量和会话一致性按需选DeepEval，模型高分不能覆盖关键事实失败。裁判只接收指标所需证据，完全相同重复项可明确引用来源，必要事实及不同历史内容不能丢；原证据及确定性检查保留。逐轮只使用当轮及此前规则，不倒罚后轮才改变的口径。缺证据或裁判错误单列，不算通过或普通业务低分。效率区分执行和等待，重复试验冻结版本及标准并保留全部样本。

### Worktree、验证及授权

后端按 EvalFlow Remote-First 规范在 `sshmy1` 的关联 Worktree 开发；Mac 相邻仓只承担镜像和必要前端验证。各 Worktree 使用独立安装目录，复用 uv/Yarn 缓存；核对 editable 实际导入路径。端口、PID、日志与测试产物使用本项目登记，服务仅监听回环地址。宿主机可用内存偏低，测试串行分批，前端重度构建只在 Mac 执行。

本次用户授权方案回写、建立 Worktree、开发与必要测试。保留两个主工作区原有未提交改动；不因此获得新的提交、推送、合并、生产重载、迁移、共享数据删除或额外生产修复授权。真实模型验证只使用已提供的合成案例和现有获准模型配置/预算，调用期间冻结评测源码。

最终分别验证同材料的一次性客观基线和原六轮固定交互。新基线仅规则、无模拟裁判；原六轮保持已选指标与0.8门槛，同证据评分不重跑Agent、不改历史error。另用数值错误、缺文件、提前操作、未知中断、拒绝审批及取消证明失败检出。组件、真实HTTP、模型和浏览器分别留证，旧Final不能替代本轮验证。
