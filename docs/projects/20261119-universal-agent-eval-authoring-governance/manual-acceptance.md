这轮要确认三个行为：聊天能转成不夹带无关规则的评测题；题目可先修订、采纳和独立发布；评分历史回答与重新运行 Agent 分别由你触发。按第一步至第十一步操作即可；正常情况下会产生两份评测集、历史评分记录和一次新的 Agent 运行。模型调用会使用当前环境的实际额度。

## 第二步：发送一条纯文本业务问题

**输入下面全文，再点击“发送”：**

```text
服务时间为周一至周五09:00至18:00，周末休息。
周日能否获得人工服务？请只根据规则回答。
```

**预期结果：** Agent 完成回答，含义应为“周日不能获得人工服务，因为周末休息”。表达可以不同，不要求逐字匹配。

先记下本次会话地址和实际回答。若回答错误也保留：后面应按原始业务规则评分，不能把错误回答抄成标准答案。若本次聊天直接报模型或预算错误，记录页面提示，先不要转换一个没有完整回答的会话。

## 第三步：把这次聊天转为评测集

**仍在刚才的聊天页操作：**

1. 点击会话顶部“更多操作”，选择“转为评测集”。
2. 在“评测集名称”填写：`手工验收-纯文本-20261119-01`。再次执行本文时把末尾序号改成 `02`，避免混淆。
3. 勾选“确认将脱敏后的会话与环境资料交给评测 AI 整理生成题目”。
4. 点击“转换并查看 AI 建议”一次。

**预期结果：** 提示转换任务已在后台启动，处理后通过通知中心提醒。弹窗关闭而没有立即跳转是正常行为。点击右上角“查看通知与告警”查看回执；“资料已送达”只表示交付成功，不等于 AI 已完成出题。

不要连续重复提交。如果数分钟后仍没有候选，先按第四步搜索评测集并看作业状态；若显示明确失败，保存错误信息，不把它记成通过。

## 第四步：在正式 EvalFlow 找到这份评测集

**另开标签页，打开：**

<http://49.233.222.54:9128/#/authoring?connection=server>

**操作：** 在“搜索评测集”输入第三步的完整名称，点击“搜索”，再点击对应名称进入详情。通知若提供该评测集入口，也可以从通知进入；检查地址保留 `connection=server`。

**预期结果：** 能看到会话生成的题目或 AI 候选，以及右侧“AI 评测 Copilot”。题目应围绕人工服务时间，不应无依据出现退款金额、`sales.csv`、`refunds.csv`、文件修改或必须使用某个工具的条件。

若显示“AI 候选”，先阅读差异；只有内容正确时点击“采纳全部并保存草稿”，或勾选具体变化后点击“采纳选中变化并保存草稿”。若首版已显示为已保存草稿，直接继续第五步。若仍在生成，等待当前作业结束，不重复启动。

## 第五步：实际做一次 AI 修订并采纳

**在右侧 Copilot 操作：**

1. “操作方式”选择“生成候选”。
2. 在“给 AI 的修改建议”粘贴下文，点击“按意见修改题目”：

```text
本次只保留一道纯文本固定轮次题，用于评分本次来源会话的已有回答。第1轮用户输入必须逐字保留来源会话原文，不改写、不增删轮次。
已确认规则只有：周一至周五09:00至18:00提供人工服务，周末休息。正确含义为周日不提供人工服务，允许同义表达，不要求逐字一致；不能把来源助手回答直接当作正确答案。
环境方式使用historical（仅评分历史回答），保留正确的来源绑定。至少保留一个能评价上述回答含义的语义评分指标。
不要增加退款、金额、文件、工具调用次数或其他没有素材依据的要求。只生成候选，等待我审核采纳，不发布、不启动运行。
```

**预期结果：** 出现基于当前草稿版本的 AI 候选和差异。候选出现时，原草稿、已发布版本和旧运行不应被直接覆盖。核对以下内容后，点击“采纳全部并保存草稿”：

- 只有一题；用户输入与第二步全文一致，业务时间没有改变。
- 正确预期来自用户规则，含义是周日不提供人工服务。
- 展开“业务规则、环境、文件、审批与评分方法”，“环境方式”是“仅评分历史回答（不重跑 Agent·直接评判老会话录音）”。
- 没有凭空要求上传文件、指定退款表、调用工具或设置工具次数上限。

采纳后应显示已保存的新草稿修订，**尚未发布、尚未运行**。如果候选仍不符合要求，先记录这份失败，再给具体修订意见；修正后可继续，但不能把它记录为首稿正确。

## 第六步：只发布题目，确认没有自动运行

**操作：**

1. 确认“发布这道题”已勾选，页面没有未保存修改。
2. 如果显示用途确认，勾选“我同意这些题目在24小时内用于隔离回归与评分；发布后由我启动运行”。已有有效用途授权时不会重复显示。
3. 点击“确认并发布选中 1 题”。
4. 查看下方“已发布版本与历史运行”，暂时不要点击运行按钮。

**预期结果：** 出现已发布题库版本及“运行这个版本”按钮。发布本身不会新增 Agent 回答、执行 Session 或运行结果。页面应保留“发布仅冻结题目、环境和指标，不会自动启动 Agent”的说明。

记下题库版本号。后续改草稿不能改写这个已经发布的版本。

## 第七步：只评分已有回答，然后重评一次

**操作：**

1. 对第六步发布的历史模式版本，点击“运行这个版本”一次，等待评分结束。这里按已发布题目的历史模式执行评分，不重新问 Agent。
2. 展开本次结果，查看回答、各指标分数及原因。
3. 记下结果中的来源 Session / Run 信息（若展示）、第二步原聊天的回答和轮次数。
4. 点击该结果下方“用当前发布标准重评（不重跑）”一次，等待新评分结果。
5. 回到第二步聊天页刷新，核对原会话没有新增消息或新的 Agent 执行记录。

**预期结果：** 结果明确显示“历史回答评分，没有重新执行 Agent”。评分使用第二步已经产生的原回答；重评会增加评分记录，但不应增加来源 Agent 的运行，也不改写原评分。

回答符合业务规则时，相应语义指标应通过；若原回答不符合，应合理扣分，而不是照抄原答案后给通过。若某指标依赖未收集的工具、文件或检索证据，应明确报证据不足／不可判定，不能伪装通过；其他证据充分的文本指标仍应有独立结果。评分调用裁判模型属于正常行为，不等于重跑被测 Agent。

若提示“来源不存在或历史不完整”或“历史评分必须保留原用户轮次”，保留错误，不手工编造历史原文；核对第二步是否真正完成、第五步的用户原文是否被改写，再反馈问题。

## 第八步：再做一份内联 YAML 文件内容的评测集

**回到第一步 Agent 聊天页，选择同一目标并“新建会话”，发送下面全文：**

```text
这是 deployment.yaml 的全部内容：
apiVersion: apps/v1
kind: Deployment
metadata:
  name: demo
spec:
  replicas: 0

请只解释为什么没有 Pod，不修改任何文件。
```

**预期回答：** `replicas: 0` 表示期望副本数为零，因此 Deployment 不会维持运行中的 Pod。不能无依据断言镜像拉取失败、服务故障；不能把“修改为1”当成已经执行的操作。

回答完成后，重复第三、四步，评测集名称改为 `手工验收-内联YAML-20261119-01`。这次素材是消息里粘贴的文件内容，**不是浏览器上传附件的测试**。

在 Copilot 选择“生成候选”，输入以下修订意见，再审核采纳：

```text
本次只保留一道固定轮次题，用于评分本次来源会话的已有回答。第1轮用户输入必须逐字保留来源原文，包括deployment.yaml、YAML缩进、replicas: 0及最后一句要求，不改写、不增删轮次。
正确预期是replicas为0意味着期望副本数为零，因此没有运行中的Pod；不应无依据推断镜像故障。用户只要求解释，不要求修复，不得要求Agent修改文件或创建产物。
环境方式使用historical（仅评分历史回答），保留来源绑定。使用能够评价回答含义的语义指标；仅凭文字不能证明实际未发生文件写入，不得用缺失工具记录伪造安全通过。
不要增加退款、财务表格、工具名称或工具次数上限。只生成候选，等我采纳，不发布、不运行。
```

**预期题目：** YAML 和输入要求逐字保留，预期解释有原文依据；不应出现无关退款信息，也不应把未选择新运行目标说成无法出题的原因。

采纳后，重复第六、七步完成独立发布和历史评分，确认文件题也能独立成库。不要把这段“文件”修订意见复制到纯文本评测集。

## 第九步：只在纯文本题上准备一次新的 Agent 运行

**打开第四步的纯文本评测集详情，操作：**

1. 展开题目的“业务规则、环境、文件、审批与评分方法”。
2. 将“环境方式”从历史评分改为“独立环境回归（推荐·在隔离沙箱中让 Agent 重新运行）”。
3. 保留原题面、业务规则和文本评分指标，点击“保存草稿”。
4. 核对新草稿后，点击“确认并发布选中 1 题”，形成新的题库版本。

**预期结果：** 旧历史版本和第七步评分都保留，新版本使用独立回归方式；保存及发布仍不启动 Agent。记下新的题库版本号。此步骤只改变运行方式，不向纯文本题加入文件或工具要求。

**仍在纯文本评测集详情操作：**

2. 弹窗标题应为“🚀 发起 Agent 大模型评测”。确认考卷名称、刚发布的版本和题数为1。

4. 确认无误后，点击“立即开考”一次，等待完成。
5. 查看本次结果；若显示“查看评测会话与链路”，点击进入，核对实际用户问题、Agent 回答、Session / Run 和 Trace；也可在详情下方本次结果的“执行 Session”与“查看本轮执行时间线”中查看。

**预期结果：** 此时才出现新的 Agent 执行和新的回答。结果应显示固定轮次回归，并能追溯到当前所选目标的执行记录和链路；不能只有一个空任务或创建成功提示。

正确回答仍应是周日不提供人工服务，相应指标按既定标准评分。若模型答错，业务质量应记失败，不能因为任务结束就算通过；若目标、权限、预算或模型不可用，应显示本次启动／执行的具体错误，原题库和旧版本仍可读。不要为了制造离线场景停止生产 Agent 服务。
