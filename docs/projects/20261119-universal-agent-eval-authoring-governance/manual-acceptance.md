- 正确预期来自用户规则，含义是周日不提供人工服务。

采纳后应显示已保存的新草稿修订，**尚未发布、尚未运行**。如果候选仍不符合要求，先记录这份失败，再给具体修订意见；修正后可继续，但不能把它记录为首稿正确。

## 第七步：只评分已有回答，然后重评一次

**操作：**

1. 对第六步发布的历史模式版本，点击“运行这个版本”一次，等待评分结束。这里按已发布题目的历史模式执行评分，不重新问 Agent。
2. 展开本次结果，查看回答、各指标分数及原因。
3. 记下结果中的来源 Session / Run 信息（若展示）、第二步原聊天的回答和轮次数。
4. 点击该结果下方“用当前发布标准重评（不重跑）”一次，等待新评分结果。
5. 回到第二步聊天页刷新，核对原会话没有新增消息或新的 Agent 执行记录。

**预期结果：** 结果明确显示“历史回答评分，没有重新执行 Agent”。评分使用第二步已经产生的原回答；重评会增加评分记录，但不应增加来源 Agent 的运行，也不改写原评分。

回答符合业务规则时，相应语义指标应通过；若原回答不符合，应合理扣分，而不是照抄原答案后给通过。若某指标依赖未收集的工具、文件或检索证据，应明确报证据不足／不可判定，不能伪装通过；其他证据充分的文本指标仍应有独立结果。评分调用裁判模型属于正常行为，不等于重跑被测 Agent。

若提示“来源不存在或历史不完整”或“历史评分必须保留原用户轮次”，保留错误，不手工编造历史原文；核对第二步是否真正完成、第五步的用户原文是否被改写，再反馈问题。

**预期题目：** YAML 和输入要求逐字保留，预期解释有原文依据；不应出现无关退款信息，也不应把未选择新运行目标说成无法出题的原因。

### 第1轮：上传五张表，只做资料盘点和澄清

**附件：上表第1轮的五个CSV。用户输入全文：**

```text

现在先不要输出正式KPI，不要直接相信旧看板的数值。请先问清统计日期、截止时间、支付去重及全额支付口径、有效发货状态、SLA边界和测试门店是否计入。
```
