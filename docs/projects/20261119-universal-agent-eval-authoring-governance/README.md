# 项目总览：通用 Agent 评测集转化与出题治理

> **项目标识：** `20261119-universal-agent-eval-authoring-governance`

> **当前状态：** 两步方向与职责边界已确认，本轮仅修订文档，产品代码未实施。
> **代码归属：** 默认在 EvalFlow；Agent 平台两个服务是否修改，以实际接口缺口及获准范围为依据。

## 1. 业务过程与两步结果

开发者把获准会话交给 EvalFlow，生成和修订评测题，人工采纳后独立发布题库。来源 Agent 的标识用于追溯，不应要求它在线、具备重新执行能力或提供完整工具清单。

用户选择评价已有回答时，EvalFlow 按所选指标检查证据；选择重新执行时，再检查目标权限、协议及具体用例所需能力。题库管理、历史评分和新运行分别处理，目标不可用不封闭已有题库。

1. **第一步：提示词与 Schema 描述去污染。** 清除固定业务假定，保留通用规则，补非退款和真实退款正例回归。
2. **第二步：通用出题与按需评分/运行解耦。** 能力描述作为可选参考，文件类与纯文本类素材均可独立成库；接口核查后再决定是否需要跨仓执行适配。

本地静态评审已确认固定业务示例和执行路径中的 `dearflow_agent` 限制；资料交付主路径没有直接调用目标快照。生产版本、偏差复现及完整依赖仍待核查，不能把现有执行限制当作通用出题的必需条件。

## 2. 当前确认的范围

2026-11-19 用户确认本轮修订：不新增必填 AgentManifest，不把完整工具全集或新增非文件型 Agent 执行接入作为出题、发布和核心验收的前提，也不预设 `platform-api`、`runtime-service` 必改。

原第二步的强制跨服务扩展调整为按实际需求启动的执行接入分支。保留结构、业务质量、来源/资产权限与实际执行安全检查；不承诺模型自愈 100% 或尚未验证的目标已可重跑。来源到期后的题库仍按自身权限管理，继续取源另查授权。
