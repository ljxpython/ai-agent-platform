# 06 实施顺序与总体验收

## 目标

以真实端到端证据收尾，不把类型通过、旧 mock 通过或截图当作执行链路可用。逐阶段替换旧代码，最终交付一套正式前端，不保留长期双轨和兼容开关。

## 方案设计

原前端合计 22–30 人天。新增 [07 队列扩展](07-message-queue-and-middleware.md) Q0—Q5 另估 10–16 人天，全部纳入则约 32–46 人天；尚未确认的 GraphHarbor 扩展另估。本轮不承诺固定发布日期，不把等待时间算成已完成工作。

实施顺序是 G0→G1→G2→G3→G4→G5→G6。阶段内可以按独立页面分工，但任何开发者不得绕过 G1 的协议门禁自行写第二套运行逻辑。G1 使用正式目标模块完成最小实现，不另建长期 demo 应用。

G0 原前端评审已完成。2026-09-10 用户确认 **07 最后完成**：先执行 G1—G6 并验收前端主体，再核对队列实现细节，依次执行 Q0→Q1/Q2/Q3→Q4→Q5。Q0 不插入 G1；G1—G6 不预建队列数据库、接口、UI 占位或通用框架。Q5 除专项 T21 外，回归普通发送、重连、停止、审批和项目隔离。未完成 Q5 时不能声称已完整复刻四项交互借鉴点，但不影响原前端范围独立交付。

不新增独立基础设施组件，复用现有服务进程、PostgreSQL 和 Vue 组件。任何阶段遇到已复现的 GraphHarbor 通用缺陷，均可在用户指定的源码仓库修复；不必等待 Q0，但禁止加入业务消息/授权/Agent 逻辑，位置与边界见 [项目概览](README.md) 及 [07 §3](07-message-queue-and-middleware.md#3-存储与执行引擎前置门禁-q0)。

### 3. 测试分层

保留已安装 Vitest、Vue Test Utils、Playwright，使用实际边界用例；不为每个纯展示 getter 写机械测试。新测试面向重构后的公开行为，旧场景可保留，但旧断言如果维护错误契约必须替换。

| 层级 | 核心范围 | 不能替代的事实 |
| --- | --- | --- |
| 单元/组件 | transcript 内容/ID、typed HITL、key/payload 冻结、权限/epoch、数字与 schema 校验、Composer/焦点 | 不能证明真实 SDK 发出的 body 或真实 Runtime 行为 |
| 前端契约集成 | 真 SDK + 可控 HTTP fixture，跨网络块 SSE、401/403/404/409、乱序/重复/断线 | fixture 应采自当前公开协议并脱敏，不是旧 Management 类型自造数据 |
| 后端契约核对 | 20 路由与 whitelist、Model/Agent/schema 样例 | 本轮先读取已有通过证据，实施改契约时重跑相关后端测试 |
| 真实浏览器 E2E | 浏览器→platform-api→GraphHarbor/Runtime→真实模型/工具工作区 | 禁 mock 模型目录、Graph 目录、审批或最终结果；mock 用例另列 |
| 安全/隔离 | 撤权、跨项目、跨账号、密钥、XSS、审批编辑、失效 ID | UI 隐藏不是安全证明，必须实际请求被后端拒绝 |
| 性能/资源 | 长列表、稳定组件实例、SSE cleanup、构建产物 | bundle 总量不是首屏下载量，模型耗时不是前端渲染耗时 |

### 5. 执行环境与命令

从仓库根目录，基础状态查询：

```bash
bash "scripts/local-stack.sh" doctor
bash "scripts/local-stack.sh" status
```

真实 Showcase 验收需部署 `apps/runtime-service/langgraph.demo.json`；默认 `langgraph.json` 没有 showcase_demo。遵守本地唯一启动入口，不手工另起散装服务：

```bash
RUNTIME_GRAPH_CONFIG_PATH="$(pwd)/apps/runtime-service/langgraph.demo.json" bash "scripts/local-stack.sh" start
```

执行前核实脚本的配置路径解析与已有进程实际配置；已有栈以另一份图配置运行时，先安排受控重启，不以命令成功返回就认为配置已切换。Docker/模型凭据/项目 grant 必须就绪，凭据由现有安全配置提供，不写入仓库或测试脚本。

前端检查从 `apps/platform-web` 执行：

```bash
pnpm test:run
pnpm typecheck
pnpm exec eslint "src/**/*.{ts,tsx,vue}" "eslint.config.js" "vite.config.ts" "vitest.config.ts" --max-warnings 0
pnpm build
pnpm test:e2e
```

正式 E2E 使用 `e2e/*-refactor.spec.ts` 替代旧脚本：使用隔离的测试账号/项目、相对路径 `test-results/`、明确语义定位器、Playwright 等待断言，不用长 sleep 和广泛 try/catch 吞掉失败。不要在正式真链路套件里 route.fulfill Graph/Model；fixture 套件清楚命名并与真链路分开。

证据仅保存脱敏后的路由、状态码、事件 ID/类型、Run/interrupt 关联、测试汇总和截图；禁记录 Authorization、密码、模型 API key 或整份身份响应。测试清理仅限自己创建的数据，并遵循危险动作确认规则。

### 6. 性能、安全与回退门禁

以下为固定验收目标，实际结果见末尾矩阵和 11；G1/G2 记录设备与基线后固定测试数据和测量方式。

- 1,000 条历史消息、200 次工具调用、2 个并发子图；输入和展开操作仍可用，已完成消息节点不随每个 token 重新挂载。
- 合成流 20 次更新/秒连续 60 秒：主线程不出现由全列表重建导致的持续长任务；记录 input→paint p95，目标 ≤100ms（排除后端模型耗时）。
- 连续切换 20 次 Thread/项目：旧会话活动订阅回到零，不持续增长；延迟旧事件不能写入新视图。
- 记录首屏、Chat chunk 和全产物 raw/gzip 大小；生产无 sub2api 参考源码。不要将全部懒加载产物总大小当首屏大小。
- 新实现 lint 零警告、类型通过；禁止通过关闭规则、删安全测试或 `any` 扩散达标。
- 当前用户无法越权读取其他项目 Thread/Run/文件；审批按当前 grant 拒绝失效动作；浏览器存储和测试日志没有内部凭据。

切换方式：在同一 app 内分阶段替换入口，开发阶段不开放两套产品导航；正式验收后只构建新版本。保留可追溯的已验收构建产物供部署负责人回退，不在源码中保留旧 Chat 兼容分支。

**旧前端已不符合新后端字段，不能把当前旧 bundle 直接当安全回退版本。** 首次切换失败时停止开放有风险入口，修正或恢复与后端契约匹配的已验收产物；后续版本才具备常规前端产物回退。演练验证入口可达、资源缓存更新、无自动重发/审批，不使用数据库回滚或旧 ID 迁移。

07 涉及新增 Runtime 数据表，按新增治理方案评审与受控迁移执行，不能在文档阶段修改现有数据库。本项目不发布生产、不执行 git 分支/提交/推送；发布需实际产物与验证完成后按授权执行。
