# 长会话断流恢复解耦与历史快照按需懒加载治理

## 关键决策
1. **断流恢复纯粹化（KISS 原则）：** `useChatSession.ts:recoverExpiredStream()` 核心职责是恢复“当前对话最新状态”，只需并发或单独拉取 `service.state(id)`。彻底剥离对 3.4 MB 巨型快照 `service.history(id)` 的阻塞式强拉取。
2. **时间旅行按需懒加载（YAGNI 原则）：** Checkpoint 历史树仅在用户主动展开“时间旅行 / 历史分支抽屉”时，由抽屉组件自行按需请求，不污染主会话初次加载与断流重连主链路。
3. **软降级与错误隔离（防雪崩）：** 即使时间旅行组件在请求 `service.history(id)` 时遭遇网络抖动或超时，错误严格局限在抽屉内部显示“历史时间线加载超时，点击重试”，严禁通过 `fail(cause)` 把整个主聊天会话打死变成红色报错条。
4. **网关层超时与重试弹性收敛：** Platform API 对长会话的 `/history` 与普通短路由做好容错隔离，避免重载时级联崩溃。
