# 记忆系统架构升级 - 验证计划和记录

## 验证计划

### 单元测试
- [ ] `test_memory_async_dispatch()` - 验证 `aafter_agent` 能够在 15ms 内立即返回，且后台协程完成提取。
- [ ] `test_prescreen_signals_and_skips()` - 验证问候语/短语被正确判定为 Skip，明确偏好正常放行。
- [ ] `test_relevance_idf_weighting()` - 验证特定技术词（如 `FastAPI`）较通用词具有更高的匹配权重。
- [ ] `test_mmr_diversity_selection()` - 验证高相似度的事实受到多样性惩罚，选出具有多样性的事实集合。
- [ ] `test_fact_dedup_merge()` - 验证语义高度相似的候选触发合并并提升置信度。
- [ ] `test_eviction_policy()` - 验证超过容量限制时，最陈旧且置信度低的事实被平滑淘汰，不抛出异常。

### 集成测试
- [ ] **场景 1：端到端非阻塞提取测试**
  - **步骤：** 发起一次 Agent 对话，附带偏好表达（如："请每次都使用中文回答"）。
  - **预期：** 流式输出快速正常关闭；1~3 秒后查询记忆候选列表，包含对应的中文回答偏好。
- [ ] **场景 2：Prescreen 节流测试**
  - **步骤：** 发起 5 次普通打招呼或简短问答会话（如"你好"、"今天几号"）。
  - **预期：** 后台提取大模型调用计数为 0，提取状态记录为 `skipped`。
- [ ] **场景 3：容量溢出软淘汰测试**
  - **步骤：** 连续灌入超出限制的事实，观察存储与读取。
  - **预期：** 系统正常存储最新事实，无 409 异常，低分事实被优雅腾退。

### 端到端测试
- [ ] **链路 1：** `platform-web` → `platform-api` → `runtime-service`
  - **操作：** 在 Web 端与 Dear Agent 交互，随后进入个人记忆管理页查看候选及已采纳事实。
  - **验证点：** 候选呈现正常，点击采纳能立即生效并在下一次对话中被上下文感知。

### 性能指标
- **对话收尾延迟降低：** `aafter_agent` 耗时从原来的 1500~4000ms 降至 < 20ms。
- **提取调用节省率：** 日常闲聊/问答场景下，Prescreen 拦截率达到 50% 以上。
