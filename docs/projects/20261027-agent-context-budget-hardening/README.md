# 智能体上下文窗口治理与 Token 预算韧性优化

## 项目概述
- **时间：** 2026-10-27 至 2026-10-29
- **目标：** 解决智能体运行中频繁触发“整理上下文”、过激裁剪（10%）导致失忆死循环、以及单次运行耗尽 100 万 Token 猝死的问题；实现前置工具输出防爆与 Token 超限优雅收尾。
- **负责人：** @lijiaxin & 老王技术流

## 改动范围
- **影响服务：**
  - `apps/runtime-service`: 上下文裁剪策略重构、工具输出前置防爆截断、Token 超限优雅结束（非崩溃）。
  - `apps/platform-api`: 模型目录 context_window_tokens 校验与默认值调优。
  - `apps/platform-web`: 模型录入/编辑体验核对。
- **改动级别：** 链路改动
- **预计工作量：** 1.5 人天

## 关键决策
1. **摒弃极端的 `keep = 10%` 策略**：借鉴 DeerFlow 实践，采用“保留最近 N 条消息”（默认保留最近 15~20 条消息）或按比例保留至少 40% 上下文，彻底切断“压缩 → 失忆 → 重新读文件 → 再次爆上下文”的震荡死循环。
2. **工具输出前置防爆（Head + Tail Truncation）**：在工具返回生成 ToolMessage 时，设定单次输出字符/Token 硬上限，对超长文本自动执行首尾保留并插入截断摘要，防止单次 `read_file` 或 `execute` 把上下文瞬间灌满。
3. **Token 超限优雅停机（Graceful Hard-Stop）**：当 Run Token 预算达到 100% 硬限时，清除后续 `tool_calls` 并追加完成总结，让图流转到终态正常交付阶段性成果，不再粗暴抛错报红。
4. **模型窗口可配置与合理底线**：在平台模型目录确保 DeepSeek 等模型配置正确的真实窗口（如 128K），并在后台提供安全保底。
