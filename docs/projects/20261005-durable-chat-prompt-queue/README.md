## 关键决策
1. 复用 GraphHarbor 已有 PostgreSQL Run 持久化和 Redis 唤醒；补齐严格顺序与审批阻塞，不新造消息队列。
2. 前端仅负责提交、展示和取消；服务端 ACK 后即拥有执行责任。
3. 草稿不入队；审批中、取消和明确撤权由服务端终态控制。
